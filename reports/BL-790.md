## The defect I introduced and caught

My first version wrote `followers` and `median_views` straight from `_row_int`, which returns **0** for an absent value. The result:

```
client rows: 1,015
  followers    non-empty 1015 | non-empty AND non-zero 0
  median_views non-empty 1015 | non-empty AND non-zero 0
```

Every client row scored **2 merge tokens that were both literal zeros**. Merged into a sentence that becomes *"you have 0 followers"* — worse than saying nothing, and it would have inflated the coverage table in this very report to "1,015 rows at 2 tokens" when the true answer is zero.

Fixed with `_BLANK_IF_ZERO` at write time. **Deliberately at write time, not in the candidate dict:** `crossdedup` ranks duplicate records by reach and reads `followers`/`median` as **integers**, so blanking them upstream would have fed it strings. My first attempt did exactly that — it added a second `followers` key to the same dict literal, which silently overrode the one the dedup uses. Both problems are in the commit comments so the next reader sees why the conversion lives where it does.

`score` and `intent_score` are untouched: those zeros come from a real calculation, and existing consumers read them as numbers.

## Google Play `profile_link`

**Mechanism confirmed:** `google_play_finder.py:893` writes the developer name into `tiktok_handle` (*"store dev name in the identity col"*), and the TikTok URL template wraps it. Measured: **212 GP master rows, 159 with a space or comma in the handle**, producing links like `tiktok.com/@2K, Inc. - a Take-Two Interactive affiliate`. Every one 404s.

**The real Play listing cannot be rebuilt.** `app_id` is set in the append record but is explicitly **not a master column** — the code comment says so and `extrasaction='ignore'` drops it at write time. There is no id anywhere in master to put in a store URL, and no column carries `play.google.com` on any row.

**So the fix is: use the developer's own website, else blank.** `link_in_bio` holds a real site on **200 of the 212** master rows. Result in the export:

| | |
|---|---|
| GP rows | 61 |
| fabricated TikTok links | **0** (was all of them) |
| real developer website | **53** |
| blank | 8 |

Blank is the floor — no link beats a link that lands on a dead page. Using `link_in_bio` is a small extension of the brief's two options, taken because it preserves a genuine destination for 53 rows that would otherwise have been emptied.
