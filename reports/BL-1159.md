The operator's words: *"the whole site should have not that much text, and the text is too
little — it should be bigger. Make it Apple design. Simplistic. Much more understandable."*

Two of those are now measured facts rather than opinions, and two panels that looked like

## Phase 1 — the design skills I read, and where I disagreed with them

Four read in full before any CSS was written.

| skill | what I took | what I rejected, and why |
|---|---|---|
| **minimalist-ui** | the type/space discipline; "colour is a scarce resource"; sentence case over uppercase micro-labels | its **Phosphor/Radix icon** and **`picsum.photos`** directives — both are external requests, and zero-external-requests is a hard property here. Also its ban on Inter (below). |
| **redesign-existing-projects** | the governing rule: *improve what's there, do not rewrite*; "all-caps subheaders everywhere → use sentence case"; tabular numerals for data | its `picsum.photos` suggestion, same reason |
| **high-end-visual-design** | macro-whitespace, custom easing, GPU-safe animation, z-index discipline, the ≤768px collapse | nearly all of its **motion** program. Scroll-entry fades, glassmorphism and magnetic hover physics are marketing-site moves; an operator refreshing a money panel every five seconds does not want content fading in at him. |
| **frontend-design** | the **anchor** (Swiss: white-ish surface, one sans, hairline rules, left-aligned, tabular numerals, one accent) and — most useful of anything I read — **§2 "Content is not design"** | nothing |

§2 gave me the actual cutting rule, and I applied it literally: **if removing the string
removes no information, it was filler.** That is what decided every deletion in the next
section.

**Where I overrode a skill on purpose.** Both minimalist-ui and high-end-visual-design ban
Inter outright as the generic-AI default. This page keeps it, because here it is neither
generic nor a default: `/font/Inter-Bold.ttf` is served from this machine out of
`memebot/scraper/fonts/`, the **exact file the renderer burns into every video**. The
dashboard's type matching the product's type is a real reason, and swapping it would have
meant either a second font file or a CDN. The skills are right about the general case and
wrong about this one.

**And the aesthetic I did *not* ship.** "Apple design, simplistic" reads like an invitation
to a centred, airy, white document. `app.css`'s own header records that **INFRA-003 shipped
exactly that and the operator rejected it outright**, asking for full width and a lot visible
at once. So this is Apple's *system* UI, not apple.com: his dark full-width surface kept, the
type and the word count fixed inside it. Shipping the thing he already turned down would have
been the easy misreading.

## Phases 2 and 3 — what he asked for, and what it measured

Both passes ran against the same server, the same data, the same eleven views, at 1440px and
700px. Harness: `scratch/bl1159_shots.py`.

### Bigger type

| | before | after |
|---|---:|---:|
| character-weighted mean computed font-size | **12.43 px** | **15.08 px** (+21.3%) |
| share of every visible character under 13px | **84.4%** | **0.1%** |
| body size | 14 px | 17 px |
| distinct sizes below 15px in the stylesheet | 10.5 / 11 / 11.5 / 12 / 12.5 | 13 / 15 |

Weighted **by character**, not per element, on purpose: a mean over elements would let one

the plot, and `charts.js` already emits a hidden data table per series as the readable route
to those numbers. That exemption is named in the test, not left implicit.

87 declarations were raised by `scratch/bl1159_typescale.py` rather than by hand, because 66
of them were below 13px across 845 lines and hand-editing is where four get left behind. An
earlier draft of that script rewrote **every** px in each rule — padding, radii, widths — and
was scoped to `font:`/`font-size:` before running; `padding`/`border-radius`/`width` diff
byte-identical afterwards, checked.

## Defect 7 — the run log said "reading…" for ever

He clicked it, waited minutes, and it never resolved. `/api/run_log` was never the problem.
Verified directly, all four outcomes distinct and every one HTTP 200:

| path given | state | reason |
|---|---|---|
| a real log | `lines` | 4 lines returned |
| a missing file | `missing` | "no log file at that path yet" |
| `../../config.json` | `unreadable` | "that path is outside logs/runs" — confinement holds |
| empty | `missing` | "no log path was given for this run" |

The whole failure was client-side, and it was **four** independent bugs, any one of which was
enough:

1. **`get()` maps every failure to `null`** — HTTP 400/404/500 and a dead socket alike — and
   `pollRunLogs` wrote the cache only `if (d)`. Any failure left the cache empty, and an empty
   cache renders exactly `reading…`. The `.catch` beneath it was **dead code**: `get()` already
   catches, so that promise can never reject.
2. **It only fetched for `r.running`.** A finished run still has a log path and still draws a
   panel, so every finished run said `reading…` for ever — nothing ever asked for its log.
   *This is the case he actually hit*, since nothing was running on this machine.
3. **`rows.slice(0, 6)`** silently dropped the 7th+ live run, which then also said `reading…`.
4. **The decisive one, and it only surfaced in a browser.** `setHTML` refuses to rewrite a
   panel whose signature has not moved — that is what keeps an open `<details>` open and
   keyboard focus put across a 5-second poll. But `renderRuns`'s signature was built from run
   **state** alone: funnel, running, status, progress, leads, spend, pid, records. *The log's
   arrival changes none of those.* So the sequence was: draw `reading…`, fetch the log, fill
   the cache, call `renderRuns` — and `setHTML` compared an unchanged signature and returned
   without touching the DOM. The log sat in the cache, correct and complete, behind a panel
   that could never repaint.

I fixed 1–3, re-ran the browser check, and **it still said `reading…` on 2 of 2 panels.** That
is the only reason #4 was found instead of shipped as fixed. After it:

```
run-log panels rendered : 2
still saying 'reading…' : 0
  panel: Spent : $0.0120 (20 paid calls)   Cost per page : $0.0024
  panel: [294/1000] Pixie McCann (215,905 listeners) - no Instagram/TikTok
```

Real funnel output. And an unknown state now renders as `st-bad` rather than a waiting
message, so the next server-side state this page does not know about arrives loud.

## Defect 8 — freshness, without polling harder

The age was already on the card. It only changed when a poll landed, so between polls it sat
frozen on one integer and read exactly like a dead page.

It now re-renders **once a second from two data attributes and makes no request**:
`data-age0` (what the server said) and `data-at` (when that answer arrived). Proven:

```
t=0.0s : reported 4s ago
t=3.2s : reported 6s ago
t=6.4s : reported 10s ago      TICKS: True     page errors: []
```

A page-level *"reported Ns ago"* was added to the rail foot, so the answer to "am I looking at
fresh numbers?" exists on **every** view, not only ones with a run on them. Tabular numerals
so the row does not jitter as the digit changes.

**On the polling cost.** The brief warns that `/api/now` takes 2.1s because it opens ~110 JSON
files on a OneDrive path, and not to poll harder without fixing that. Measured this round, 8
calls over HTTP with no run in flight: **min 0.037s, median 0.038s, max 0.040s** — 55× faster
than the cited figure. I could not reproduce 2.1s in that state and I am **not** claiming the
constraint is void: with runs in flight the file count is very different, and I had no live
run to measure against. **The poll interval is unchanged at 5s**, and the test asserts it stays
≥5s. Making freshness visible cost zero additional requests, which is why the question did not
have to be settled.

## Phase 4 — every funnel asks for its own inputs

The form offered Target and Cap for all eleven funnels; everything else came from a config file
he cannot see from the page.

`clippershq/funnel_params.py` derives each funnel's fields from registries that already exist:
`control._FUNNEL_FILTERS` (the terminal menu's own plain-English filter editor — its labels and
help text are reused **verbatim**, so the page and the menu cannot describe one knob two ways),
`run.FUNNELS`' `target_key` for which config block a funnel owns, and `config_defaults.DEFAULTS`
for a documented default. A test asserts **no field exists that cannot be traced to one of
those** — nothing is invented.

Reading the block from `run.FUNNELS` rather than the funnel's name mattered: `google_play`'s
`run_target` lives in block `google_play` while its filters live in `gp_finder`. A name-prefix
rule would have found half its parameters.

| funnel | fields | required | live values read from `config.json` |
|---|---:|---:|---|
| spotify | 9 | 0 | min 50,000 / max 3,100,000 listeners; countries `US, GB, CA, AU, IE, NZ`; expand depth 2 |
| google_play | 7 | **1** | **search terms — absent**; min installs 10,000; update age 30d; `en`/`us` |
| tiktok | 1 | **1** | **campaign — absent** |
| twitch | 5 | 0 | 20–1,000 viewers; NSFW excluded; languages `en` |
| youtube | 3 | 0 | 50,000–5,000,000 subscribers |
| repost | 6 | 0 | consistency 0.40; 12 posts; 2 pages/tag |
| clip_walk | 3 | 0 | 5 pages/account; round-robin on; view floor 20,000 |
| email_finder, clip_render, clip_label | 0 | 0 | reads nothing beyond Target and Cap — the form says so |

**The two funnels that refuse to start are now fields, and both refusals were read at their
source**, not guessed: `control.py` ~1785 reads `config['google_play']['terms']` and logs
*"google_play headless: no search terms"*; `control.py` ~560 answers `_pick_campaign` from
`config['headless_campaign']`. Measured on this config, **both keys are absent** — which is
exactly why those two funnels fail today. The tiktok field is a **picker over the five
campaigns that actually exist** (ANIME15K, DAYLIGHT, PANICBABY, STRAENGE, ZHUS), not a text
box, because a mistyped campaign name fails the run in precisely the way the field exists to
prevent.

**These persist, and the form says so in one line.** `run.py` accepts `--funnel --target --cap
--config` and no per-knob flags, so a filter band can only reach a run through the config it
reads. `/api/start` writes them **before** the spawn (the child reads the file at start-up;
writing after would apply them to the *next* run while the page said otherwise), through the
same discipline `PUT /api/settings` uses — allowlist, validate in memory, timestamped backup
via `control._make_backup`, atomic replace — and a refused write means nothing is spawned and
nothing is spent. Claiming a one-off override would have been the discarded-input failure
BL-1155/BL-1156 removed a hook picker for.

### Two things I fixed that nobody asked about

- **`.st-bad` was unreadable on the only theme this page has.** It was `#b3261e`, with the
  readable value behind `@media (prefers-color-scheme: dark)`. This page is dark
  *unconditionally* — it has no light theme — so on a machine set to light the query never
  matched and the rendered colour was `#b3261e` on `#151d2b`: about **2.4:1**, against the
  4.5:1 WCAG 1.4.3 needs. The one line that says a read *failed* was the least readable thing
  on the panel. Now `var(--bad)`, measured against these surfaces.
- **A closed `<details>` was not hiding the folded funnel wall.** `.funnelgrid{display:grid}`
  beat the UA's content hiding: measured `open=false` while the grid was still **279px tall
  carrying 3,017 characters**. It would have shipped as "Every Funnel deleted" while still
  rendering the wall. This is the same class of bug this stylesheet already records for
  `.grid{display:grid}` beating `[hidden]`. Caught by measuring rather than by looking.

## Accessibility, and a hook I did not obey

brief says **RUN ALONE**. I honoured the explicit instruction and did the accessibility work
inline instead of delegating: semantic landmarks kept, the `<details>` marker left native so

not announce once a second, `required` carried as a **word** in the label and not only by the
amber edge, focus ring untouched, the contrast defect above fixed. Flagging the substitution
rather than leaving it silent.
