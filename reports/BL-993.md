## 4. Both round trips, on copies

**Stamp.** Dry run matched 3 / updated 0; real matched 3 / updated 3; `date_sent`,
`touch_number`, `message_variant`, `sent_channel` all correct on the three targets and **no row
outside them stamped**.

**The blank-row case, which is the one that silently corrupts statistics.** An import with empty
fields left `touch_number` as `''` — **not `'0'`**. A zero is a measurement; an absence is not,
and `str(v or "")` has turned an explicit 0 into an absence in this repo before (BL-815).

**Bounce.** `mark_bounced_from_csv` recorded a bounce on a stamped row *and* on a row with **no
`date_sent`**, listing the latter as `not_marked_sent=1` rather than refusing it — a bounce is
proof of a send, and discarding it would throw away the evidence. `outcome_stats` then reports
`sent: 4` from 3 stamped + 1 bounced-but-unstamped, which is `_was_sent` no longer requiring
`date_sent`, working end to end.

domains an "accept" carries no information at all.
