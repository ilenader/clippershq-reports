## 1. The language gate — and the obvious fix was wrong

You said: *"The captions the language check reads are ALREADY IN THE PAGE PAYLOAD that was already paid for. Move the check before the paid call."* The premise is right. The straightforward implementation is not, and measuring it is what showed that.

`account_gate` deliberately judges the **aggregate** of an account's captions, and its docstring says why: *"a single foreign line cannot condemn a page"*. A pre-gate on the one seed caption throws that property away. Replaying the same classifier over **139 real accounts** in the clip library:

| captions the pre-gate can see | drops | **wrong** |
|---|---:|---:|
| 1 | 13 | **2 (15%)** |
| 2 | 13 | 1 (8%) |
| **3** | 14 | **0 (0%)** |

Dropping a real English repost page to save $0.0006 is a bad trade — a confirmed page is worth orders of magnitude more than the call.

**So the fix is not a new check. It is to stop throwing evidence away.** The discovery loop did this:

```python
if r["username"] in candidates:
    continue          # <- and the caption on this clip is discarded
```

Every further clip an already-seen account shows on a page **we have already bought** carries another free caption. Those are now accumulated, and the pre-gate may drop only with **three or more** (`pre_lang_min_captions`, a measured threshold, not a guess).

**Fewer than three falls through to the paid gate exactly as before**, so this can only remove spend, never coverage. New counter `non_english_pre` reports what it saved.

**What I did not prove:** how many of the 48 this recovers in a live run, because that needs a discovery run and both the runner situation and the budget argued against starting one. The mechanism is measured; the recovery rate is not.

## 2. Duplicate first-writes

`have = set(load_index(root))` was read once at run start and `append()` is deliberately blind, so two overlapping walks both saw a clip as absent and both wrote `rev=1` — 27 clips, 24 of them from two separate **paid** fetches.

The index is now re-read immediately before the append, and anything another writer landed in the meantime is dropped and reported as `skipped_raced`.

**This narrows the window; it does not close it.** A writer can still land between the re-read and the append. Closing it completely means doing the check *inside* the per-shard `filelock` that `append_many` already takes — which is `clip_library.py`, held by BL-849. Said plainly rather than claimed as done.

## 3. An unmetered call is now impossible by accident

BL-863 spent **$0.015 through 25 direct `session.get()` calls** and nothing objected, because `session` is an ordinary attribute.

`session` is now a `_MeteredSession` whose verbs **raise** when called from outside `_request`:

```
ig_client: session.get() called directly, which skips the pacer, the
x-hiker-info receipt and the spend meter. Use the client's own endpoint
methods, or IgClient.raw_get(url, params) if you genuinely need an
unmetered request (a probe reading headers, say).
```

Raising rather than silently metering is deliberate: a direct call is a bug in the caller and should be loud at the call site. `raw_get()` is the documented on-purpose escape hatch — the probe's legitimate case — and it says "UNMETERED" in its own docstring. Ordinary attribute access is untouched, so the key and headers still work; all seven verbs are guarded, not just `get`.

  distinction is real: the knob is not in the settings surface the dashboard exposes.
