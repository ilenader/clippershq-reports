### THE ONE NUMBER: the cap was 20% loose, and this round's own plant found it

`if spent >= cap` stops **one call too late**, because OpenRouter bills per token and a
call's price is only known once the reply has arrived and been paid for.

```
  six clips at $0.04 against a $0.10 cap
    before :  spent $0.1200   <- 20% over a ceiling the operator set
    after  :  spent $0.0800
```

Every check in the log said the cap had bound correctly — and it had, one call too late. It
now subtracts the **expected next call** before making it: this run's own observed mean cost,
or `USD_PER_CLIP` as the prior before the first reply. That bounds the overshoot to the
variance of one call rather than to its whole price, and it uses measured costs rather than a
constant that drifts.

## 2. Both dark stages emit a DecisionLog

BL-1000 named repost discovery and the labeller as the two stages producing no log. Discovery

to see — so a silent loss there is invisible in every later stage and reads there as "there
was nothing to do".

**Four paths in `repost_finder` dropped a row with a bare `continue` and no counter:**

| now named | why it matters |
|---|---|
| post carried no username or cover-image URL | — |
| another clip from an account already a candidate | — |
| **cover image could not be fetched** | not hypothetical: @outside_edge_07 lost 3 of 8 posts this way and was filed THIN (unjudged) rather than judged |
| accounts never reached before the target or the cap | opposite next action from "rejected" — raise the cap, or fix the gate |

`not reached` is measured as **offered minus examined**, from two real counters — never as
the stage's leftover. INFRA-019 shipped a self-balancing drop that made `unaccounted`
structurally 0, which disables the one thing the log exists to report.

## 3. The bounce recorder now has a caller that is not a test

`outcomes.mark_bounced_from_csv` was written, tested and correct, and was **called by its own
test suite and by nothing else**. `bounced` was already a column, already validated, already
counted by `outcome_stats` — and empty on all 59,006 rows, because a bounce report is a LIST
of twenty addresses and the only recorder was interactive and one-at-a-time.

```
  headless : python clippershq/run.py --mark-bounced bounces.csv          (DRY RUN)
             python clippershq/run.py --mark-bounced bounces.csv --apply
  menu     : [o] -> [5]  "Record a BOUNCE report"
```

Dry-run is the default and `--apply` is the opt-in: it stamps every matched row in one pass,
and headless has no human to say no, so the default itself has to be the safe one.

A first send day produces exactly one number worth having. A bounce rate nobody writes down
is a deliverability problem nobody finds until the sending domain is already burned.

## Honest limits

* **My fixtures were wrong twice, in the direction that fakes a pass.** The clip fixtures
  wrote bare keys with no `provenance`, and `clip_library.field()` is the consumer rule — a
  value with no provenance entry reads as `None`. So the pool filter dropped every clip, all
  three labeller plants scored 0, and it looked exactly like a code failure. The library was
  right and the test data was wrong, which is the correct direction for that rule to fail in.
  Separately, `ask_fn=_ok_reply` bound the video bytes to the helper's `cost` parameter.
* **I guessed the scanner's path** (`tools/secret_scan.py`) and the harness reported "scanner
  missing" as a **finding** rather than a pass — an absent gate is not an open gate. The real
  one is `scratch/scan_report_for_secrets.py`, which is what `publish_report.py` invokes.
* **Two drop reasons both contained the word "thumbnail"**, so a search for one counted both.
  Reworded, because a drop reason is read by searching, not by reading the whole log.
* **`_mark_bounced` was written against a remembered contract**: it printed `res["read"]` and
  `res["marked"]`, neither of which `mark_bounced_from_csv` returns, so `.get(k, 0)` would
  have reported 0 addresses and 0 matches on a good run, forever, in the cheap direction.
  Caught by reading the function rather than by running it.
* **No paid labelling run was made.** The stage is proven against injected fakes and a temp
  config; the cap's mid-run binding is measured on fake costs. What is NOT proven end to end
  is a real vendor response through the real retrieval leg — that is what the $0.10 budget
  was for, and it was not spent because every property in the brief could be established
  without it.
