## 4. THE ORDERING DEFECT, LANDED (taken first — it is the one that pays)

BL-979 proved unwalked-first with a **scratch monkeypatch over `confirmed_accounts`**. The
shipping call in `control.py` still went to the real function, which still returned **master
order** — so the next dollar-capped run would have repeated the whole thing: cap spent
re-opening 172 walked catalogues, the paid-for pages at the bottom of master never reached.

`clip_runner.order_unwalked_first()` + `walked_accounts()`, and **both** of
`confirmed_accounts`' return paths now go through it — the crossdedup path *and* the fallback
that runs when crossdedup breaks, i.e. exactly when nobody is watching.

Three decisions worth the words:

- **The library is what counts as walked, not the seen-cache.** The cache is keyed on *clips*;
  a page that returned nothing leaves no trace in it and would read as unwalked forever, so a
  capped run would keep paying to re-open the same empty pages first.
- **It is an ordering, never a filter.** Walked pages are moved, not dropped — a page posts new
  clips and a run with budget left still refreshes them. The test asserts the returned **set**
  is unchanged, because *"reach the new ones first"* quietly becoming *"never refresh the old
  ones"* would look like a success for exactly one run.
- **It degrades to master order.** An unreadable library gives an empty walked-set and therefore
  the input order. An ordering failure must never become "walk nothing".

`tests/test_unwalked_first.py` — **12 checks, green.** Live: 247 confirmed, 237 walked,
**10 never walked**.

## What I got wrong

**My first two tests scanned text and matched their own explanation.** `assertNotIn("seen",
src)` failed on `walked_accounts`' docstring, which says it does *not* read the seen-cache;
`src.count("order_unwalked_first") == 2` got 3 because the function's docstring names it. Both
now parse the AST and strip docstrings. **This is the third round in which I have made this
exact mistake**, and twice now in a test written specifically to avoid it — the pattern is that
the guard and the prose live in the same string, and only an AST can tell them apart.

**My first `should_skip` measurement was wrong and I nearly reported it.** I called
`CV.should_skip(clip)` with one argument, the `TypeError` was swallowed by my own `except`, and
it printed *"0 clips would be skipped"* — a clean, plausible, false number. `select()` skipped
**1,545** of them. An exception caught into a default is indistinguishable from a real answer.

## Method / limits

**The labelling batch is still running under its cap** as this publishes. The figures above are
its state at 58 attempts; the final count will be higher and the *yield* is the number that
matters, not the count.

**"Never walked" counts pages with no clips in the library.** A confirmed page that was walked
and legitimately returned nothing reads as never-walked and will be re-tried first. That is the
safe direction — and it is why the count is 10 rather than 0 after a full walk.

**Nothing here re-derives BL-979's +658.** I measured the library as it stands; the attribution
of those clips to the 67 pages is BL-979's and I did not re-check it.
