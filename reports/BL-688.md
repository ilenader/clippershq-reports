# BL-688 — the report-ID race: three reports were destroyed, not one, and only one was noticed

## THE COLLISION IS NOT A ONE-OFF. Auditing all 149 reports found **three** paths silently overwritten by unrelated reports — `BL-649` (lost five days, nobody noticed), `BL-675` (lost the same day, nobody noticed) and `BL-677` (the known one). All three are recovered and republished. A fourth failure mode turned up that no link-fix can repair: `BL-648` reserved two IDs *in prose* for reports that were never written, and both numbers were later claimed by unrelated work. `CONVENTION.md` now documents the exact pre-push check — **and that check caught a real collision during this very round.**

**2026-07-29 · REPORTS REPO ONLY. No pipeline code, config or data was touched.** Writes are confined to this repository: one new `CONVENTION.md`, one README pointer, two recovered reports, and three citation repairs that change no finding.
**Concurrency, stated plainly: this round did NOT have the repo to itself.** BL-681 and BL-682 were published by another agent while it ran, and two benchmark processes were live. Every step used the collision-safe procedure below, and the tree was resynced to `origin/main` and regenerated deterministically from git history before the final push.

## PART 1 — what the audit found

I enumerated every path on `main` that had been written by more than one commit, then compared the `# ` title at each commit. A path whose title changes has been **overwritten by a different report**, not edited.

| ID | first report — **lost from `main`** | second report — kept | gap before anyone noticed |
|---|---|---|---|
| **BL-649** | "Do already-installed iPhone PWAs get the new launch images? NO. And why no trick changes that." (`321ceef`, 2026-07-24) | "Merge BL-648 to main (iOS launch images + recharts defer)" (`40ea3df`) | **5 days — found only by this audit** |
| **BL-675** | "Instagram reels move to /v2/user/clips, and a test that was set to fail on a date nobody chose" (`4c9b4f0`, 2026-07-29) | "merge BL-673 (Instagram cover capture) to main" (`c4b38ce`) | **hours — found only by this audit** |
| **BL-677** | "beat-drop timestamp and mood for Instagram Reels" (`773dfe2`, 2026-07-29) | "Apify is supposed to be dead, so why did it run?" (`54e19d6`) | noticed same day |

**Two of the three had never been reported.** The known BL-677 case was not the anomaly — it was the one that happened to be caught, because its author was still working when it was overwritten.

The pattern is identical in all three: a **merge/audit report** overwrote a **research report**. Both agents read the same ceiling, both picked the same number, and git accepted the second as an ordinary commit because *the path already existed*. Nothing failed. No warning was printed.

Across the repo: **149 reports, 902 cross-references, and every `.md` link resolves** — which is precisely why this was invisible. `reports/BL-677.md` returned HTTP 200 the whole time. It just returned the wrong document.

## PART 2 — a fourth failure mode that cannot be link-fixed

`BL-648` wrote:

> "Two pre-existing issues were **reported, not fixed** … and filed as **BL-649** (the viewport meta blocks pinch zoom, WCAG 1.4.4) and **BL-650** (the recharts SVG has no text alternative in any of its six usages, WCAG 1.1.1)."

Neither report was ever written. Both numbers were later claimed by unrelated work — `BL-649` by the iPhone-PWA report (then by a merge report), `BL-650` by "the analytics-screenshot reader". So `BL-648` now cites two documents that have nothing to do with the accessibility issues it describes.

**No relink repairs this**, because the referenced content does not exist in any commit. It is a different bug from the overwrite: an ID *reserved in prose* before it was published. `CONVENTION.md` now says to describe future work rather than number it — an ID becomes real when the file lands on `main`, not when someone intends to write it.

Recorded here rather than silently patched: **two accessibility findings (pinch-zoom blocked by the viewport meta, WCAG 1.4.4; recharts SVG with no text alternative across six usages, WCAG 1.1.1) were reported in BL-648 and appear never to have been written up or fixed.** That is a live loose end, not a citation problem.

## PART 4 — what was fixed

### New: `CONVENTION.md`

Documents the rule and the exact check:

> **A push that would create a path which ALREADY EXISTS on `origin/main` is a COLLISION. Stop, take the next free ID, push that instead. Never fast-forward over it, never overwrite, never `--force`.**

```bash
git fetch origin
for f in BL-688.md; do                       # every NEW report in this push
  if git ls-tree origin/main "reports/$f" --name-only | grep -q .; then
    echo "*** COLLISION: reports/$f already exists on origin/main — NOT pushing ***"
    exit 1
  fi
done
```

`git ls-tree origin/main <path>` prints a blob line if the path exists on the **remote** and nothing if it does not, so `grep -q .` is the whole test. It reads the remote ref rather than the working tree, which is what makes it correct under concurrency.

It also documents reading the ceiling **numerically** — `sort -t- -k2 -n`, because a plain `sort` puts `BL-99` after `BL-681`, which is one way a ceiling gets misread — how to handle a rejected push, when editing an existing path is legitimate, and the prose-reservation rule from PART 2. `README.md` now points at it.

### The check works — it fired TWICE during this round

The guard refused a push twice, on ids that were free when I read the ceiling:

```
*** COLLISION: reports/BL-682.md already exists on origin/main — NOT pushing ***
*** COLLISION: reports/BL-683.md already exists on origin/main — NOT pushing ***
```

Another agent published `BL-682` (mood-from-text) and then `BL-683` (`energy_step_ts`) while this round ran. **Under the old procedure both would have been silent overwrites of their work — two more destroyed reports, produced by the very round whose purpose was to stop that happening.** Each time I re-read the ceiling from `origin/main`, resynced, regenerated the recovered reports deterministically from git history, and moved up. Final ids: `BL-686` / `BL-687` / `BL-688`.

That is the strongest evidence here. The race is neither rare nor historical — it fired twice in one afternoon against an agent actively watching for it.

### A third agent hit it too, and solved it correctly

While this ran, commit `99ace1f` landed:

> "BL-676 (ClippersHQ): … Published beside the existing `reports/BL-676.md`, which belongs to a different project (clipper-finder) and was not touched."

They created `reports/BL-676-clippershq-campaign-refusal.md`. **This exposes a second, independent source of collisions: the repository carries reports from more than one project** — `clipper-finder` and `ClippersHQ` — each numbering its own tickets, so the same `BL-NNN` can legitimately belong to both. "Take the next free ID" is the wrong remedy there, because the number is not the problem; the *path* is. `CONVENTION.md` now records the suffix pattern (`BL-NNN-<project>-<slug>.md`) that agent used, which preserves both ticket numbers and every existing raw URL.

## PART 5 — what is still open

1. **The two accessibility findings from PART 2** — pinch-zoom (WCAG 1.4.4) and the recharts SVG text alternative (WCAG 1.1.1) — were reported in `BL-648` and never written up. Not a citation defect; genuinely unfinished work.
2. **The check is a convention, not a hook.** It stops a collision only when an agent runs it. A server-side guard (a pre-receive hook, or CI that fails when a commit modifies an existing `reports/*.md` without a `[citation-repair]`/`[edit]` marker) would make it structural. Not built here — it would be a change to repository infrastructure, beyond this round's scope.
3. **No audit of merge reports overwriting each other** where the title happened to match; the detector keys on title change, so a same-titled overwrite would be invisible to it. No evidence any exists.
