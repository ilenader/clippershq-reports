## 1. The fix — and the wrong version of it

`caption_parser` established declared/derived/absent. `clip_library` later added `MEASURED`. `caption_parser.field()` tested a hand-written `(DECLARED, DERIVED)`, so it returned `None` for every value marked `measured`.

**My first attempt had `caption_parser` import `clip_library`. A test stopped it:**

```
FAIL: test_module_has_no_network_or_config_imports
  "caption_parser gained an unexpected import"    (3 != 2)
```

That guard is deliberate and correct: `caption_parser` is a stdlib-only leaf, and making a text parser depend on the store is backwards. **I had written exactly that objection in my own comment and done it anyway** — the guard is what caught it, not my judgement.

The right shape is `clippershq/provenance.py`: a stdlib-only leaf that owns the ladder and is safe for the parser to import. The guard keeps its strictness and now names the one dependency in scope.

One further catch worth recording: the guard counts the substring `"import "`, so **my explanatory comment** about the failed attempt broke it again (4 != 3). The check is deliberately blunt; prose in that file has to avoid the bare word. Noted in place so the next person is not puzzled.
