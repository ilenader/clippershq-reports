# BL-748 — YouTube funnel audit: the stack is the CORRECT (Spotify) shape, but three fields arriving free at 100% are discarded, and the subs floor is deleting good leads.

**Date:** 2026-07-31 · **Type:** Audit, read-only · **Spend:** $0.00
**Quota used: 101 of 10,000 free units** (one search + one channels.list). No writes, no paid
calls, no code changed.

---

## Headline

1. **The filter stack is correct.** Every gate fires **before** any paid step — the Spotify
   shape, not the Twitch shape. Nothing is applied at the API query level.
2. **`snippet.description` carries an email on 10.0% of channels, arrives free, and is never
   read.** That is 5× the 2% previously attributed to description text, and it is this funnel's
   `socialMedias`.
3. **The subscriber floor is deleting good leads** because `viewCount` — 100% fill, free,
   already fetched — is discarded. Measured case: 26,900 subs but **16.8M views**, dropped.
4. **The contaminated `podcaster` default is still live.**

---

## 1. The filter stack, in firing order

All from `find_contact`, `clippershq/youtube_finder.py`.

| # | gate | line | config key | live value | paid? |
|---|---|---|---|---|---|
| 1 | `/about` fetch | 226 | — | keyless HTML | **FREE** |
| 2 | `fetch_blocked` / `fetch_failed` | 233–239 | — | `BLOCK_STATUSES` | FREE |
| 3 | **subscriber floor** | 247 | `youtube_finder.min_subscribers` | **50,000** | **FREE** |
| 4 | **subscriber ceiling** | 253 | `youtube_finder.max_subscribers` | **5,000,000** (code default) | **FREE** |
| 5 | **country gate** | 264 | `youtube_allowed_countries` | `US,GB,CA,AU,IE,NZ` | **FREE** |
| 6 | **language gate** | 277 | `youtube_allowed_languages` | `['en']` | **FREE** |
| 7 | `passed_filter = True` | 287 | — | — | — |
| 8 | handle + master dedup | 289–296 | — | — | **FREE** |
| 9 | email: listed → **paid resolve** → website | 298+ | — | — | first paid step |

**Every gate is upstream of the first paid call.** A channel rejected on subscribers, country
or language costs $0. Dedup also precedes spend, so a handle already in master is never
paid-resolved. This is the shape BL-744 confirmed correct on Spotify; BL-726's Twitch problem
(gates pushed into the API query) does **not** occur here.

**Wiring verified, not assumed.** `run_youtube_live:1213-1217` reads the floors from config
with the module defaults as fallback, and `run():622-625` passes `min_subscribers`,
`max_subscribers`, `allowed_languages` and `allowed_countries` through to `find_contact`. The
values reach the gate.

## 2. What each filter discards — 50 real channels, live query

One free search on the **live default niche** (`podcaster` → `"business podcast"`), then the
real gate logic:

| outcome | n | correct? |
|---|---|---|
| **low_subscribers** | **35 (70%)** | mostly — **but see the false negatives** |
| non_target_country | 5 | **yes, all five** |
| too_many_subscribers | 1 | yes |
| non_target_language | 0 | gate did nothing here |
| **PASS** | **9 (18%)** | — |

**`non_target_country` — every drop correct.** BD, MA, GR, ZA, DE — including
`2 Cents Podcast` (682k subs, BD) and `Christian Wolf & Eric Demuth` (50.2k, DE). This gate is
doing exactly the job it was added for.

**`low_subscribers` — mostly right, and demonstrably deleting good leads:**

```
TOMorrow Business Podcast      subs= 26,900   views= 16,843,033   <- DROPPED
The Business Round Podcast     subs= 37,500   views=  1,553,334   <- DROPPED
```

**26,900 subscribers and 16.8 million views.** That is 626 views per subscriber — exceptional
reach, and a better lead than several that passed (`The American Business Podcast`: 218k subs,
1.72M views; `Colorado Business Podcast`: 209k subs, 2.29M views). The floor asks the wrong
question, and `viewCount` — the right one — is already in hand and thrown away. **This is the
"looked right, deleting good leads" pattern again.**

**`non_target_language` fired zero times.** Country had already removed the clearly-foreign
channels, and English-titled foreign channels pass. Which brings us to:

**The podcaster contamination is still live and the country gate cannot fully catch it.**
`MERI PODCAST` (236k subs) **passed** with `country=US` — but its listed contact domain is
`meri.et`, an Ethiopian operation. The country field is self-declared and this one is wrong.
The gate is not broken; the niche is.

## 3. The known weak points

| claim | verdict |
|---|---|
| `min_subscribers` 50,000 floor is live and reaching the run | **CONFIRMED** — `config.youtube_finder.min_subscribers = 50000`, passed at `run():622`. It fired on 35 of 50 channels in the probe. |
| `max_subscribers` = 5,000,000 | **LIVE, via the code default.** The key is **absent from `config.json`**, so it resolves to `DEFAULT_MAX_SUBS`. Effective, but invisible to anyone reading config. |
| country gate reads `snippet.country`, ~80% populated | **MEASURED 76.0%** (38/50) — slightly below the claimed 80%. |
| what happens to the other 20%? | **KEPT and flagged**, never dropped. `country_flag = "country unknown"` (line 271), then falls through to the language gate. Correct, and matches Spotify. |
| default niche still `podcaster`? | **YES — still `podcaster`** (`config.youtube_finder.niche`, and the hard-coded fallback at line 1209/1210). |
| fitness / gaming available as alternatives? | **NO.** `NICHE_QUERIES` contains only `podcaster`, `coach`, `business`. The measured-better niches (fitness 68%, gaming 82%) **have no preset** — they can only be reached by hand-supplying `queries`. |

## 4. Contact recovery — and yes, there is an unread field

The Data API exposes no email field, correctly. The funnel's contact path is:

| surface | cost | measured fill |
|---|---|---|
| `/about` page HTML → listed email | FREE (no quota) | not re-measured here |
| `/about` HTML → IG / TikTok handle | FREE | — |
| paid handle resolve (HikerAPI / LamaTok) | **PAID** | — |
| website two-hop scrape | FREE | — |
| **`snippet.description` from channels.list** | **FREE — already fetched** | **10.0% carry an email** |

**`snippet.description` is populated on 98.0% of channels and is never read.** It arrives in
the *same* `channels.list` response already paid for at 1 quota unit per 50 channels — the call
that fetches `subscriberCount` and `country`. Measured on 50 live channels:

- **email present: 5/50 = 10.0%**
- Instagram link: 0/50
- TikTok link: 0/50

So the description is worth reading **for email only** — socials genuinely are not there, and
the `/about` scrape remains the right surface for handles. But 10% is five times the 2%
previously attributed to description text, and it costs nothing.

**This is the direct analogue of Twitch's `socialMedias`:** a field already in the response,
never parsed.

## 5. Fetched and discarded

`subs_fn` requests `part=snippet,statistics` and keeps **two** fields. Everything below arrives
in the same 1-unit call and is thrown away. Fill rates measured on 50 live channels:

| field | fill | currently | worth |
|---|---|---|---|
| `statistics.viewCount` | **100%** | discarded | **the reach signal the subs floor should be using** — see §2 |
| `statistics.videoCount` | **100%** | discarded | output volume / whether the channel is active |
| `statistics.hiddenSubscriberCount` | **100%** | discarded | tells you when `subscriberCount` is **unreliable** — the repo's own "missing ≠ bad" rule should apply |
| `snippet.customUrl` | **100%** | discarded | the `@handle`, free, no scrape needed — useful for dedup and for outreach |
| `snippet.publishedAt` | **100%** | discarded | channel age; separates a 10-year archive from a rising channel |
| `snippet.description` | **98%** | discarded | **10% carry an email** (§4) |
| `snippet.thumbnails`, `snippet.localized` | 100% | discarded | low value |

`search_fn` similarly keeps only `id` and `title` from a `part=snippet` response, discarding
that call's `description` and `publishedAt`.

**Six usable fields, all at 100% or 98% fill, all already paid for.** This is a larger unused
surface than BL-744 found on Spotify.

## 6. Quota reality

Measured unit costs from the live config: `search.list` = 100, `channels.list` = 1 per 50 ids.

| | |
|---|---|
| per query of 50 channels | **101 units** |
| queries per free day | **99** |
| channels seen per day | **4,950** |
| **qualified channels per day** | **≈891** (at the 18% pass rate measured above) |

`/about` fetches cost **no quota** (keyless HTML), and paid handle-resolves come from the dollar
budget, not the quota. So the quota bounds *discovery* only — and it is not the binding
constraint at current volumes.

**Exhaustion is handled properly, and the prior "generic error" problem is fixed.** There is a
dedicated `YouTubeQuotaExceeded` raised only on `403` with `quotaExceeded`/`dailyLimitExceeded`
in the body; `discover_channels` catches it, **keeps everything already found**, and sets
`status['quota_exceeded']`, which `run_youtube_live` surfaces as:

> *"YouTube's free daily search limit is used up. What was found so far has been saved. Try
> again tomorrow."*

`estimate_quota_units` also warns **before** the run if the plan exceeds the daily free quota.
Both the pre-flight warning and the graceful stop are in place.

## 7. Top five improvements, ranked by (leads × quality) / effort

1. **Parse `snippet.description` for an email.** 10.0% fill, field already in the response,
   one regex on data in hand. No new call, no quota, no scrape. Highest ratio by a distance —
   at ~891 qualified channels/day that is ~89 extra emails/day for nothing.
2. **Make the subscriber floor use `viewCount`.** Replace `subs >= 50k` with
   `subs >= 50k OR views >= N`. 100% fill, free, and the probe shows the current floor deleting
   a 16.8M-view channel. Low effort, directly recovers good leads that are being destroyed
   silently.
3. **Change the default niche off `podcaster`, and add `fitness` / `gaming` to
   `NICHE_QUERIES`.** Measured 68% and 82% in-band versus podcaster's demonstrated
   contamination (5/50 dropped on country, plus `MERI PODCAST` slipping through). Currently
   those niches are unreachable without hand-written queries. Config + a dict entry.
4. **Honour `hiddenSubscriberCount`.** When true, `subscriberCount` is not trustworthy, so the
   floor should not cut on it — the same "missing ≠ bad" rule already applied to views on
   Instagram. 100% fill, prevents a class of silent false negatives.
5. **Keep `customUrl` and `publishedAt`.** The `@handle` for free (no scrape, better dedup) and
   channel age for ranking. Lowest value of the five, but near-zero effort.

Not implemented — audit only, as instructed.

## Limits

- **The probe is one query, 50 channels, one niche.** The 18% pass rate, 76% country fill and
  10% description-email rate are from that single sample. Directionally solid, but a second
  niche would move them — and `podcaster` is the *worst* niche on record, so the pass rate is
  likely a floor.
- **`/about` email fill was not re-measured.** Doing so needs 50 HTML fetches against a
  block-prone surface; the funnel's own block-halt exists for that reason. The 2% figure is
  carried from the prior round, not re-verified here.
- **No end-to-end run.** `find_contact` was not executed; §2's gate outcomes were reproduced
  from the real gate logic against the live API payload, which exercises gates 3–6 but not the
  `/about` fetch, dedup or email path.
- **Rank order in §7 is judgement**, not measurement — only #1 and #2 have measured fill rates
  behind them.

## Method

Static reading of `clippershq/youtube_finder.py` (1,332 lines) and `config.json` for the stack,
config values and wiring. One live `search.list` (100 units) and one `channels.list` (1 unit) —
**101 of 10,000 free daily units, $0** — provided the payload for §2, §4, §5 and the fill
rates. Gate outcomes were computed by applying the funnel's own thresholds and
`market_filter.classify_market` to that payload. The API key was read from config into the
client only and never printed. Nothing was written; no paid call was made.
