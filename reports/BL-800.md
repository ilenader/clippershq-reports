## The rebroadcast filter — and the correction that mattered

BL-780 flagged 8.1% of live "streams" as unattended VOD loops. The filter shipped, and the
**first version was wrong in the expensive direction**.

Run against 911 real live channels, the loose version caught 37 (4.1%). Reading the full
titles rather than the truncated ones, **16 of those were real people**:

```
juanlilshow      CRASH OUT BOYZ MARATHON DAY 7                     <- live subathon, day 7
lil_gai          STREAM ENDS WHEN ARTFIGHT ENDS | 72 hour marathon <- live artist
missionaryjorbo  SPIDERMAN 2 MARATHON PULL UPPP 17 DAYS FROM MCR   <- live gamer
naded            Day 12 - LIVE 24/7 - Keep Stream Open To Support  <- explicitly LIVE
emilycc          sleeping until i wake up! 1728 days 24/7 LIVE!    <- live sleep stream
mafiathontv      24/7 MAFIATHON MADNESS                            <- live event
```

**On Twitch a "marathon" is a live endurance event with the streamer extremely present** —
the exact opposite of a rebroadcast. And a bare "24/7" is very often a live streamer claiming
uptime, not a loop. A false positive here is permanent: the channel is dropped *before* the
free panels call and never reconsidered.

Two changes, both driven by the observed titles:

- **`marathon` removed as a signal entirely.**
- **`24/7` demoted to a weak signal** that fires only alongside a word naming recorded content
  (`vod`, `rerun`, `replay`, `compilation`, `archive`, `best of`).

Strong signals that still fire alone: `rerun`, `re-broadcast`, `pre-recorded`, `replay`,
`vod loop/channel/stream`, `on loop`, `not live`, `unattended`, plus rebroadcast login
suffixes (`_vods`, `rerun`, `_replays`, `_247`, `_archive`).

| | loose | **tightened** |
|---|---:|---:|
| caught on 911 live channels | 37 (4.1%) | — |
| caught on 727 live channels (re-measured) | — | **21 (2.9%)** |
| false positives on 20 hand-read real titles | 6 | **0** |

Genuine catches it still makes, verbatim:

```
alinitytv247            24/7 VOD RERUNS | Follow me !s @alinity
cooksuxalwayson         24/7 CookSux Rerun Channel > main @cooksux
stormchase_tv           24/7 StormChase_TV | Best of @stormchaserirl VODS
gamegrumpscompilations  Game Grumps Compilations 24/7 STREAM!
happyhappygal_vod       Official HappyHappyGal VOD Channel
linny                   ...Live again soon enjoy rerun
```

**2.9% against BL-780's 8.1% is expected, not a miss** — BL-780 measured across ASMR and
Animals, where rebroadcasts concentrate, and both are excluded from the shipped ten.

### The enabling change

`title` was arriving in the Helix payload and being discarded — `discover_fn` returned only
`{login, viewers, language}`. Carrying it costs nothing and is the strongest rebroadcast
signal there is. **Titles now present on 911/911 channels**; without it the filter would have
had only login suffixes and would have caught 6, not 21.

**Proof it is wired, not just written:** of the **260 rows this run appended, 0 have a login
that trips the filter.**

## The Twitch login column

`twitch_login` appended to `writer.FULL_COLUMNS` (70 → 71) and written by the Twitch append
path. Master migrated 68 → 71 columns, **58,065 rows unchanged, 0 rows differing outside the
new columns**.

**Populated on 260 of 260 new rows** — `theprimeagen`, `jstanzaweatherman`, `struggle_4`,
`tasyamikhailova`, `supereyepatchwolf`, `saiiren`.

It is deliberately **not** a crossdedup identity key and never written into
`instagram`/`tiktok_handle`: a Twitch login is not a social handle. It is provenance, like
`source_tag`. Nothing about dedup or spend changes — repeats were already caught at the handle
stage before the paid resolve. What changes is that **"which channels have I already
contacted?" is now answerable**, where BL-780 had to word-boundary match 645 logins against
the whole master and could only report "18, several of them coincidences (`button`,
`blueberry`, `allium`)".

## The language correction — recorded in code, not acted on

BL-726's "0 language leaks in 2,669 streams" is **tautological**: the client re-check compares
the identical ISO code Helix already filtered on, so a streamer who sets `en` and broadcasts
in German passes both by construction. The real rate is **1.3%**, hand-checked, after removing
19 of 31 flags that were region tags (`[AUS]`, `[OCE]`, `[SG/EN]`).

The misleading comment at the re-check site is replaced with the corrected measurement. **The
check itself stays** — it costs $0 and does catch a genuinely mislabelled code. It was the
*claim* that was wrong, not the code. No behaviour changed, exactly as instructed.

## Honest limits

- **The run used the LOOSE filter.** It was tightened after reading the full titles, so the
  260 appended rows were screened by the over-catching version. That direction is safe — the
  loose filter dropped *more*, so nothing bad got in — but up to 6 real leads may have been
  discarded from this run's pool and will be picked up on the next.
- **`marathon` removal is a judgement from 3 observed titles.** All three were unambiguously
  live events, but three is three.
- **Discovery was 17:52 CEDT on a Friday** — BL-780's own note applies: it measured 1,128 EN
  streams in general-chat against BL-726's 2,302 on a Wednesday evening, so this pool is
  roughly half of peak. The 911 is a floor.
- The two re-discovery passes returned 911 then 727 channels minutes apart — **live supply
  moves by ~20% within the hour**, so no single count should be treated as the number.
- `test_funnel`'s `APPENDED` constant needed bumping 4 → 5 for the new column. That is fixture
  bookkeeping, but it means the migration test only checks the *last N* columns and will need
  the same bump every time a column is appended.
- One suite run showed `test_spotify_serial_fix` red; it passes in isolation (22 tests, OK)
  and passed on re-run. Flaky under load, not caused by this round — but it is flaky.
