## 1. Two corrections to BL-939, and the first one matters most

**BL-939 said `publish_report.py:133` is "the credential scanner's own call site" and that a miss there "leaves the machine". That is wrong.** The scanner is checked, and always was:

```python
# publish_report.py:99, inside scan()
return proc.returncode == 0, (proc.stdout or "") + (proc.stderr or "")
```

`scan()` reads the return code off the object, exactly as the module docstring promises. The gate was never open. **I am not going to let a report stand that says a credential gate is unguarded when it is not.**

**Line 133 is `exists_on_remote()` — the collision check — and *that* one is a real proxy:**

```python
r = _run(("git", "-C", clone, "ls-tree", "origin/main", "reports/%s" % name, "--name-only"))
return bool((r.stdout or "").strip())
```

git fails → empty stdout → `False` → *"this report does not exist on the remote"* → the publish proceeds. `CONVENTION.md` records **three reports lost** to exactly that ID collision. Held by MEMEBOT-058, so not converted.

**A second real one the sweep buried:** `tools/claim.py:590`, `staged_paths()` returns `[]` when git fails — that is *"nothing staged"*, and the staged check is what these last several rounds have been gating on. Also held by MEMEBOT-058.
