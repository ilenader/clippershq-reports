## 3. The provenance trap, enumerated — 9 keys, 2 modules

BL-837 hit this once. It is not a one-off:

| module | keys with a value but **no provenance entry** |
|---|---|
| `caption_parser` | `caption_chars`, **`is_templated`**, `valence_evidence`, `valence_score` |
| `content_genre` | `medium_conflict`, `genre_declared_raw`, `genre_conflict`, `tag`, **`content_genre_source`** |

`field()` is behaving **correctly** in every case — the consumer rule says an unattributable value reads as None, and these have no attribution. The trap is that the call *looks* right and yields nothing.

Two of the nine matter today:

- **`content_genre_source`** is the exact key BL-837 reached for. It holds the tier (`'declared'`), and `cg.field(rec, "content_genre_source")` returns `None`. The tier lives at `record["provenance"]["content_genre"]`.
- **`is_templated`** is BL-833's caption-template signal. It is unreachable through `field()` — which is how my own blast-radius pass measured it at 0 until I checked why.

## 4. A latent trap that will fire on wiring

`clip_library.py:304-305`:

```python
# the audio axis is not ready. UNKNOWABLE, not False.
put("arousal_audio", None, ABSENT)
put("affect_conflict", None, ABSENT)
```

Honest today. But `put()` is:

```python
def put(name, value, how):
    rec[name] = value
    prov[name] = how if value not in (None, "", [], {}) else ABSENT
```

`how` is used **verbatim when the value is non-empty**. So the moment the audio axis produces a real number, it will be stored with tier `ABSENT`, and every consumer following the rule will read `None` — **for 100% of arousal data, silently.** `caption_parser` already emits both keys, so the wiring is closer than it looks.

Note this same `put()` behaviour is why my tier rule's three hits are **false positives today**: `valence_text` is passed a hard-coded `DERIVED`, but `put()` downgrades it to `ABSENT` whenever the value is empty, so 0 of 755 records carry a wrong tier. I checked before claiming it.

## 5. The check that would work — assert a property, not a name

Name similarity is the wrong instrument, proven above. Two rules in the shape of BL-801's config contract and BL-820's claims manifest — each asserts a property and needs no judgement:

**Rule 1 — no literal tier where a computed one exists.** Implemented and validated in `scratch/bl838_tier_rule.py`:

```
BROKEN  put('content_genre', g, DERIVED)  -> FIRES
FIXED   put('content_genre', g, _gsrc)    -> quiet
```

It catches what name matching cannot, because it keys on the **role** of the argument (position 3 of a storage call) and on whether a `<field>_source` exists anywhere — not on what the variable happens to be called. It needs one refinement before shipping: model `put()`'s value-aware downgrade, or it reports the three false positives above.

**Rule 2 — every key a producer returns must have a provenance entry, or be explicitly exempt.** This is the §3 trap as a one-line assertion:

```python
for key in producer_output:
    assert key in record["provenance"] or key in EXEMPT, key
```

Nine keys fail it today. An `EXEMPT` set makes each exclusion deliberate and reviewable rather than accidental — `caption_chars` is genuinely not a claim about the world; `content_genre_source` genuinely is.

**A third, cheaper than either:** a **producer/consumer coverage report** — for each producer, the fraction of its keys that reach storage. `content_genre` 3/13, `caption_parser` 1/21. That single number, printed after each walk, would have surfaced §2 without anyone sweeping for it.

## The headline: the pipeline works, the cost case does not

BL-835's correction — OCR is 1.397 s/frame, not 16.08 — is **directionally right and quantitatively wrong on this corpus**. Measured on 10 real h264 clips (173 sampled frames):

| quantity | BL-835 | **measured here** | factor |
|---|---:|---:|---:|
| frames KEPT by dedup | 41% | **82.7%** | 2.0x worse |
| dedup cut | 2.4x | **1.21x** | 2.0x worse |
| OCR per frame | 1.397 s | **4.030 s** | 2.9x worse |
| **CPU per 1,000 clips** | **6.6 h** | **16.01 h** | **2.4x worse** |

**Per-frame OCR is still not the 15-minutes-per-clip disaster the 16.08 figure implied** — that part of BL-835 holds, and the 12x mis-costing was real. But 16 CPU-hours per 1,000 clips is a materially different proposition from 6.6, and the decision to run it should be made against 16.

### Why dedup underperforms

**6 of 10 clips deduped to ZERO** — 100% of frames kept:

```
3930662188434470293  sampled=19  kept=19  100%
3933027311380938917  sampled=13  kept=13  100%
3942016323929917782  sampled=31  kept=15   48%
3935703573937379183  sampled=16  kept=9    56%
```

The clips that dedup well (48–60%) are the static-caption-bar format. The ones that do not are ordinary moving video, where every second genuinely differs. **This is the same population split that makes scene detection useless as a sampler** — and it cuts the other way for dedup. A corpus is not uniformly compressible, and the 41% figure appears to have come from the compressible half.

**The mechanism is sound and cheap**: 0.0300 s/frame measured, ~134x cheaper than the OCR frame it might avoid. It is worth keeping at any hit rate. It is just not a 2.4x saving here.

## What was built

**`clippershq/frame_pipeline.py`** — sampler, dedup, OCR, timings.

**Perceptual hash implemented in-module, no new dependency.** `imagehash` is not installed and this repo guards its numpy/PIL ABI, so the 8x8 DCT hash is ~15 lines of numpy. Verified on a real decoded frame: **hamming 0 at noise sigma 1, 3 and 8**.

> A bug worth recording: my first fixture was a hard two-tone image, which makes many
> low-frequency DCT coefficients exactly zero by symmetry — any perturbation flips half of
> them and the hash looks catastrophically noise-sensitive. It was the fixture, not the hash.
> The self-test now uses a realistic gradient and says so, so nobody "fixes" a working hash
> to satisfy a pathological input.

**The three refuted options stay refuted, in code and in tests:**
- scene detection is **not** the sampler (kept only as an optional prefilter) — it returns nothing on 60% of the library
- **no crop** to the caption bar — BL-733: cropped CER 0.219 vs 0.112 full-frame
- **no downscale** — BL-733: max_side=512 took usable match 82% → 36%

**`dedup_frames` always keeps the first frame.** That single guarantee is what makes it usable where scene detection is not: it can never return empty.
