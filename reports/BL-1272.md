## 1. The defect, restated precisely

The operator was quoted five different costs for one thing in a day. None was dishonest;
most were locally correct. The defect is structural: **~70 reports exist and no single place
held the current numbers**, so every round re-derived one from whatever slice it happened to
hold. A per-page cost derived from a truncated run, a lane curve that measured a different
stage, and a cross-link rate measured on a population selected for the outcome all read
identically once they are quoted without their provenance.

**The fix is not another report.** It is one file, machine-checkable, with a lookup a round
can use instead of re-deriving.

## 2. `docs/FACTS.md` — what is in it

Eleven sections. **35 facts** in a machine-readable block, every one carrying value, `n`,
interval, source and date; the human tables carry the same numbers and the guard enforces
that the two agree.

Coverage, as required: **vendor unit prices per platform** (4 token rates plus 3 vendors);
**calls per page** for TikTok (measured 1:1 against the receipt) and Instagram (composed,
and flagged as composed); **pass rates per platform with their own n**; **email rates per
source with separate denominators**, every selected-population figure labelled; **judging
cost free vs paid**; **throughput for capture and for judging kept strictly apart**; and
**lifetime spend per ledger**.

### The lookup is the point

```
.venv\Scripts\python.exe tools\facts_guard.py --list        # every fact id
.venv\Scripts\python.exe tools\facts_guard.py --get <id>    # one fact, fully sourced
```

Asking for a biased figure prints its replacement beside it, so it cannot be quoted alone
even by accident:

```

ig_crosslink_selected = 27.8

```

## 3. The guard, and proof it fires

`tools/facts_guard.py` checks **three kinds of rot**, because they fail differently:

1. **Ledger drift** — recompute the field **from the rows**, never trust the stored header.
2. **Prose/data drift** — every value in the machine block must appear literally in the
   prose. Two copies of a number in one file is how a file starts lying.
3. **Missing denominators** — a `rate` must carry `n`; a `selected_population` fact must
   carry `fresh_alternative`.

**A guard that has only ever been seen to pass is not a guard.** This project has the record
to prove it — `tiktok_send_list.assert_clean`'s dead-MX branch can never fire, three shipped
drawn-text rules fired zero times on 1,885 pages, and `test_config_contract` collects zero
tests and still prints OK through unittest. So the guard was **demonstrated against the real
`docs/FACTS.md`**, not only against fixtures (`scratch/bl1272_guardrun.txt`):

| arm | exit | what fired |
|---|---:|---|
| the shipped file, untouched | **0** | clean, 35 facts |
| `lifetime_vision_usd` typed as 999.0 | **1** | ledger recomputes ~7.08 — total has gone DOWN |
| `lifetime_total_usd` typed as 1.0 | **1** | **STALE** — grown past the band |
| judging throughput edited in the block only | **1** | the value does not appear in the prose |
| a rate with its `n` removed | **1** | *a number without its denominator is not a measurement* |
| the 27.8% figure with its fresh alternative removed | **1** | a biased rate may not sit here alone |

`tests/test_facts_guard.py` — **25 tests, all green**, each planting a specific defect and
asserting the guard reddens on **that** defect by name.

### And the suite caught a defect in the guard that I did not

`tests/test_vendor_sources.py::test_no_module_hand_lists_three_or_more_vendor_keys` went red
on the first full run — **because of me**. `main.py` owns the vendor list
(`main.VENDOR_USD_KEYS`, `main.row_usd`) and my `facts_guard.py` had re-spelled it as a
literal. The consequence is exactly the rot this guard exists to prevent: **the next vendor
added to `main.py` would silently not be summed here**, and `docs/FACTS.md` would
under-report lifetime spend while passing its own check. Now imported, never copied.

That is a guard catching a guard, and it is the reason the round is worth more than a file.

### A hole in my own first version, found by my own test

The lifetime check began as one-sided: `live >= claimed` passes. That let `FACTS.md` claim
**$0.01** against a real **$29** forever — rot in exactly the direction this file is most
likely to rot. The rule is now a **band**: fail if the total went *down* (rows lost), and
fail if it outgrew the snapshot by more than 25% (stale, re-stamp it). At the current
lifetime that band is about $7.4 of new spend — many rounds' worth, so it will not redden on
ordinary use.

### A trap in deriving unit prices from the ledger, recorded because I fell into it

Dividing a vendor column by the row's `calls` field gives LamaTok **$0.00039089** — a price
that has never existed. `calls` is **generic per row, not per vendor**, so rows booking two
vendors corrupt the division. Restricted to rows where exactly one vendor column is
non-zero, the answer snaps to **$0.0006 on 98.4% of rows**.

## 5. The undenominated figures — a ratchet, not a rewrite

**The brief said 18 across five files. 18 is one file's worth.** `clip_pipeline.py` alone
carries 18; the true total across all five depends on how you count, and both counts are
recorded rather than one being quietly chosen:

| method | count |
|---|---:|
| this round's automated scan (a `%` or bare `0.xx` **plus** a performance word, no denominator within ±3 lines, geometry excluded) | **18** |
| a careful manual read grouping contiguous table blocks and accepting looser performance words | **~49** |

Neither is wrong; they count different things. **The automated number is the one a guard can
ratchet**, so it is the one recorded — with the disagreement stated in the file itself.

| file | sites |
|---|---:|
| docs/FINAL_STATE.md | 0 |
| docs/HANDOVER.md | 2 |
| docs/GROUND_TRUTH.md | 0 |
| clippershq/clip_pipeline.py | 8 |
| clippershq/repost_finder.py | 8 |

**Why a ratchet and not a sweep.** `tests/test_bl1254_stated_n.py` already enforces the
denominator rule — but only on `control.py` and `dashboard/static/*.html`. Widening it today
would redden the tree with dozens of failures in files this round has no business rewriting
wholesale, and **a guard everyone has to skip is a guard nobody reads**. So the debt is
counted, recorded, and frozen: `test_the_count_has_not_grown` refuses new debt, and
`test_the_baseline_is_not_silently_generous` refuses a baseline set above the live count,
because slack nobody can see is slack somebody will spend.

**Fixed outright: `clippershq/clip_pipeline.py::measure_label_box`** — the last surviving
copy of the MEMEBOT-085 pair, wrong on **three** counts at once (mis-stated n, stale
threshold, and prose inverted relative to the code — it said bands "at or above"
`TOP_BAND_MAX` where the code gates `top_band <= TOP_BAND_MAX`). The docstring now states
all of it and refuses to advertise the pair as shipped behaviour.

**My own fix tripped my own scanner**, which is worth recording: the corrected docstring
writes `21/23` and `21/22`, and the scanner did not recognise the slash form as a
denominator. The scanner was failing the exact thing it exists to reward. Fixed.
