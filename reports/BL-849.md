## The three-way comparison — they are not substitutes

Same clip, three signals, three genuinely different answers:

**Clip `3371509042222320195_…`**
- **VISION** — *"The clip juxtaposes scenes from a TV show with a man reacting to them…"* → **the structure of the video**
- **OCR** — *"be careful how you treat people HILDI be careful how you treat people…"* → **the caption bar**, repeated across frames
- **SUBS** — *"How come? With your dad? Barney, that's not my dad. His name is Greg…"* → **the spoken dialogue**

**Clip `3384569942634425954_…`**
- **VISION** — *"a split screen… a young man sitting at a desk, looking at something off-screen"*
- **OCR** — *"Best Bankai? Best Bankai? Best Bankai?…"* (the bar)
- **SUBS** — *"I never would have guessed there would be this much difference in our power…"* (the show's dialogue)

Mean length is nearly identical — vision 239 chars, subs 234, OCR 212 — so this is not one signal being richer. **They answer different questions:** OCR gives the page's framing, subtitles give the source's words, vision gives what is happening. For song matching the second and third are the ones with emotional content; the first tells you how the page packages it.

Note the OCR column repeats the same phrase many times: the caption bar is static, so per-frame OCR mostly re-reads one string. That is the dedup problem measured in BL-839 showing up as text.

## What was stored, and how

Six fields added to `CLIP_FIELDS`, all **`derived`** — a generative model inferring from pixels is an inference, not a `measured` detector read, and the tier must not overstate it:

`vision_scene` · `vision_beats` (timestamped) · `vision_on_screen_text` · `vision_title` · `vision_model` · `vision_control_declined`

`vision_control_declined` is the exception: it is stored **`declared`**, because whether the model declined is a *fact about the exchange*, not an inference about the clip. That matters mechanically — `put()` marks a falsy value `absent`, which would have made `False` unreadable through `field()`, silently hiding exactly the rows that need flagging.

**Two failure modes avoided by construction:**
- **The key is never reconstructed.** The library's own `clip_id` is used verbatim. `pk + "_" + uid` joined 0 of 100 in an earlier round because `media["id"]` already *is* `<pk>_<uid>`.
- **Rows are merged, not rebuilt.** Each labelled clip is copied, given a higher `rev`, and re-appended — so no field an earlier round wrote is dropped by a pass that never knew about it.

Declaring the fields rather than writing them undeclared was deliberate: an undeclared key is unreadable through `field()`, which is the trap `speech_frac` is still in (BL-847).

## Limits

- **The pass is incomplete**, and the fabrication rate is measured on the 178 done. One event is one event: the 95% interval on 1/178 runs roughly 0.01%–3.1%, so "0.56%" is a point estimate with a wide interval, not a settled figure. It will firm up as the pass completes.
- **The three-way used 4 clips, not 10+.** 50 candidates exist; each needs a re-retrieve, a subtitle fetch and an OCR pass, and it was competing with the labelling run for the same network and CPU. The qualitative finding is clear at 4; the quantitative one is not attempted.
- **`vision_title` is unverified.** 56.7% of rows offer a title and nothing here checks any of them against the caption. That is the obvious next measurement and it is free — the captions are already stored.
- **The library grew during the run** (634 → 664, another round appending), so the denominator moved. Percentages are as of the moment quoted.
- **Suites were not re-run at report time** — the labelling process holds the library open and a full run competes with it. The only code change is additive to `CLIP_FIELDS` and `build_record`, verified directly: provenance tiers assert correctly and `False` reads back through `field()`.
