## 2. The name is the whole incident

```
import name    spotify_scraper     (underscore)
distribution   spotifyscraper      (NEITHER hyphen NOR underscore)
```

Measured:

| looked up as | `importlib.metadata.version()` |
|---|---|
| `spotifyscraper` | **3.9.2** |
| `spotify-scraper` | `PackageNotFoundError` |
| `spotify_scraper` | `PackageNotFoundError` |

BL-1147 looked up the hyphenated form, got nothing, and wrote *"no version of it is installed
here — the spotify funnel therefore cannot run here today"* into a file that a launcher builds
a venv from. One wrong hyphen turned into a requirements file that would have made its own
false claim true.

## 3. What nobody had done: build it and import it

Every claim in this chain was made by **reading** — BL-1147's *"not installed"*, my BL-1150
*"pip name: spotify-scraper"*, BL-1149's correction. Two of those three were wrong. So this one
is made by **building** (`scratch/bl1151_verify.py`):

```
pin found in requirements.txt : spotifyscraper==3.9.2
the 'cannot run here today' claim is still in the file : False
a retraction is present in the file                    : True

building a clean venv WITHOUT system site-packages...
control - can the EMPTY venv import spotify_scraper? CLEAN
installing spotifyscraper==3.9.2 from the file...

IMPORT_OK 3.9.2 SpotifyClient
```

**The control is the load-bearing part.** A venv created with system site-packages inherits the
3.11 install that already has the module, and the test would pass while proving nothing — which
is precisely how the original claim went unchallenged for a day. The empty venv reported
`CLEAN`: it could not import `spotify_scraper`. After installing **only the line this file
ships**, `from spotify_scraper import SpotifyClient` — the exact statement at
`spotify_finder.py:1323` — resolves.

The pin is extracted from `requirements.txt` by regex rather than retyped, so the test cannot
pass against a pin the file does not actually carry.

**Scope, stated:** the Spotify line and its dependency closure, not all fourteen pins. numpy,
opencv, onnxruntime and faster-whisper are hundreds of megabytes and the disk has been full
here before. The claim under test was narrow and so was the test.
