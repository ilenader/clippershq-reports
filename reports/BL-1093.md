# BL-1093 — the unwalked backlog is 8 pages, they yield 3 clips, and the ~11.6 average was survivorship

The walk is finished. What is left is not 67 pages worth ~780 clips, and it is not 8 pages
worth ~91 either — **it is 8 pages worth 3 clips**, and the reason the estimate was 30×
high is worth more than the clips.

**$0.0364 of a $0.60 cap**, across both legs.

BL-979's 67-page backlog is gone; the ordering fix did its job and this round found the
remainder down to 8.

**My own estimate from these numbers was wrong and it is worth saying why.** At the measured
11.32 clips/page the 8 pages should have yielded ~91 clips. They yielded **3**.

> **11.32 clips/page is a survivorship number.** It is computed over accounts that are IN the
> library, and an account is in the library precisely because it yielded clips. A page that
> returns nothing leaves no row and no trace — and pages that yield nothing are exactly the
> ones that stay unwalked. The average of the walked can never estimate the unwalked.

## 7. What I got wrong

**Five invented signatures in one round.** I wrote call sites from memory instead of reading
them, and each cost a run:

| what I wrote | what it is |
|---|---|
| `build_record(taken_at=…)` | no such parameter |
| `IncrementalMeter(path, vendor=…, cost_per_call=…)` | takes a `record_fn`, a label and a campaign |
| `IgClient(cfg)` | first positional is the **API key** |
| `pool_filter(...)` → one name | returns a **tuple** `(clips, why)` |
| `record_retrieval_spend_fn(calls)` | is called as `(leg_cost, pages)` |

The third one was not merely a crash. Passing the config dict where the API key belongs put
it in an HTTP header, `requests` raised `InvalidHeader`, and **the exception text contained
the entire config including the live API key**, which landed in the run's output file. I
deleted that file and confirmed the key appears nowhere in the working tree outside
`backups/`, which is gitignored. *That path is still open* — see §9.

**And the walk's own spend did not reach the ledger.** The two `CLIP_LIBRARY` rows it wrote
carried `ig_calls=None, cost=$0.000000` while the client warned that **8 billed requests were
never written** — the BL-876 leak, live, in my wiring. I recorded the $0.0048 explicitly
afterwards. My first attempt at the cap was worse: `spent_fn=meter.spent_fn() if
hasattr(...) else None` would have **silently** passed `None` and left the cap governed by
counted calls rather than billed dollars, which is precisely the hole the brief opens with.

**`run()` over-counts paid calls when master supplies the pk.** It reported 16; the client
billed 8. `_open` increments `paid_calls` unconditionally, including for the resolve it
skipped. The cap is conservative in the safe direction, but the reported call count is wrong.
