## A correction to the brief's premise for fix #3

The brief says to *add* a skip list. **One already exists.** `enrich_links.py` defines
`_SKIP_OUTBOUND_REFERENCE`, and it already contains `'wikipedia.org'`, `'wikimedia.org'`,
`'wikidata.org'`, `'wiki.'`, `'fandom.com'`, `'imdb.com'`, alongside `_SKIP_OUTBOUND_HOST`
(cdn, gstatic, googleapis, google-analytics, googletagmanager, doubleclick, …) and
`_SKIP_OUTBOUND_COMMERCE`.

So the real defect is **not a missing list — it is that the list is not reaching the fetch
path that made these 827 requests.** The wikipedia fetches are logged by
`urllib3.connectionpool`, and `enrich_links` itself logged only **8 lines in the entire run,
none carrying a URL** — which is also fix #2 in miniature: the scraper's own per-fetch
activity never reaches the log, so the host list above had to be reconstructed from urllib3's
DEBUG output rather than from anything the module reports.

Whoever picks this up should diagnose why the existing skip is bypassed before adding a
second one. Adding a parallel list next to a working-but-unreached one would leave the bug
and double the maintenance.

**Caveat:** `enrich_links.py` was modified at 18:28:50 while this was being written, so the
skip-list contents quoted above may already have changed. They were read at ~18:28. The log
analysis is unaffected — the log is immutable evidence of what the code did on 2026-07-29.
