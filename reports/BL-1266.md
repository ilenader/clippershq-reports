## 0. The price model is solved from the receipts, not looked up

Every dollar below comes from a `usage_raw` block the vendor returned. Four rates are
solved from two records that differ in exactly one term each — the two attempts of a single
forced-truncation test in `scratch/bl1263_retry_proof.json`:

| | prompt | cache write | cache read | output | vendor receipt |
|---|---:|---:|---:|---:|---:|
| attempt 1 | 10,505 | 9,863 | 0 | 600 | **$0.07985375** |
| attempt 2 | 10,505 | 0 | 9,863 | 842 | **$0.02919150** |

```
input $5.00/M   output $25.00/M   cache write 1.25x = $6.25/M   cache read 0.10x = $0.50/M

attempt 1:  642*5e-6 + 9863*6.25e-6 + 600*25e-6  =  0.07985375   EXACT
attempt 2:  642*5e-6 + 9863*0.50e-6 + 842*25e-6  =  0.02919150   EXACT
```

Not "to the cent" — to eight decimal places. The model was then re-priced against **all 30
recorded attempts across six files**: `scratch/bl1266_usage.py` reports **0 mismatches**.

**One receipt fought back, and the reason is worth keeping.** A cached-arm call in
`scratch/bl1258_cache_probe.json` appeared to be $0.0123 over model. The round's own flat
summary row records `cache_write_tokens: null` while the vendor's nested block right beside
it records **9,863**. Solving the receipt backwards returns 9,863.0 exactly. So the charge
was real and the summariser dropped it. `dict.get(k, default)` returns a stored `None`
rather than the default, so any reader that trusts the round's copy instead of the vendor's
block silently prices a cache write at zero. **Read the vendor's block, never a round's
transcription of it.**

### The finding he has not been told: the invisible half is the expensive half

A 1,500 cap is **2.5× the largest visible reply ever observed** and looked generous. It cut

`BL-1258 cached rate run (OVER CAP - see report)`, **$0.522053**; 0.228 / 0.522053 = 43.7%,
so the waste reconciles against its own ledger row. Two of the five spent the entire 1,500
on reasoning and emitted **zero characters**.

Output is billed per token **generated**, not per token **allowed**, so raising the cap to
3,000 cost essentially nothing per page and took cost per *usable* verdict from $0.074579
