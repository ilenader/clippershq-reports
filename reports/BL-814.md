## 1. The export now names the two numbers so they cannot be confused

`median_views` is **gone**. The merge block is now:

```
handle, display_name, fandom, fandom_display, fandom_is_character,
followers, clip_views, clip_date, rank_median_views
```

| column | source | what it is for |
|---|---|---|
| **`clip_views`** | `matched_video_views` | **THE SENTENCE.** One real video. |
| **`clip_date`** | `matched_video_date` | the date of that video, so the claim is checkable |
| **`rank_median_views`** | `deep_median_views` | **RANKING ONLY.** Never prose. |

The median is kept because ranking is exactly what a median is good for — it is the honest reach signal — but the name now states its job. A template author reaching for a views number can no longer pick the wrong one by accident.

`clip_views` is also in `_BLANK_IF_ZERO`, for a sharper reason than tidiness: a zero would render *"the one at 0 views"*, a checkable claim that is false. Blank makes the row visibly unusable for that template instead of quietly wrong.

**The leading ten columns are byte-stable**, so an existing consumer is untouched. A regression test now asserts both the new block and that `median_views` is absent.

## 2. Character-name tags are flagged, not classified

New `fandom_is_character` column, driven by a **hand-maintained list**. BL-794 tested and correctly rejected a classifier: length cannot separate these, because `frieren` (418 rows) and `bleach` (380) sit right beside `shoko` (224) and `mikasa` (211). No threshold splits them, so none is used.

The list starts from the five BL-811 swapped (`rapunzel`, `sophie`, `daisy`, `howl`, `ryan`) and extends to names of the same shape.

**Three names are deliberately EXCLUDED — `frieren`, `power`, `violet`.** Each is a character name that is *also* how the show is commonly tagged; "Frieren" is the everyday short title and carries 418 rows here. Flagging them would demote a correct title tag at scale. **When a name is both, the title reading wins:** a false flag costs a good lead swapped out, and there are far more of those than there are Sophies.

It flags. It never cuts.

## 3 & 4. The name and tag defects, both fixed at export time

| input | before | now |
|---|---|---|
| `display_name` = `priz.cc` | **"Hi priz.cc"** | `prizclips` — falls back to the handle |
| `display_name` = `www.foo.com` | "Hi www.foo.com" | `foohandle` |
| `#upedits` | **"#up"**, then *"saw your #up edits"* | **blank** — unusable, visibly |
| `#arcaneeditsedit` | `arcaneedits` → *"your #arcaneedits edits"* | `arcane` |

**The domain guard**: a display_name that is a URL or a bare domain passes the has-a-Latin-letter test and reads as a website, not a person. It now falls back to the handle — which is exactly what the greeting said before `display_name` was wired at all, so this can never be a regression.

**The double-suffix guard**: the suffix strip now runs **repeatedly**, so `arcaneeditsedit → arcaneedits → arcane`. Verified: **zero fandoms in the corpus end in `edit`/`edits`**.

**The short-stem guard**: a stem under 3 characters returns blank. `Up` is a real Pixar film, and blanking it is still the honest call — a sender can write a specific line, and a blank field is visibly missing where `up` is silently wrong.

**This half-shipped state has already caused downstream damage.** BL-810's UI audit — published one round ago — documents the `[o]` menu as offering *"[4] Mark a whole sent list"* and describes its dry-run behaviour in the present tense. **The live menu at `control.py:3119–3121` has exactly three options.** A careful reader inspected the surviving schema and documented a feature that does not exist. That is the specific failure mode a half-reverted round produces: the evidence that remains is real, and the conclusion drawn from it is false.

**Restored this round:** `SEND_TRACKING_COLUMNS`, `RECORDABLE_COLUMNS`, and validation so both fields are accepted.

**NOT restored:** `mark_sent_from_csv`, `build_key_index`, and the `[o][4]` menu entry. **BL-797 is the complete specification** — including the measured index-once design (0.18 s against a projected 121 s looped, and the reason `match_indices` must not be looped) and the ghost-key finding that was really an address-normalisation mismatch. ## Limits

- **Item 6 is not attempted**, not estimated. There is no number in this report for the block boundary.
- **The rendered sample was built against my 22:34 master backup**, not the live file, precisely because the live file was moving. It is a snapshot of 58,325 rows.
- **The character list is hand-maintained and incomplete by construction.** It will miss names nobody has hit yet. That is the accepted cost of refusing a classifier the evidence does not support.
- **`_DOMAIN_NAME` is a TLD allowlist.** A display_name on an exotic TLD will pass through as a name.
- **Item 5 is half-restored.** Validation accepts the fields; nothing bulk-stamps them and no menu reaches them. A pilot still cannot record which follow-up or which message a row received.
- **`clip_views` derives from `avg_views_sampled`** via `_views_fields`, so it inherits that field's provenance: it is the surfaced video, which the feed ranked *because* it performed. It is a real clip with a real date — it is not a typical clip.
