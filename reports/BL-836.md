## 2. The provenance rule — and why it is in a sidecar, not the CSV

The rule ships in **three** places: the module docstring, both menu handlers, and a `clips_<ts>.README.md` written beside every export.

```
declared   the platform payload said so, verbatim
measured   computed from the actual pixels (currently `layout` only)
derived    this pipeline inferred it
absent     not available

zero-inference subset  ->  *_src IN ('declared', 'measured')
NOT                    ->  *_src == 'declared'
```

**A judgment call worth stating plainly.** The brief said the rule must be "documented in the file's own header." I put it in a sidecar instead, because `#` comment lines at the top of the CSV would break `csv.DictReader` and every naive consumer — the exact audience this format exists for. Python's csv module does not skip comments. **A self-describing file nobody can parse is worse than a parseable file with a README.** A test asserts the CSV begins with `clip_id,` and never a `#`.

The `unattributed` tier is preserved: a populated value with no provenance entry exports as `unattributed`, never as a silent `declared`. There are none today; the column keeps it visible if it returns.

**682,477 bytes of real video, one page, one call.** The claim BL-833 could only read from source is now measured.

**And the round trip produced live confirmation of BL-798 that nobody had captured before.** The library's stored rendition inventory for that clip was:

```
stored heights : [1280, 1280, 1280]
```

The fresh manifest served **360x640** — a rendition **not present in the stored inventory at all**. The ladder does not merely reorder between fetches; it can offer entirely different rungs. That is the strongest possible argument for the never-export-a-URL rule, and it arrived by accident.

`retrieval_depth_hint` stays, and stays honest: it is an **age heuristic, not a measured page count**. A 20-day-old clip on an account posting 30×/day is not on page 1, and the library does not store posting rate, so this cannot be improved without new data. The docstring, the README and a test all say so.

## 4. The rendition-URL guard is enforced by test

`tests/test_clip_export.py` — **23 tests**. The load-bearing class is `NoRenditionURLEverEscapes`:

- poisons `media_renditions` with `https://scontent.cdninstagram.com/expiring/thing.mp4?oe=DEADBEEF` and asserts `cdninstagram`, `.mp4` and `oe=DEADBEEF` are all absent from the export;

- asserts the capability summary still survives the stripping (`rendition_max_height` 1920, `rendition_count` 2, codecs include `avc1`), because a guard that also destroys the useful part is not a fix.

Verified against the real 755-row export: **zero non-permalink URLs**.

A test I got wrong first is worth recording: I asserted an empty value yields empty provenance. It does not — the real writer marks unavailable fields `absent` (measured: `content_genre` is `absent=466 / derived=289`). The fixture was unrealistic, not the code. The test now covers both `absent` and genuinely-missing-from-provenance as distinct states.

## Honest limits

- **The retrieval round trip was one clip, the newest in the library, bounded to one page.** It proves `clip_id` is sufficient for a page-1 clip. It says nothing about whether a `deep-walk` clip (5% of the library, up to 1,675 days old) is reachable at all — that would cost many calls to find out, and this round was authorised for one.
- **`retrieval_depth_hint` remains unvalidated.** No clip was retrieved at a depth that would test the bands.
- **`medium` is still empty**, by the decision above. The column exists; nothing fills it.
- **The library grew during the round** (a paid walk was running), so 755 is a snapshot. Re-running the export gives a different count, which is correct behaviour, not drift.
- **The claims manifest proves symbols exist at HEAD, never that they are correct or reachable.** `verify_claims` says the menu key is in both the listing and the dispatch; it cannot say the export is useful.
- **I exercised both entry points by calling their handlers directly**, not by driving the interactive menu through stdin. The dispatch wiring is covered by the `menu:` claim rather than by a keypress test.
