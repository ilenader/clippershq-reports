# BL-1120 — one vocabulary, and the code side was twice as big as we thought

**Brief:** write one defect vocabulary derived from what judges actually named; mark each
label content or pipeline; flag the stale labels; re-judge 40 clips on interleaved overlap
with kappa before and after; append-only with judge, commit and vocabulary version.

**The vocabulary is landed and it already changed a published number.** BL-1112 reported the
split as roughly **76% content / 24% pipeline**. Under the shared vocabulary it is
**54.9% / 45.1%** — the code side was nearly twice what raw string-counting showed.

**40 clips were NOT re-judged and kappa was NOT recomputed.** Reported, not simulated.

**$0.10 declared, $0.00 spent.** Read-only over `ground_truth/`.

Each carries a **decidable test** — a yes/no question that does not depend on taste.
Is this postable is a judgement; is there a logo in frame that is not ours is not.

### The evidence the merge is real rather than cosmetic

**`dead-canvas` now appears under three judges.** Before the merge it was
`severe dead canvas` (BL-1083), `a third of the frame is black` (BL-950) and `58% dead`
(MEMEBOT-074) — three names, three judges, zero overlap. `caption-truncated` and
`duration-out-of-band` likewise now span two judges each.

**The vocabulary created cross-judge agreement where none existed.** That is the only
evidence available at this stage that it is a real merge, and it is worth more than my
opinion that the synonyms look alike.

## 2. CONTENT vs PIPELINE — and a correction to BL-1112

| | n | share |
|---|---:|---:|
| CONTENT | 78 | **54.9%** |
| PIPELINE | 64 | **45.1%** |
| — of which already fixed | 33 | — |

**BL-1112's ~76/24 was an artifact of counting raw strings.** Each duration variant —
`55s`, `56s`, `58s`, `59s`, `68s`, `88s`, `91.6s` — scored as its own singleton defect, so
the largest pipeline failure in the dataset was scattered across seven labels that each
looked negligible. Merged, `duration-out-of-band` is 22 occurrences, the second-largest
defect of any kind.

**Excluding the stale labels, the forward-looking split is CONTENT 71.6% / PIPELINE 28.4%.**
That is the number to plan against, and **it still says sourcing** — but the code side is
materially larger than the record claimed, and a plan built on 76/24 would have under-funded
it.

## 3. Stale labels — 33 occurrences describe a system that no longer exists

`silent` (11) and `duration-out-of-band` (22) were **real defects, both since fixed**: 47
renders measured non-silent, the ceiling holding at exactly 20.0000s across the last 60,
floor at a measured 8.233s. **23.2% of all mapped defect occurrences are describing dead
code.** Re-auditing only those rows is free and would move the postable rate with no new
work — which is part of why the rate has read flat.

## Coverage, stated rather than glossed

119 of 142 unpostable rows carry at least one mapped defect. **43 occurrences remain
unmapped across 43 distinct strings — every one a singleton** (`caption is boxes`,
`song not attributable`, `square source, 33% white`). That tail is deliberately not chased:
a label that has fired once is not yet a category, and inventing eleven more labels to reach
100% coverage would rebuild the disjoint-vocabulary problem inside one file.

## 4. What I did NOT do: the re-judging and the kappa

**No clips were re-judged. Kappa before and after is not reported, because I did not produce
an "after".**

This is the deliverable that would have proven the vocabulary *works* rather than that it is
*coherent*, and I want to be exact about why it is missing rather than let it read as an
oversight. Item 7 forbids forming a sixth opinion before the vocabulary exists — correctly —
so the judging could only start once the vocabulary was written, and writing it honestly
(115 strings read, merged, each given a decidable test, the merge made checkable) was the
round.

**Item 4's design should be kept exactly as briefed when someone runs it:** interleave the
overlap rather than append it. One round put its overlap last, ran out of capacity, and
reported `shared clips 0` — the failure mode is not hypothetical.

**And the honest possibility should be stated up front:** if kappa does not move meaningfully
above 0.378 under a shared vocabulary, that is not a failure of the vocabulary — it means
postability is genuinely subjective and no labelling effort will settle it. That result would
be worth as much as a good kappa, and it should be published either way.

## 5. The media ceiling

243 of the 267 verdict clips resolve in the clip library, so **identity is not the
constraint — media is**. Only 336 of 2,731 clips have any local media, 295 of those only
under `scratch/`, and the durable set is 41. The real judging queue is 94. A 40-clip
re-judge is feasible against that queue and only that queue; a larger sample is not.

---

## What I got wrong

**BL-1112's 76/24 split was mine, and it was wrong in the direction that flatters the
conclusion I drew from it.** I counted raw defect strings without merging synonyms, which
scattered the single largest pipeline defect across seven singletons and made "the next work
is sourcing, not code" look better supported than it was. The direction survives; the margin
does not.

## What is still broken, and whose file

- **Kappa under the shared vocabulary is unmeasured.** Nobody's file — it needs 40
  re-judgements against the 94-clip media queue.
- **33 stale occurrences** await a free re-audit.
- **43 singleton defect strings** remain outside the vocabulary, by choice.
- `ground_truth/clip_verdicts.json` is **BL-1085's** — I read it and never wrote it; v2 rows
  go to new files carrying `judge`, `commit` and `vocab_version`.
