## 1. `apply_vendor_costs` — landed

`row_usd` fixed every **reader** five rounds ago. Both **writers** kept building their numbers by hand:

```python
_record_spend_locked      run_cost = round(tt_cost + ig_cost + tikhub_cost, 6)             # 3
_record_aux_spend_locked  run_cost = round(tt_cost + ig_cost + tikhub_cost
                                            + link_cost + vision_cost, 6)                  # 5
```

plus five hand-written `d["X_spent_usd"] = ... + X_cost` accumulators each, and a hand-written `d["total_spent_usd"]` — **the field every cap actually reads.**

That hand-maintained list produced the same omission at three separate depths, each invisible because the number still looked like money: `record_aux_spend` had no vision field at all; `run.py` re-summed by hand for the per-campaign cap; `dashboard/server.py` omitted it while under-reporting **26.8%** of the total.

**Adding a vendor is now one edit — its key in `VENDOR_USD_KEYS`.**

| | |
|---|---|
| readers | `row_usd()` |
| writers | `apply_vendor_costs()` — both call it |
| per-vendor running total | `VENDOR_TOTAL_KEY`, **derived** from the same list, not re-listed |
| `total_spent_usd` | written in **exactly one place**, asserted |

`_record_spend_locked`'s row now also carries all five vendor keys instead of three. That was latent rather than active — `row_usd` reads a missing key as zero — but it made the ledger's shape depend on which flow wrote the row.

**Verified against both writers and the live ledger:** every row's `row_usd` equals its own `dollars` field, and across 220 real rows the sum equals `total_spent_usd` to the cent.

## 4. The attestation rule — recorded

> **"Cannot run" and "nothing depends on it" are different properties.** Before deleting any tracked file, check `docs/claims/` as well as the import graph.

BL-948 verified ten scratch probes broken — each named a symbol HEAD no longer defines, nothing imported them — and deleted them. One, `scratch/memebot028_audit.py`, is named in `docs/claims/MEMEBOT-028.claims` as a `file`, a `func` and a `const`. That manifest is checked against `git show HEAD:` and is **permanent**. Deleting the file did not tidy anything: **it made a published claim false.**

**The mistake was checking one kind of dependency and concluding there were none.** The import graph answers *does anything call this*. It does not answer *does anything attest to this*, and nothing about a broken file suggests the second question. `docs/ORPHAN_RULE.md` now carries the check, and the rule that you **restore the file, never amend the manifest** — editing another round's published claim so it agrees with your deletion makes the record match you by rewriting what it attested to.
