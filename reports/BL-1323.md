## 2. Why one honest sentence became a false one

`media_by_url` **already captured** the status and body. It had four different failure returns
and gave **all four the same reason key**, and the batch loop then **hard-coded** that key and
its sentence over every failure — discarding the detail it had just collected.

So four causes needing four different responses from you all arrived as *"check your links"* —
the single most expensive thing you could have done, because they were fine.

### Each cause now has its own key and its own sentence

| status | key | what you are told |
|---|---|---|
| 5xx | `vendor_unavailable` | *"the data provider was down (HTTP 5xx) — this is their server, not your link. **Your links are fine.** Wait a few minutes and paste the same list again."* |
| 429 | `rate_limited` | *"the data provider rate-limited us — too many requests too quickly. **Your links are fine.** Wait a minute and run the same list again."* |
| 401/402/403 | `vendor_auth_or_billing` | *"the data provider refused our key or our credit — nothing to do with your link. Check the API key and the account balance."* |
| 200, unreadable | `response_not_understood` | *"the provider answered but we could not read the answer — their response changed shape. **Your link is fine.** This one is ours to fix"* — and it now records the top-level keys it actually saw |
| 404 | `could_not_resolve` | the original sentence, kept, for the one case where it is true |

**These four are not "physical refusals".** A gateway error is a failure to retry, not a
property of your clip, so they no longer count as "this post cannot be made" — which is what
stopped a four-minute outage being recorded as 59 dead posts.
