## 1. Transport is not content

`vision_attempts` is a **retirement budget**, not a diagnostic counter: past `MAX_ATTEMPTS` a clip is never selected again. It exists to stop paying forever for media that cannot work — no DASH manifest, a response that will never parse, a file too big to send. Those are facts about the clip, and a second attempt genuinely tests them.

An HTTP 502 is a fact about **the vendor on that minute**. Retrying it tests nothing about the clip, so charging it there spends a content budget on an outage.

**VERIFIED, the new behaviour:**

| failure | attempts charged | recorded |
|---|---:|---|
| `openrouter HTTP 502` | **0** | `kind=transport`, `vision_transport_failures=1` |
| `no video_dash_manifest` | 1 | `kind=content` |
| **four consecutive 502s** | **0** | clip **still fully selectable** |
| two 502s + two content faults | 2 | correctly **retired** on the content ones alone |

**The cost is recorded either way.** The money was spent and the fact of it must survive the run; what changes is only whether it counts toward never trying again.

**An unrecognised reason counts as CONTENT.** That is the conservative direction and it is deliberate: a novel content bug must not become an immortal retry loop. The transport marker list is written out explicitly so it can be read and argued with rather than trusted.

## 3. The falsification rule, recorded in the module

Written into `clip_vision.py` above the estimator, because it is why BL-934's result can be believed:

> BL-934 confirmed its axis change by retrieving 10 clips it had newly **recovered**. All 10 were found. **That result alone proves nothing** — it is equally consistent with a correct filter and with one so permissive it recovers everything. What makes it evidence is the other test: 8 clips the new axis newly **excluded**, of which 0 were found.
>
> **THE RULE: a confirming test cannot distinguish a correct filter from a permissive one. Whenever a change moves items across a boundary, sample BOTH sides — what it let in and what it kept out — or the result is not evidence about the boundary.**
>
> The same shape applies to every gate here: a view floor, a duration window, a spend cap. Measuring only the survivors measures the survivors.

## Limits

- **The 92% saving is still not measured on a live dead clip.** Fixture and historical data only. The library no longer holds a clip that is both dead and eligible, so this may not be testable here at all.
- **`clip_pipeline.py` still opts out of `clip_views`.** Held live by BL-899. One argument, whenever that file is free.
- **Only the LAST error is stored**, so a clip whose earlier failures were transport and whose final one was content cannot be identified. Those stay retired and are reported as unknowable rather than counted. The new `vision_transport_failures` counter fixes this going forward, not backward.
- **The transport marker list is a substring match on a free-text reason string.** It is what the runners store, and a runner that phrases a timeout unusually will be classified as content — retired sooner, not never, which is the safe direction but still wrong.
- **One clip was retired this round on `unparseable` during a vendor outage.** Under my own rule that is content and it was charged correctly, but I cannot rule out that the malformed response was itself a symptom of the outage. **GAP: content-versus-transport is decided by the error string, not by correlating with vendor health.**
- **The re-open sweep found 0**, so the repair path for retired clips is exercised only by the sub-threshold case and by unit tests. The `--apply` branch for genuinely retired clips has never run on real data.
- **I did not re-run a labelling pass to exercise the new classification at scale.** Two 502s in one small pass is the whole live sample.
