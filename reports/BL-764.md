### The cause, per funnel

Both send predicates open with the identical two lines:

```python
verdict = str(row[_F["verdict"]] or "").strip().upper()
if verdict not in BOT_READY_VERDICTS:     # {'EDITOR', 'LIKELY'}
    continue
```

**Five funnels — spotify, twitch, google_play, email_finder, kick — never write a `verdict` at all.** It is blank on 100% of their 1,995 rows. Every one is discarded on the first line of both send paths, before their email is even looked at. **1,306 valid, deliverable addresses sit behind that check.**

**repost_finder is different and genuinely empty.** It *does* write a verdict on all 42 rows, but never `EDITOR`/`LIKELY` — it records a page-format verdict, a different vocabulary. It also holds **0 emails and 0 profile URLs**. There is nothing to send; it stores pages, not contacts.

**A second, independent blocker for the DM list.** `dm_list_rows` also requires a profile URL, and `instagram_url`/`tiktok_url` are empty on nearly all of these rows — Spotify has one on **14 of 1,233 (1.1%)**. So even a verdict alone would not open the DM path for them. The handle is present on 1,233 of 1,233; only the derived URL is missing, and `writer.handle_url()` already exists to build it.

### Yes — this is exactly the BL-746 class of loss

You asked whether the "master keeps 8 of 62 columns" truncation explains it. **It does, and `verdict` is one of the 54 columns that never survives the write.** BL-746 found the Spotify write path discarded name, listeners, country, language and the verify flags. `verdict`, `instagram_url` and `tiktok_url` are in the same discarded set — and unlike the others, these three are not merely informational: they are the fields the send path gates on. The truncation is not a Spotify problem. It is the shared shape of every funnel that was built after the hashtag crawl.

**Yes. Six of your eight funnels produce leads you cannot reach.**

Decide what a "verdict" means for a Spotify artist or a Twitch streamer. `EDITOR`/`LIKELY` is TikTok-editor vocabulary; these funnels qualify a lead on entirely different criteria and are being asked a question they were never designed to answer. That is the real design debt underneath the empty column.

## Honest limits

- **`date_sent` is empty on all 57,386 rows** (BL-757's finding, re-confirmed). There is no bounce history in the system, so "deliverable" here means *the domain accepts mail*, not *this address is good*. A live MX does not prove a live mailbox; expect real bounces above the 1.2% structural figure.
- The +1,232 is a **simulation of the predicates**, not a live run. It shows what the code would emit given the field — it does not prove those leads reply.
- My funnel attribution buckets bare-hashtag `source_hashtag` values (`aotedit`, `mikasaedit`, …) separately from `tt:hashtag:*`; BL-751 folded them into `tiktok_crawl`. Same rows, different labels — it does not move any number above.
- 8 deliverable addresses could not be attributed to a funnel (merged rows whose provenance collapsed).
- Domains only are printed anywhere in this report; **no address local-part appears.**
