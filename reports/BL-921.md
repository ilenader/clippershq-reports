## 2. The fixture rule is documented

New **`docs/TESTING.md`** — five rules, each naming the incident that paid for it. Rule 1 is
the one this round is about, with all three MEMEBOT-050 failures quoted:

| # | what the fixture did | why it could not detect anything |
|---|---|---|
| 1 | 150 s clip widening at 110 s | `overlay=...:shortest=1` **truncated the output to 110 s** — the second half never existed |
| 2 | rebuilt with `concat`, wide half **blue** | blue's luma in `yuv420p` is **~29** against `limit=24`, so after encoding it read as **black** |
| 3 | — | cropdetect emitted **`crop=-718:...`**, a negative width meaning "found nothing", and the regex **skipped the line rather than raising** |

All three returned the output a genuine negative would: *no difference, the exposure is
theoretical.* The doc states the rule as an executable pattern (assert the fixture's duration,
assert its halves differ, before any test uses it) and lists the three traps that generalise:
`shortest=1` truncates the *output*; luma-thresholding detectors see blue as black; and a
tool's "nothing found" may be a **value** rather than an error.

The other four rules consolidate things this repo has re-learned: a guard that cannot fire
(**ten instances**), tests writing production state (**three**), the instrument sharing state
with the subject (**four**, per MEMEBOT-046H's bytecode-cache finding), and skipping loudly.

**No confirmed second instance of the MEMEBOT-050 defect exists in the tree.** Of the two
SYNTH-NO-GUARD hits, one is a diagnostic script rather than a suite, and
`tests/test_clip_media_audio.py` builds its media with `check=True` — so a failed fixture
*raises* rather than silently producing a fixture that cannot detect. That is the property
rule 1 asks for, arrived at by a different route.

**The sweep caught itself twice, which is the part worth reporting.** Its first pass flagged
**116** ASSERTS-NOTHING; the two I checked were both fine — `test_cluster_detect.py` asserts
through a local `check()` helper and `test_cli.py` through `self.fail()` inside an `except`.
Teaching the detector how this tree actually asserts took it to 18. Then SYNTH-NO-GUARD
flagged `test_edit_bed.py`, whose docstring says *"Offline: no ffmpeg, no render, no
network"* — the sweep had read the word **ffmpeg in prose** and concluded the file
synthesises media. Requiring a quoted token inside an argv dropped that class.

A sweep with a 6:1 false-positive rate gets switched off, which is the same failure mode as
the untestable fixtures it hunts. **Remaining known blind spot, stated rather than hidden:**
project-specific assertion helpers (`_blocked()`, `check()`, `chk()`) still produce
ASSERTS-NOTHING hits, so that column is a reading list, not a defect count.

## 4. The residual is closed: no duration is not a licence to read a prefix

`clip_cuts.content_region` computes an even spread from the clip's duration, and when ffprobe
could not supply one it fell back to `-frames:v 48` — **the first 1.9 s at 25 fps** — silently
reverting to the full-frame blindness the module exists to remove (33% cut coverage instead of
77%), reachable by a failure path and announced by nothing.

Two changes:

* **`duration_s` now asks three ways** — `format=duration`, then `stream=duration`, then
  `nb_frames ÷ avg_frame_rate`. Fragmented MP4 and stream captures routinely omit the first
  while carrying the others, so most of this branch's traffic should now never reach it.
* **When it is genuinely unknown, sample at a low fixed rate across the whole stream**
  (`fps=1`) rather than taking a prefix. `UNKNOWN_DURATION_MAX_FRAMES = 900` — 15 minutes at
  1 fps — is a **runaway guard**, far above the longest real clip (179.9 s), so it never
  decides what the sample looks like on real material.

**Proven by mutation, not by inspection.** Reverting the branch to `-frames:v probe_frames`
turns the suite red on **two** tests, including the behavioural one:

```
FAIL  "a region that only moves late is still found without a duration"
      -> unexpectedly None
FAIL  "the fallback samples across the stream not from the front"
```

The behavioural test monkeypatches `duration_s` to `None` so the degraded path actually runs,
against a clip whose only motion starts at t=6 s — past the old 1.9 s window.

The 98 clips total 12,016 s (200 min), max 179.9 s. **The compute is free** — cropdetect at

was. At six cents it is cheap enough that the reason not to run it is scope, not budget.

## A bug I introduced and caught

My own `test_verify_claims.py` perturbs `memebot/scraper/edit.py` to prove the checker reads
HEAD and not the working tree. The first version read it in **text mode** and wrote it back in
text mode — universal newlines collapsed CRLF to LF on read, and the write converted LF back
to `os.linesep`, so "restore the original" silently **rewrote every line ending in a 118 KB
file another round owns.** `git status` showed it modified with a zero-line diff.

Fixed to read and write **bytes**, with a closing assertion that the file is byte-identical
afterwards. Restored from the nested HEAD. It is the same lesson as rule 4 in the new doc —
the instrument must not perturb the subject — arrived at the hard way, half an hour after
writing the rule down.
