## Part 1 — empty-200 is now loud, and a normal drain is still quiet

`discovery.warn_empty_source()` is the shared helper — it lives beside `ApiShapeDriftError`
because it is the same class of problem the other half of. It WARNS rather than raises: one
dead category among ten must not abort the other nine.

**The critical distinction is enforced structurally, not by tuning.** It is called only where
a source yields nothing on its FIRST request for a seed / category / query / page, which
cannot be a normal end-of-well. Where pagination genuinely exists (`repost_finder`), the call
is gated on `p == 0` and page 2+ keeps its quiet `emit`.

| funnel | where | first-page condition |
|---|---|---|
| `spotify_finder` | `discover_artists`, per seed | one page per seed — empty *is* first |
| `twitch_finder` | `discover_channels`, per category | `discover_fn` paginates internally |
| `youtube_finder` | `discover_channels`, per query | one search call per query |
| `repost_finder` | the page loop, `p == 0` only | page 2+ stays quiet |

Spotify and YouTube additionally warn when **every** seed/query came back empty — the case
that means discovery is dead rather than one source being quiet.

`repost_finder` also gained the second half: rows returned but **none parsed** on page 1
(`if not medias and p == 0`). That is the shape-drift case, on a **deprecated endpoint**, and
it was equally silent before.

### Proven, both directions

```
funnel           scenario                                 expect   result
spotify_finder   all seeds empty                          LOUD     LOUD
spotify_finder   seed returns data                        quiet    quiet
twitch_finder    all categories empty                     LOUD     LOUD
twitch_finder    category returns data                    quiet    quiet
youtube_finder   all queries empty                        LOUD     LOUD
youtube_finder   query returns data                       quiet    quiet
repost_finder    page 1 empty                             LOUD     LOUD
repost_finder    page 1 OK, page 2 empty (normal drain)   quiet    quiet
                                                          mismatches: 0
```

The message names the endpoint and the parameters and says what happened in plain terms:

> `spotify_finder: SpotifyScraper.get_playlist/search returned ZERO results on its FIRST call
> (per_seed=10, seed='playlist:playlistA'). The request SUCCEEDED and the payload was empty —
> this is not an exhausted source, it is a source that gave us nothing.`

## Part 2 — the twelve are one. This corrects BL-778

BL-778 reported 12 keys "read with no default at all → silently `None`". **Measured at every
read site, eleven of them already have an effective default.** Its AST pass looked for a
second argument to `.get()` and missed two idioms that are just as real:

| how the default is actually supplied | keys |
|---|---|
| **`or FALLBACK`** inline — `cfg.get("clip_labels") or _tv.DEFAULT_LABELS` | 7 — `clip_good_categories`, `clip_labels`, `clip_noneditor_cats`, `clip_onniche_cues`, `ig_creator_identity_words`, `ig_shop_link_hosts`, `min_deep_median_views` |
| **callee-side** — the receiving function defaults on `None` | 2 — `death_markers` (`markers if markers is not None else _DEATH_MARKERS`), `ig_follower_scrape_ua` (`ua or DEFAULT_UA`) |
| **display-only**, guarded — renders `"off"` when unset | 2 — `target_split_tiktok`, `target_split_instagram` |
| **genuinely defaultless** | **1 — `cut_garbage_min_views`** |

**Latent crashes: 0. Silently-empty rules: 1.**

`cut_garbage_min_views` is the real one, and it is the shape BL-778 correctly called worse
than a dead knob:

```python
_gmin = cfg.get("cut_garbage_min_views")          # None — the key is absent from config
if (isinstance(_dmv, (int, float)) and _gmin is not None      # <- never true
        and _dmv < float(_gmin) and not _sunk):
    reasons.append(f"low-views({int(_dmv)})")
```

The low-views limb of the garbage cut **has never fired**. Not a crash — a rule that reads as
active and does nothing. Now `cfg.get("cut_garbage_min_views", DEFAULTS[...])` with a
documented default of `0`, which makes the shipped behaviour (no view-based cut) explicit
instead of accidental. Raise it in config to switch the limb on.

All twelve are in the defaults table regardless, because the contract test needs them there to
be checkable.

## Part 5 — the structural fix, and it caught me first

Two files:

- **`clippershq/config_defaults.py`** — `DEFAULTS` (the documented default for every key code
  reads without config providing one) and `KNOWN_UNUSED` (keys present in config that nothing
  reads, each with a reason). Rule B is unenforceable without this; "read but absent" is only
  actionable against a list of what is *legitimately* absent.
- **`tests/test_config_contract.py`** — a static AST pass, in the suite, red on violation.

```
RULE A  every key in config.json is read by something (or is in KNOWN_UNUSED)
RULE B  every key code reads exists in config.json, has an inline default, or is documented
```

Static, not a runtime hook, for BL-778's reason: a runtime assertion only sees keys on
executed paths, and a knob inside a rarely-taken branch is exactly how 83 invisible knobs
accumulated. The AST sees every read site whether it runs or not. The receiver allowlist
(`cfg`/`config`/`eff`/…) is carried over — without it, `media.get("height")` in
`repost_finder` counts as a knob, which is the over-count BL-778 had to correct twice.

**Proven to discriminate:**

```
with a seeded cfg.get("a_knob_nobody_documented") present  -> exit 1
   [FAIL] RULE B: ... (1 undocumented: ['a_knob_nobody_documented'])
violation removed                                          -> exit 0
```

### The test found a bug in itself before it found one in the code

Its first run failed Rule B on six keys — `off_niche_keywords`, `extra_red_flags`,
`prioritize_with_contact`, `run_default_mode`, `theme_keywords_exclude`,
`ig_niche_adjacent_keywords`. All six are **present in every campaign block**; my traversal
skipped `campaigns` entirely. That is the same mistake BL-778 made with nested sections, one
level deeper, and it would have shipped six false violations on day one. Campaign sub-keys now
count as config keys; campaign *names* do not, since they are identifiers rather than knobs.

Rule A then surfaced **11 genuinely unread keys**, matching BL-778's count: nine `meme_*`
leftovers from the repost finder's original config surface, plus `meme_viral_plays` and
`ig_niche_check`. They are allowlisted with reasons rather than deleted — a stale value that
nothing reads cannot change behaviour, and deleting a tuned threshold is harder to undo than
leaving it.

**`ig_niche_check` is worth a decision.** It is set to `null`, read by nothing in
`clippershq/`, and referenced twice in `tests/test_funnel.py` — the same "a test makes it look
covered" shape as `enrich_website`. Removing it was not in scope, so it is recorded, not acted
on.

The function-level rule (BL-778's 32 orphaned functions) is deliberately out of scope: it
needs a generous allowlist and would make this test noisy on arrival, which is how a contract
test gets deleted.

## Honest limits

- **The warnings are proven against synthetic fetchers, not a live outage.** A stubbed
  `discover_fn` returning `[]` is exactly what an empty 200 looks like to the aggregation
  layer, but no real dependency was broken to confirm the end-to-end path.
- **The guard is at the aggregation layer, not at every swallow site.** BL-772 counted 15
  `except Exception → return empty` sites across the four funnels; this makes the *outcome*
  loud rather than each individual swallow. A mid-pagination exception that yields a partial
  page still passes quietly.
- **`DEFAULTS` documents behaviour; it is not the source of truth.** Only
  `cut_garbage_min_views` actually imports from it. The other entries are checked by the test
  against the literals at their read sites, so a drift between table and code is caught — but
  the table could still describe a default that a future edit changes.
- **`KNOWN_UNUSED` is an allowlist**, and allowlists rot. Eleven keys are in it today; if that
  number grows without entries leaving, the rule has stopped doing its job.
- Rule B accepts an inline literal default as self-documenting. That keeps the table small,
  but it means the 83 invisible knobs BL-778 wants **surfaced** still pass the test — the
  contract stops new ones appearing undocumented; it does not itself move the existing 83 into
  `config.json`.
