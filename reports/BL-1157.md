## 2. So why did those three cards survive — and the real structural finding

**THE PANEL READS TWO STORES, AND ONLY ONE OF THEM WAS EVER HARDENED.**

| | written by | `pid` | `pid_created_at` | `boot_epoch` |
|---|---|---|---|---|
| `scratch/*.status.json` | `spend_ledger.write_marker` | ✔ | **✔** | **✔** |
| `scratch/runs/*.json` | `run_status.RunStatus` | ✔ | **✗** | **✗** |

BL-1150 recorded process identity in `write_marker` **only**. His three cards all came from
the other file. With nothing to weigh a pid against, every check on a `run_status` record
degraded to *"does that number exist"* — the exact question BL-1150 was built to stop anyone
asking.

That is why the sweep rewrote **30** sibling records to `died` at 20:25 and left **exactly
these three** saying `running`: those thirty had pids that genuinely no longer exist. These
three had pids that happened to be occupied.

And the merge made it worse: where both stores describe one run, the marker is primary and
the copy-across list did not include the identity fields — so a run whose `run_status` record
*did* carry identity lost it on the way to the card. Measured live during this round.

## 6. What I got wrong

* **I introduced a 10-second timeout and had to measure my way out of it.** Naming the pid's
  holder meant calling `process_name()` in `describe()`'s dead branch — 840 ms per call by
  PowerShell, uncacheable for a gone pid (no creation time, so no cache key), on 14 idle
  rows. Four consecutive `/api/now` timeouts on the live panel. Fixed by asking `pid_exists`
  (0.3 ms) first and memoising on `(pid, created_at)`; 840 ms → 0.1 ms.
* **I broke another round's export and only caught it in the suite.** My repost run added
  seven accounts and left their 11:26:58 snapshot 7 rows short. Regenerated. A paid leg has
  side effects on shared files, and I did not think about that before starting one.
* **I asserted the wider port sweep would be free. It cost 42.3 seconds.** A closed loopback
  port on Windows is dropped, not refused, so each one burned the full 1.5 s timeout. Bind
  first: 0.09 s. I wrote the wrong claim into a comment before measuring it.
* **My own change made `describe()` lie in a new way.** The "recorded under a previous boot"
  branch fired on the mere *presence* of a boot epoch — harmless while no record carried one,
  and I made every record carry one. Every dead run of this boot got a false explanation.
  Caught by `tests/test_dashboard.py`, which was right to pin it.
* **`run_status._identity` worked for half the callers.** A bare `import proc_identity` fails
  under `python -m clippershq.run`; the package form fails under the suite. Silently returned
  `None` for one of the two, which reads as "identity unavailable on this machine".
* **My first test file imported the wrong module.** `tools/run_status.py` shadows
  `clippershq/run_status.py`.
