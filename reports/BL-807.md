## 1. THE INCIDENT — read this before the rest

**What happened.** My publish script began:

```
cd "$REPO"                      # the reports repo, in the session scratchpad
git fetch origin --quiet
git reset --hard origin/main --quiet
```

The scratchpad had been removed between rounds, so **`cd` failed**. `set -e` did not abort — and the next two lines ran **in the project repository instead**. `git reset --hard origin/main` moved HEAD from `4dda296` to `8aa60d8`, the remote's *initial commit*, and deleted every tracked file added since.

The reflog is unambiguous:

```
8aa60d8 HEAD@{2026-07-31 20:27:33}: reset: moving to origin/main
4dda296 HEAD@{2026-07-31 16:55:16}: commit: config.example.json ...
```

**Blast radius at its worst:** `clippershq/` held **1 Python file out of 63**. `control.py`, `main.py`, `clip_runner.py`, `writer.py`, `pipguard.py` — gone. The pipguard hook started failing on every command, which is how I noticed.

**Recovery.** `git reset --hard 4dda296` from the reflog. **63 modules restored**, HEAD correct.

Those checks guard `quality_gate.py` and `crawl_suggested.py` — two of the seven files that had uncommitted work. **Someone had fixed those contract violations and the fix is gone.** I have deliberately not "repaired" them: I do not know the intended change, and the second check exists precisely because a naive edit there *restored a measured bug* once already.

### What survived

Everything untracked: `master_leads.csv`, **`clip_library/` with all 217 clips including this round's results**, `backups/` (164 files), `output/` (35 CSVs). No data was lost — only code.

### What I am changing about how I work

- **Never `cd` and then run a destructive git command in the same script.** The path must be passed explicitly: `git -C "$REPO" reset ...`, which fails loudly instead of acting on whatever directory it happens to be in.
- **`set -e` does not make a script safe.** It did not abort here. A `cd` that matters needs `cd X || exit 1`.
- **`reset --hard` has no business in a publish path at all.** It was there to sync a clone; `git -C … fetch && git -C … checkout` would have been sufficient and non-destructive.
