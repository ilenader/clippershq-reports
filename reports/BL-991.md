## 1. The greeting — and the correction to my own number

BL-977's 484/30.7% counted every greeting equal to the handle as a defect. This file has
always (correctly) defended that case: *"Hi onytitned" is what that person is called
everywhere they post.* Counting it as broken inflated the figure **2.75×**.

Measured properly — by the `source` `greeting_name()` already returns for exactly this
purpose:

| source | clipper rows | read as a bot |
|---|---:|---:|
| `display` | 1,433 | 160 |
| `display_first` | 107 | 0 |
| `handle` | **36** | 16 |
| profile / generic | 2 | 0 |
| **total** | 1,578 | **176 (11.2%)** |

**The brief said the fix is the fallback, not the detector. The measurement says the
fallback was only ever reached by 36 rows.** 1,433 came from `display` — so the population
that needed fixing was the display path *not falling through* to the fallback. Both halves
were needed: a reason to fall through, and a fallback worth falling to.

### The fallback: an `@` turns a defect into a convention

```
before   Hi J J E D I T Z,        Hi nicol4s_de_castro,   Hi Cykl0psFilm,
after    Hi @jjeditzfilms,        Hi @nicol4s_de_castro,  Hi @cykl0psfilm,
```

One character. `Hi nicol4s_de_castro,` promises a name and delivers a handle, so the reader
sees a merge that broke; `Hi @nicol4s_de_castro,` promises a handle and delivers one, which
is the ordinary way people address creators. The underscore and the digit are unremarkable
*in a handle*. It also keeps the greeting specific instead of dropping the row to
"Hi there".

`_is_merge_artifact()` routes three shapes to that fallback: letter-spacing (`J J E D I T Z`
— profile-page padding), an underscore, and a digit standing in for a letter.

**Result, over the live export: 0 of 2,970 greetings read as a bot, in both arms.**

The honest cost is reported beside the benefit: **196 clipper rows (12.4%) and 223 client
rows (16.0%) are now greeted by @handle.** That is grammatical and specific and it is still
not a first name — only 107 clipper rows (6.8%) have one. Counting an @handle as clean is a
claim about grammar, not about warmth.

### The rule I added and removed within ten minutes

I first included `len(s) > 20` as a fourth artifact shape, to catch page titles like
`Melhores filmes e series`. It also caught **`Innovative Language Learning USA, LLC`** —
which BL-965 had deliberately fixed to greet as a company after dumping all 16 GENERIC rows
and reading them. The suite failed within a minute.

> Length is not the signal. For a business the full name **is** the correct greeting, and
> `@innovativelanguage` would be worse. **A rule that fires on a legitimate case is not a
> stricter rule, it is a wrong one.** 36 rows were caught only by length; they keep their
> names.

## 2. `your The Odyssey edits` — fix the phrasing, not the data

Two determiners cannot stack on one noun phrase. 125 of 1,578 clipper rows carry a title
that brings its own article.

```
before   I found you through your The Time Traveler's Wife edits — …
after    I found you through your edits of The Time Traveler's Wife — …
```

Stripping the article was the wrong repair: it renames the work (*your Odyssey edits* is a
different title, and *your Last Of Us edits* is still ungrammatical). The title is correct
as recorded; the sentence bends around it. One sentence covers both shapes, so there is not
a second variant to keep in sync.

**Result: 0 messages stack a possessive on an article**, asserted over the whole file.

## 3. The A/B is now real, and stratified

BL-977 found `message_variant` was reporting `clipper/full` vs `clipper/reach` — a **data
tier**, chosen by whether the row happens to carry a fandom and a clip. Two things were
wrong with calling that an A/B test: the copy did not differ by arm at all, and the tier is
**confounded with lead quality**, so a richer lead got the richer message.

I built the two messages rather than removing the field, because the field was worth having
once something real was behind it.

| | arm A | arm B |
|---|---|---|
| length | ~120 words | **~55 words** |
| the ask | two recent edits **and** the rate you want | one closed question, answerable "yes" |
| the proof | leads with their numbers ("did 4.4M views") | leads with the offer; the work is only the reason for writing |
| terms | Rate / Turnaround / Payment inline | **withheld** — offered in the reply |

They are not a reworded pair. The hypothesis is that a short mail asking one question
out-replies a complete brief; if B wins, the terms move to the second message.

**`arm` is reported separately from `variant`.** `variant` stays the data tier, because
reports and tests already quote it. Collapsing the two is the original mistake.

**`assign_arms()` stratifies within each tier**, so each tier contributes as near half its
rows to each arm as parity allows — the confound cannot come back. It is deterministic (no
RNG), so a pilot can be rebuilt and re-audited. In the 20-row clipper read: tiers
`{FULL: 14, REACH: 6}`, arms `{A: 10, B: 10}`, balanced inside each tier.

**Client rows have no arm B, and are labelled A.** A client message carries no evidence
paragraph and no terms block, so the three axes B varies do not apply — inventing a second
client message to make the table symmetrical would be a variant with no hypothesis behind
it. My first version of `assign_arms` labelled client rows B anyway, which would have put
two identical-copy client arms into `outcome_stats` — the exact defect this round exists to
remove, one layer down.

## What I got wrong

- **The 484/30.7% in BL-977 was mine and it over-counted by 2.75×.** The real figure is 176
  (11.2%). It counted `Hi onytitned` — a handle a person actually goes by — as a defect,
  and it obscured that the *display* path, not the fallback, held the population.
- **I added a length rule that broke BL-965's deliberate company-name fix.** Removed.
- **I reintroduced BL-965's own ordering bug in the same function**: I stripped the leading
  `@` from a handle *after* the usability test, so a row already storing `@raeedits` was
  rejected as decorated and fell to "Hi there". Caught by a test I had just written.
- **My `assign_arms` labelled client rows with an arm B that does not exist.** Caught by
  reading the output.

### The one the suite caught that I would not have

I appended the 19 new tests to the end of the file. `if __name__ == "__main__":
unittest.main()` was already sitting at line 596, and **`run_all.py` executes each suite as
`python <path>`** — so `unittest.main()` ran before the new classes were even defined.

```
python -m unittest tests.test_message_template   ->  Ran 83 tests   (what I kept checking)
python tests/test_message_template.py            ->  Ran 64 tests   (what CI actually runs)
```

Nineteen tests that existed, passed when invoked directly, and **never ran in the suite**.
That is the third failure mode from `docs/ENFORCEMENT.md` in miniature — written,
implemented, committed, unrun — and the only reason it surfaced is that `run_all` prints a
check count beside each suite and **64 was smaller than the number on my screen**. The
entry point now lives at the true end of the file with a comment saying why.
