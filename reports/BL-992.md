# BL-992 — the sentence that contradicted its own numbers, and the one I wrote to replace it

**Headline:** the consistency claim is now conditional on what the figures show. Of the 781
messages that carried it, **167 keep it and 614 no longer make it** — 372 because the numbers
show a spike, 242 because there is no evidence either way. **Nothing was sent.**

**And the first version of my fix reproduced the bug it was fixing.** I caught that by reading
the output, not by running the suite, which was green for it. §2.

---

## 1. The defect, reproduced before it was touched

BL-986 found *"a real audience, not one lucky post"* printed beside numbers that disprove it.
The tail was chosen by **how many fields merged** — a fact about the export, not about the
creator — so a row reading `906 views ... a 123 median` and a row reading `4.4M views ... an
8.1M median` got the identical sentence.

Reproduced exactly on `output/ALL_BOT_READY.csv` before changing anything:

| clip ÷ median | rows | share of the 1,075 median-citing |
|---:|---:|---:|
| ≥ 2 | 809 | 75.3% |
| **≥ 3** | **751** | **69.9%** |
| ≥ 5 | 664 | 61.8% |
| ≥ 10 | 534 | 49.7% |

**The median ratio is 10.5 and the maximum is 13,117.** A clip dwarfing its account's median
is the normal case in this file, which is why the sentence was false on 70% of median-citing
rows rather than on a handful.

## 2. The fix — and the fix's own first draft, which was the same bug

`reach_shape(f)` returns `spike` / `consistent` / `unknown` from
`clip_views ÷ rank_median_views`, and `_reach_tail()` says only what that supports.
`SPIKE_RATIO = 3.0` is BL-986's bar and is deliberately generous: at 3× the clip is already
three times the account's typical result.

**My first draft returned `"that's the account, not one post"` for the unknown case.** Reading
ten rendered messages caught what that produces on a row with followers and no median:

> I found you through your Fruits Basket edits — the one from October 2022 did 385k views.
> **That's 126k followers — that's the account, not one post.**

That is the original defect in new words. A follower count is **not evidence about
post-to-post consistency**, so pointing at one and saying "not one post" asserts exactly what
cannot be supported. The 91-test suite was green on it.

So the unknown branch now returns **nothing** and the sentence stops at the figures — *"That's
126k followers."* — with the caller dropping the em dash rather than printing `— .`
`test_followers_alone_claim_NOTHING` pins it, and its docstring says why it exists.

A second correction fell out of the same reading: a **median with no clip beside it** is
`consistent`, not `unknown`. The median *is* the consistency evidence and there is no single
number for it to contradict.

disprovable in principle* (751) versus *how often did a reader see it* (372).

## 3. The sweep — one real class, one false alarm of my own making

Every assertive clause the template can emit, against whether the row's own printed numbers
can contradict it:

| clause | can the numbers disprove it? |
|---|---|
| "a real audience, not one lucky post" | **yes — FIXED** |
| "real reach, not one lucky post" | **yes — FIXED (same routing)** |
| "the one from {Month Year} did {N} views" | no — both printed verbatim |
| "I found you through your edits on {platform}" | no — platform derives from the profile link |
| "{N} followers" | no — printed verbatim |
| "reply with two recent edits and the rate you want" | no — it is a request |
| "your live sets / VODs / uploads" | **not checkable** — the file carries no client reach at all |

Numeric traps swept across all 2,970 rows:

| trap | rows |
|---|---:|
| consistency claim beside a spike | 751 → **0** |
| clip cited below the quotable floor | **0** |
| median cited below the quotable floor | **0** |
| clip dated in the future | **0** |
| median cited with no clip to compare | 35 (now `consistent`, correctly) |

The two floor checks returning 0 is `QUOTABLE_MIN_VIEWS` doing its job silently.

**A false alarm I raised and withdrew:** 437 rows print a median *larger* than the follower
count. That is ordinary on short-form — views come from the For You page, not from followers —
and the copy asserts no relationship between the two numbers. It is recorded in the sweep as a
non-finding so the next round does not re-raise it. My trap was wrong, not the copy.

## 4. Forty messages read verbatim

20 clipper (10 per arm) and 20 client, addresses redacted. Reading them is what found §2.


Every sentence is now true of the numbers standing next to it.

**Clipper, arm B** carries **no numbers at all** — ~62 words, one question, terms withheld —
so the defect never reached it. **Client** copy cites no reach either (the file holds none for
clients), so no self-contradiction is possible there; BL-991's `@handle` fallback and the
agency variant (*"I'm writing about @2bratty"*) both read correctly.

The sha256 either side is the observation; *"I passed `master_csv=` so it must have used it"*

operator needs it to sanity-check delivery), and a six-character sha256 of the whole address
so the same person is re-identifiable across reports without the address ever appearing.
