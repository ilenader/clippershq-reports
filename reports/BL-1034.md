## Item 8 — verified read-only, and correctly NOT fixed

The duplication is real:

```
clippershq/clip_pipeline.py:2286   class LedgerUnreadable(RuntimeError):
clippershq/spend_ledger.py:305     class LedgerUnreadable(RuntimeError):
clip_pipeline.py imports spend_ledger   -> spend_ledger is canonical
```

The brief's instruction is *"fix if free; report if not."* `spend_ledger.py` **is** free, but
the change belongs in `clip_pipeline.py` — the alias has to replace the duplicate definition
— and `clip_pipeline.py` is **BL-1028's**. So: reported.

The hazard the brief names is correct and worth restating for whoever takes it: **two
identically-named exception classes will eventually be caught separately by an `except` that
knows only one of them**, and on this specific pair the failure mode is a ledger read that
raises the *other* `LedgerUnreadable`, escapes a handler written for the canonical one, and
either crashes a run mid-spend or — if some outer handler swallows it — returns a permissive
number. That is the same shape as the "unreadable ledger returns a permissive value" bug the
brief's budget section says has already fired twice.
