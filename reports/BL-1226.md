**And a per-second RMS envelope of the delivered file said which of two stories was true.**
`adelay` is supposed to put 9.77 s of *silence* in front of the bed, so "8.7 s of audio in

neither of the innocent readings:

t=  3.0s  -16.2 dBFS   #####################

**The surviving 8.731 s is music at full level starting at t=0.** The leading silence never
reached the file at all: the muxer rebased the delayed stream back to pts 0 (`start_pts=0`,
`start_time=0.000000`, no empty edit list). So one mechanism caused **two** defects that
have been shipping together:

* the drop landed at **t=0**, not on his hand-marked beat; and
* the output ran short by **exactly the delay**.

That is why `audio == video − adelay` held on 14 of 14 clips. BL-1224 measured that
relationship correctly. BL-1225 inverted the inference from it — it read "the tail is short
by the delay" and concluded the bound was doing the cutting.

## 3. THE FIX — the placement is a PHASE, not a pad of silence

`clippershq/clip_pipeline.py::hook_chain` no longer emits `adelay`. The bed is an infinite
loop of a window of length `L`, so a delay of `D` and a rotation of

```
X = (L − D mod L) mod L
```

put the window's first sample at the *same* clip second: at `t = D` the phase is
`(X + D) mod L = 0`. Alignment is preserved exactly; what changes is only what plays
*before* `D` — the loop's own tail instead of silence. That is what he asked for: *"it
should stay across the whole thing, beginning to end."* The window's natural run-up still
plays from `D` into the drop, untouched, so **BL-1163's `lead`/`trim`/`bed`/`delay`
arithmetic is unchanged** — only how the third argument is spent.

A second `asetpts=PTS-STARTPTS` rebases the rotated stream, which puts the bed and
`edit.py`'s bound back on the same clock. The whole class of "which clock is the bound on"
bug is gone rather than patched.

**One semantic worth stating, because it is easy to misread and I misread it myself while
checking this.** `hook_chain`'s third argument is `chain_args()`'s `delay`, which is **not**
`place_at_s`. On clip 1: `place_at_s = 4.0` is where the *drop* sounds; `delay = 0.77` is
where the *window's first sample* goes, and the `lead = 3.23` of run-up between them is what
BL-1163's `action = delay + lead` describes. `adelay=770` put the window's first sample at
0.77 s and the rotation puts it at 0.77 s — **the same argument, the same instant, so the
drop is preserved exactly.** Verified per clip: every applied chain's rotation equals
`(L − delay mod L) mod L`, and three clips carry a rotation of 0.0 because their marked
run-up was longer than the action second, so `delay = 0` and the lead-in is cut — BL-1163's
other branch, still working.

**Zero `adelay` remains in any applied chain in the delivered batch** (checked across all 16
configs).

`edit.py`'s delayed-clock compensation is **kept**, now as an explicit legacy path: a
`hook_chain` string persisted by an older round can still carry an `adelay`, and on such a
string the bound must still shift. On every chain generated now the regex finds nothing and
it adds 0.0. The comment there that claimed "this is why his music stopped" is corrected in
place, because it was wrong and the next round would have believed it.

### AND THE SHIPPED READBACK GUARD WAS DEAD — fixed

`our_line` read `"readback: OCR found no text inside the label band"` on **all 16 clips of
this batch and all 16 of the previous one**. The cause:

```python
res = clip_ocr.reader()(dst)          # paste_batch.py:1056 — the ONLY call site that
                                      # did not unwrap
```

`reader()` returns the RapidOCR engine; calling it returns `(result, elapse)`. Every other
call site in the repo spells it `res, _elapse = reader()(png)` (`clip_ocr.py:370`,
`clip_label_text.py:399`). This one handed the 2-tuple to `blocks_in_band`, which could
unpack neither element as a block and returned `[]` **every time**.

BL-1218 built this readback precisely so the "his line == our line" check had a second,
independent origin instead of comparing `src_line.text` to itself — **and the replacement
could not fail either, for a different reason.** Fixed in `clippershq/paste_batch.py`.
