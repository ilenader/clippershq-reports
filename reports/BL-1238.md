## 3. The backup pile — pruned and given a lifetime

**Measured, not quoted.** The brief's dry run said 263 files / 6.43 GB → delete 211 / 5.14 GB,
keep 52 / 1.29 GB. On disk at 2026-08-12 23:45 it was **263 candidates / 5.97 GB**, and my rule
split them **43 keep / 220 delete**. Same file count, different split — so I report mine and
name the difference rather than adopting a number I did not take.

**The rule, in `tools/backup_prune.py`.** A backup is kept when either holds:

1. **it is the newest its funnel has** — forever, no expiry. Whatever a funnel last did to the
   master stays undoable however long ago it ran; a funnel that has not run in months is
   exactly the one whose backup nobody can reconstruct.
2. **it is the last of its funnel on its day, and that day is inside 14 days.**

"Funnel" is the label in the filename, and an unlabelled backup is its own funnel — so the
plain `writer.py` copies are never grouped with a labelled run's.

**Ran it:**

```
before   263 candidates   5.97 GB
KEEP      43 files        988.40 MB
DELETE   220 files          5.00 GB      repost 184, twitch 10, bl1221_tiktok 7,
                                         spotify 5, googleplay 5, bl1176_meme 5,
                                         youtube 3, (unlabelled) 1
after     43 candidates   988.40 MB      second run: 0 to delete — idempotent
disk     707G used / 225G free  ->  702G used / 230G free
```

**28 funnels, and every one still has a surviving backup** — checked explicitly, because a rule
that silently orphans a funnel's only undo is worse than no rule.

**It refuses** to touch anything whose name it cannot parse (`master_leads.csv.bl806.bak` and
`master_leads.csv.lock` were both skipped and reported, not deleted on the assumption they were
junk), anything tracked by git, and anything at all without `--apply`.

**Automatic now.** Scheduled task `ClippersHQ-BackupPrune`, daily 04:30, pointing at
`tools/backup_prune_task.ps1` — a wrapper because `schtasks /TR` refuses a command string over
261 characters, which the inline invocation exceeded. Same shape as `ClippersHQ-Backup`
(BL-1035) and the same rule: **every run appends to `logs/backup_prune.log` and its last line
says PRUNED / NOTHING TO DO / FAILED in those words**, because a scheduled job that quietly
does nothing is worse than no job — the pile grows and nobody looks, which is the state this
