# BL-1343 — The Instagram wall: the safe volume cannot be measured, and the wall is not a cooldown

**The safe run size is still unmeasured, and this round can say why with a number instead of an
excuse: the wall was still up after 6.71 hours of complete idleness.** Not 6.71 hours of polite
polling — 6.71 hours in which nothing in this repo touched instagram.com at all. Every earlier
"reset floor" was measured while probes kept arriving every 13 minutes, so it recorded how long we
kept asking. This is the first measurement of how long the address was left alone, and it still
said no.

A wall that survives being left alone all night is not a cooldown to wait out. That makes §3 —
how to get a different address — the whole answer rather than one option among four.

**And the cheapest way to a different address is not what it looks like.** After measuring that
Instagram compresses its pages **5.39×**, a pay-as-you-go residential proxy costs **$0.37–$0.42
per 1,000 pages** against the paid grid's **$0.64**. My own first pass concluded the opposite, on
an unmeasured byte count. One request settled it.

Vendor spend this round: **$0.00** of a $1.00 cap. Every request made was free.
All numbers from `.venv\Scripts\python.exe` (3.11.9) unless stated.

## 3. Getting a fresh IP — costed per 1,000 pages, buying nothing

### First, the measurement that decides the whole section

Proxies bill **bandwidth**; the vendor bills **requests**. So everything here turns on page size,
and my first pass used the 606,428 bytes the probe recorded — **measured with no
`Accept-Encoding`, which urllib does not send by default.** Paired curl requests to the same URL:

```
Accept-Encoding: identity   ->  606,097 bytes
Accept-Encoding: gzip, br   ->  112,538 bytes      5.39x smaller
```

A proxy bills the wire and the wire carries the compressed body. **The billable page is ~112 KB,
1,000 pages is 0.105 GB, and every per-GB figure is 5.39× cheaper than my first pass said — which
inverts the conclusion.** I had written "no proxy tier beats the vendor." That was wrong.

(112,538 bytes is still a *wall* page; no non-walled profile page has been byte-counted here.
Break-even page size is therefore printed per tier in `scratch\bl1343_cooling.json`.)

### ⚠️ "All datacentre IPs are banned" is vendor marketing

Datacentre is ~88× cheaper than the grid, so this claim is worth $0.63 per 1,000 pages and
deserves scrutiny. It does not survive it:

- **The claim** — *"blocked on the first request, regardless of how slowly you scrape"* — traces
  to a Medium post whose author sells a scraping product, carrying **no method, no sample size, no
  measured rates.** HikerAPI, Scrapfly, DataImpulse and others echo it near-verbatim, which
  manufactures the appearance of corroboration from one unsourced assertion. Every Scrapling
  sponsor is a proxy company: the library is free, and not being blocked is the product.
- **Instaloader's own docs** — open source, nothing to sell — say promiscuous cloud/VPN/proxy
  addresses *"might be subject to significantly stricter limits for **anonymous** access"*, while
  *"logged-in accesses do not seem to be affected."* Our capture is anonymous, so that is exactly
  our case, and it describes **stricter limits, not a block.**
- **The one report that ran datacentre and residential side by side** labels the datacentre address
  *"blocked more frequently, but works sometimes"* — failing with 429 and 302-to-login, **never a
  403 and never a connection refusal.**

**Verdict: NOT PUBLICLY ESTABLISHED that Instagram refuses datacentre ranges outright, and the
independent evidence says it does not.** Nobody has published the *size* of the penalty, which is
the only number a decision needs. At 88× it would still win if nine of every ten pages walled.
**$2.99 settles it** — outside this round's $1.00 cap, so recommended rather than run.

### Does rotating two addresses double the volume or split it?

**NOT ESTABLISHED, and it is the crux.** What is known here: the wall is an *address*-level
decision, not a network-level one — a TikTok control stays OK on this same IP through every tick
while Instagram walls. What is not known: whether the budget is scoped **per IP, per /24, or per
ASN.** If per subnet or per ASN, two addresses from the same ISP share one budget and rotating
splits it rather than doubling it.

The numbers in circulation are not measurements. *"~200 requests per hour per IP"* and *"4,800
profiles per day per IP"* are **Meta's own published *authenticated Graph API* formulas with the
denominator stripped off** — the real ones read `200 × Number of Users` and
`4800 × Number of Impressions`, keyed to App ID and account, and **IP address is not a rate-limit
key anywhere in that documentation.** They are also mutually incompatible, which is itself the
proof nobody measured them.

**A phone hotspot is a different ASN, so one page over it settles address-vs-network for $0.00.**
That is the single most informative free request available.

### ⚠️ And it may not be a per-IP budget at all

Every option above assumes a fresh address helps. Independent reports say it may not: *"Even with
a fresh IP and significant cooldown periods, the error triggers immediately upon the first
request"*, persisting 72+ hours across a network change; failures *"regardless of what IP I use"*;
home IP, datacentre VPS and residential proxies behaving **identically**, with the error body
`429 {"message": "useragent mismatch"}`; and 429s under HTTP/1.1 that *"succeed reliably with
HTTP/2."* A failure that turns on the protocol version is not an address-budget failure.

Against that, **our own evidence**: logged-out capture demonstrably worked on this line — 788 real
grids between 17:53 and 18:39 on 2026-08-16, then 0 of 524 in the next 27 minutes. Something
changed state part-way through one evening on one address. That rules out "logged-out viewing is
simply gated by product design", which would never have returned 788 grids.

**HTTP/2 is free, untested, and should come before any purchase.** It is untested here because
`h2` is not installed in the venv and this machine's curl is built **without HTTP/2** (its
`Features` line lists none). One `pip install h2` and an `httpx` request with `http2=True` settles
it.

## 4. The paid fallback's place, and the view floor

### ⚠️ The fallback is wired inside a function nothing calls

`clippershq\paid_grid.py` ships and works. It is called from exactly one place —
`clippershq\page_capture.py:245`, guarded by `_paid_grid_needed()` → `paid_grid.is_walled()`,
which triggers on the wall and **never** on an empty page (so a deleted account does not buy a
grid). That design is right.

**But `capture_one` has zero production callers.** `clippershq\meme_finder.py` contains no
reference to `page_capture` at all; the only callers are tests and scratch runners that define
their own `capture_one`. So today the paid fallback cannot fire in a shipped run: the funnel
would judge blanks. **That is the gap between "the paid grid works" and "the paid grid is the
fallback."**

The one live proof is n=1 and cost **2 billed calls, not 1**, because no `user_pk` was passed —
and master carries a pk on 221 of 62,692 rows, so one call is the exception, not the rule.

### The honest hybrid: X free per **address**, then $Y

⚠️ **"Per run" is the wrong unit, and that is this round's correction.** Every earlier statement
of this shape said "X pages free per run." Runs do not recur: a walled address has never been
observed to recover across 669 requests and 6.71 hours of rest. **F is free pages *per address*,
once.** An address is a consumable, and the unit of supply is addresses per day.

Winners cost a flat $1.274 per 1,000 wanted under judge-first (2 calls each). Pictures cost
$0.000637 for every page **judged** — `1,000 / want rate` of them.

| free pages per address | paid pictures @9% | **$/1,000 wanted @9%** | @28% |
|---:|---:|---:|---:|
| **0 — MEASURED TODAY** | 11,111 | **$8.35** | **$3.55** |
| 135 (largest known-clean run) | 10,976 | $8.27 | $3.46 |
| 788 (BL-1329's observed yield) | 10,323 | $7.85 | $3.05 |
| 1,200 | 9,911 | $7.59 | $2.79 |

**So the honest Instagram number on this machine right now is $8.35 per 1,000 wanted at a 9% want
rate — not $1.27.** The $1.27 is real, and it prices only the pages the free capture covers.

**To clear $2.00 at 9%:** $0.726 remains after winners, which buys 1,139 pictures of the 11,111
needed. The other **9,972 must be free** — that is **74 unwalled addresses per 1,000 wanted
pages** at F=135, 13 at F=788, 9 at F=1,200. At 28%: **19 addresses** at F=135, 4 at F=788.

### `play_count` as a view floor — scored at every threshold, and it does not ship

BL-1339 already bought this: 200 of his independently marked handles, 411 receipt-counted calls,
**$0.2466**. Re-buying it would have spent a quarter of this round's budget to reproduce a table
already on disk, so this round **re-scored it from that artefact for $0.00** — and evaluated
**every threshold at which the answer can change** (389 of them), not sixteen chosen values.

His 200 marks: **37 WANT, 163 REJECT.**

Two reads, and the difference between them *is* the result. `play_count` is **absent as a key** on
`product_type=igtv` posts, where the count is called `view_count` — so reading only `play_count`
scores an igtv page as unmeasurable and never kills it.

| floor | **WANTED killed** | rejects killed | % of measured rejects |
|---:|---:|---:|---:|
| *play-only read* | | | |
| 0 → 1,870 | **0** | 0 → 25 | 0% → 15.92% |
| 1,871 | **1** | 25 | 15.92% |
| 5,000 | 6 | 40 | 25.5% |
| **play-or-view read (the correct one)** | | | |
| 0 → 385 | **0** | 0 → 4 | 0% → **2.53%** |
| **443 — highest safe floor** | **0** | **4** | **2.53%** |
| **444** | **1** | 4 | 2.53% |
| 1,000 | 1 | 10 | 6.33% |
| 1,870 | 1 | 25 | 15.82% |

**Verdict: the CUT does not ship. The SCORE does.** At zero wanted loss with the fields read
correctly the floor is worth **4 of 158 rejects — 2.53% — with a margin of ONE VIEW.** At 444 it
takes a page he wants. That is not a filter; it is a coin balanced on its edge, and the downside is
a page he wants. `play_count` belongs as an **ordering** signal beside the SigLIP probe, where
being wrong costs judging order and never a page.

⚠️ **This contradicts BL-1339's own sub-agent, which recommended a floor of 1,000.** That is safe
only under the read that cannot see igtv pages; under its own play-or-view finding it kills a
wanted page. Its artefact contains both tables and a caveat saying so — the recommendation did not
follow the caveat. BL-1339's *round* refused the floor, correctly, and that is what reached code.

⚠️ **And BL-1339's report prints a threshold row — `25,000 / 22 wanted killed / 94 rejects` — that
does not exist in the artefact.** The highest floor ever tested is 5,000. The other rows reproduce
exactly.

**No follower floor, at any value, and none was tested as a filter.** Reported for description
only: his wanted pages run from **957 followers** to 10.8 M, median 33,790. A follower gate starts
by throwing one away.
