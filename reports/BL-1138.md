# BL-1138 — a shareable render repo, and the four things only a clean extract could find

**One sentence:** the meme-render pipeline is now a self-contained 53-file repository at
`Desktop/meme-relabel`, with one local commit and **no remote**, that a stranger can clone
and run — verified by extracting its own HEAD to a fresh directory and rendering a clip
there — and the extract found **four defects the working tree could not have shown**,
including a `NameError` that every import test passed straight over.

**Spend: $0.00 of a $0.00 cap.** No paid call was made, none was attempted. Nothing was
pushed anywhere, no token was requested, offered or used.

**The build is a script, not a copy-paste.** `scratch/bl1138_build.py` enumerates every
file by name — there is no `copytree` anywhere in it — slices `clip_pipeline.py` by AST so
each extracted function is byte-identical to its original, applies three named layout
patches, and then **audits what it wrote rather than what it intended**. Re-runnable, and it
lists what it took.

### What was left behind, and it is about half of what the imports suggested

A static import closure from the render roots reached **80 of 102 `clippershq` modules** —
`clip_pipeline` names `main` and `ig_client`, and those two drag in the entire lead half.
Almost every one of those edges turned out to be a **deferred import inside a function**, so
the closure was an over-count. The runtime need is **16 modules**.

Absent by construction: the whole lead-generation half, `master_leads.csv` and its 200+
backups, every scraped clip and the clip library, every credential, the outreach templates,
the claims machinery, every report, the spend ledger and its budget guards, the paid
Instagram retrieval leg, and the operator's own hand-marked song store.

Two cuts worth naming because the code already handled them:

- **`outcome_loop` / `outcomes` did not need stubbing.** `song_library` imports
  `outcome_loop` inside a `try/except ImportError` that returns `{}`, so a hook with no
  outcome evidence carries weight 1.0 and nothing breaks.
- **The three ledger-backed rotation helpers ARE stubbed, and loudly.**
  `ROTATION_AVAILABLE = False` and the docstrings say "nobody looked", not "we looked and
  found nothing". An empty bias map and an absent one are different answers, and collapsing
  them is how an unrotated pick reads as a rotated one.

**The paid retrieval leg was replaced, not ported.** `pipeline/fetch.py` takes a local file,
a direct media URL, or hands anything else to `yt-dlp` if it is installed. It sends no
cookie, no session and no token, and there is nowhere to put one.

## 2. The clean extract — and the four things it found

`git status` compares the worktree to HEAD. It reports what is **different**. It is
structurally silent about whether a tree **stands alone**, which is why three shipping
modules were untracked-and-working for eight rounds in this project. So:
`git archive HEAD` → a realpath'd directory outside both repos → `git init` + commit
(a clone IS a repository) → run everything there.

```
53 files in the extract (the source worktree has 53 outside .git)   <- nothing untracked was needed

ARM 1  no OCR engine on the path (a fresh clone BEFORE pip install)   17 suites, 0 failed
ARM 2  OCR engine reachable      (a fresh clone AFTER  pip install)   17 suites, 0 failed
ARM 3  python relabel.py <clip> --no-song, in the extract             rendered
```

Arm 3, in full, on a clip the extract synthesised for itself:

```
3. BAND     x=0 y=120 w=720 h=59  (source pixels)
4. CARD     x=0 y=0 w=720 h=300  (23% of frame height)
5. READ     5/5 frames agreed character for character, weakest block 0.945
            'Me when bro finally texts back'
7. RENDER   rc=0 in 2s
8. VERIFY   ffprobe finds a video stream with a duration
   720x1280, 10.93s  (source was 720x1280, 12.00s)
```

Both arms matter. Only running *with* the engine answers "does it work"; only running
*without* it answers "does it skip cleanly instead of crashing". A stranger is the second
case before `pip install` and the first case after, and both have to be true.

### The four defects

**1. `shutil` was missing from the sliced module — and every import test passed.**
`media_duration` calls `shutil.which("ffprobe")` with no local import; it relied on a
module-level import that did not come across. The module imported fine, 17 suites were
green, and the failure waited for the first real clip. **This is the whole argument for an
end-to-end test**: an import test proves a module *loads* and says nothing about whether it
*runs*.

**2. A renderer suite asserted the parent project's directory layout.**
`test_edit_bed` checks that a repo-root-relative asset path resolves, and wrote that path as
`memebot/scraper/config.yaml` — a directory that does not exist here. Green in the source
tree, red in the copy, and **`git status` could never have said so: the file is identical in
both.** The property under test is one this copy needs too, so only the fixture path was
re-pointed.

**3. The renderer refused `--only local:clip`.** Its platform allowlist is
`tiktok / youtube / instagram`, because upstream a clip always arrived from one of those.
Here a clip arrives from a file, and making someone type `instagram:` to render a video off
their own disk would be lying about where it came from.

**4. The renderer's duration floor did not come across.** `MIN_DURATION_S` and the three
constants it is derived from were missing. **The name-checker could not have caught this** —
it only sees names the sliced code *reads*, and `relabel.py` reads `CP.MIN_DURATION_S` from
outside the slice.

### And two bugs in my own instrument, which is the more useful finding

The name-checker that was supposed to catch #1 reported it clean, for two independent
reasons that both had to be fixed:

- it collected imports made **inside functions** into the module-level scope, so one
  function's `import shutil` made the name look module-level to every other function;
- it **unioned** every function's locals into one set, so a name bound anywhere looked bound
  everywhere.

Between them, `shutil` was covered twice over by bindings that were not in scope where it
was read. Fixed to per-function scoping against module-level-only bindings, it reports
`shutil` correctly. **Three instrument errors this round; every one was found by running the
thing rather than by analysing it.**

## 3. The scanner: both profiles, and a join whose zero is worth something

```
LIVE LEAD LIST: master_leads.csv, 133,476 rows

--profile public    52 files scanned, 0 FAILED, 0 matched a live lead
--profile private   52 files scanned, 0 FAILED, 0 matched a live lead

NOT SCANNED (binary, the scanner reads UTF-8 text): 1
     renderer/fonts/Montserrat-Bold.ttf
```

104 scans, **zero findings**. The one unscannable file is named rather than silently
excluded — "0 findings" over a set that quietly dropped something is the shape of every
scanner failure this project has paid for.

**The first version of that zero was worthless, and this is the finding.** My sweep counted
a file clean when the words "live lead" did not appear in the scanner's output — but the
scanner prints that line **only when the join matches something**. "No line" and "the check
never ran" are the same output. I read the absence of a failure as evidence of a pass: an
absent gate reading as an open one, arriving in the instrument instead of the code.

So `scratch/bl1138_join_control.py` plants a **real address from the live list** and
confirms a refusal:

```
CONTROL ADDRESS (fingerprint only): ar**@gmail.com (b8ac67)

  public   planted REAL address   exit 1 (want 1)  OK    live LEAD addresses (join, 4,772 indexed) : 1
  private  planted REAL address   exit 1 (want 1)  OK    live LEAD addresses (join, 4,772 indexed) : 1
  public   invented address       exit 1 (want 1)  OK
  private  invented address       exit 0 (want 0)  OK

  planted files deleted
```

The join **fires on a real address under both profiles** and stays quiet on an invented one
under `private` — so it discriminates rather than refusing everything, and **a zero from it
is now evidence**. 4,772 addresses were indexed. No address was printed at any point; the
control reports a fingerprint (two characters, the true domain, six hex) and the planted
files were deleted in a `finally`.

`tests/test_shareable.py` ships inside the new repo as the cheap always-on version: it walks
the tree for addresses, credential-shaped literals, unlicensed fonts and media files, and
**reports findings by location, never by value** — a test failure that prints the secret has
published it into every CI log that ran it.

## 4. The licence question — stated, not decided

`LICENSING.md` sets out the question and names what constrains it. It does **not** choose.

**There is no licence on this code, and that is a decision.** Published with none, it is
"all rights reserved" — readable, not usable. The candidates (MIT/BSD, Apache-2.0, AGPL-3.0,
no-licence-public, stay-private) are laid out with what each actually buys.

**Nothing vendored forces a copyleft choice.** Only one third-party file is committed.

> **OUTSTANDING — `renderer/fonts/Montserrat-Bold.ttf` ships without its licence text.**
> Read from the font's own name table (not a filename, not a README): *"This Font Software is
> licensed under the SIL Open Font License, Version 1.1"*, family `Montserrat`. The OFL
> **permits redistribution**, so committing it is fine — but **clause 2 requires the licence
> text to travel with the font, and it is not there.** The remedy is one file: copy `OFL.txt`
> from <https://github.com/JulietaUla/Montserrat> to `renderer/fonts/OFL.txt`. **Do not
> hand-type or paraphrase it.** Left open deliberately: the correct file has to come from the
> canonical source, and committing a licence text taken off the network unverified is its own
> small risk.

**The font that is deliberately absent is the sharper half of this.** `.gitignore` excludes
every `.ttf` with one explicit exception, because a file named `Inter-Bold.ttf` sat in that
folder for eight rounds while the font selection routed Greek, Hebrew and Arabic to it — and
it was **family `Arial`, version 7.05, vendor Monotype, licence "Microsoft supplied font"**,
put there by an auto-copy that grabbed the first system bold face. Arial Bold is **not
redistributable**; it could never have been committed even in principle, and nothing said so.
Nothing raised either: FreeType substitutes `.notdef`, ffmpeg exits 0, the cost is paid.
`tests/test_shareable.py` now fails if any other `.ttf` appears.

`LICENSING.md` also states what **no** licence here can grant: the clips (whoever made them),
the music (none ships, deliberately), and the outputs (their status follows the source's).

## 5. How to push it — two commands, and PRIVATE is the safe default

Nothing was pushed. No remote is configured. `git -C <repo> remote -v` returns nothing.

```
gh repo create meme-relabel --private --source "C:\Users\Game Centar\OneDrive\Desktop\meme-relabel" --remote origin
git -C "C:\Users\Game Centar\OneDrive\Desktop\meme-relabel" push -u origin main
```

**Make it private.** A private repository becomes public in one click once the checklist in
`LICENSING.md` is settled. **A public one cannot be un-published** — it is cloned, cached and
indexed within minutes, and deleting it afterwards does not retract the copies. This project
has already sent 20 live addresses belonging to 19 people to a public repository once.

Before flipping it public: pick a licence, add `renderer/fonts/OFL.txt`, add a copyright
line, run `python tests/run_all.py`, and decide whether the provenance comments are
acceptable — `pipeline/` and `renderer/` carry ticket numbers, measurements and incident
notes from the private project. Nothing in them is a secret (that was checked, twice, under
both profiles), but they do describe how an operation works.

The commit message carries a `Co-Authored-By` trailer. Amend it before pushing if you would
rather it did not.
