## 1. RANK 2 — the live one. Fixed by the operator, from the side I was allowed to touch

The disagreement, restated exactly:

```python
clip_speech.classify       talking = speech_frac >  SPEECH_PRESENT_MIN   # 0.20
clip_library.build_record  MUSIC if speech_frac  <  SPEECH_MUSIC_MAX     # 0.20
```

There is now **one predicate**, `clip_speech.is_talking()`, and `classify` calls it:

```python
def is_talking(speech_frac):
    return speech_frac is not None and speech_frac >= SPEECH_PRESENT_MIN
```

**Why `>=` and not `>`** — and this is a decision, not a convenience. `clip_library.py` is held by BL-937, so the boundary had to move to the side I own. That constraint and the correct answer point the same way: calling a 0.20 clip MUSIC routes it to `mute-and-replace`, which **destroys real dialogue and is unrecoverable**; calling it DIALOGUE keeps a music bed under a clip that may not have speech — a volume complaint, and reversible. BL-852 already settled that asymmetry for the threshold itself ("when one side of the trade destroys content and the other side is a volume change, the threshold belongs at the low end"); it settles the boundary too. The direction is now pinned by its own test so a later `>` is a deliberate act.

## 2. RANK 1 — the dead branch is dead. The three-numbers claim is REFUTED

**The part that was right.** `secret_values()` pre-filtered on `NEEDLE_MIN_LEN` and then tested `SECRET_MIN_LEN`, both 16, so the rule could only ever see values that had already cleared the pre-filter — `max(16, SECRET_MIN_LEN)`. out.add(v)

Removing it is **behaviour-preserving, which is what proves it was dead**: against the real config, needles are 8 before and 8 after, shortest 30, longest 73 — identical. Tests assert **identity, not equality** (`assertIs`), ban a second literal, and — the test the old structure would have failed — assert that **lowering the constant actually changes the answer**.

### The correction: 12 / 16 / 24 are not one decision

BL-932 reported credential length as one question with three answers and proposed collapsing all three. **I measured that before doing it, and it is wrong.** Over all **479 published reports**, the publish gate's `RUN_MIN`:

| `RUN_MIN` | reports flagged | what the extra hits are |
|---|---|---|
| 24 (current) | **249 of 479** | — |
| 20 | 333 of 479 | `scripts/migrations/BL-538-repair-…` |
| 16 | **438 of 479** | `checkpoint/BL-538`, `/api/v1/instagram/v1/fetch_user_in…` |

Collapsing to 16 would flag **189 more reports** — branch names and API paths, not keys — and re-break publishing, which is exactly the MEMEBOT-051 failure MEMEBOT-056 had just repaired. The three numbers test three **populations** with opposite false-positive costs:

- **16** — a config value in a credential block. False positive ⇒ a real log line is corrupted by over-redaction.
- **24** — an unbroken run in free report **prose**. False positive ⇒ the report cannot be published at all.
- **12** — a quoted value after a credential-**named** key in a diff. The name does the work; length is a weak secondary filter and can afford to be loose.

So this is **pair #8's shape, not pair #3's**: the disagreement is correct and what was missing was any *reference* tying them together. `secrets_guard` now cites `RUN_MIN` and `wip_commit.CRED_SHAPE` by name with the measurement, and a test fails if those cross-references are removed. **One constant per decision — but deciding two things are one decision because they share a units label is how you break a working gate.**

**Pair #2 was fixed by BL-931 between rounds, not by me.** The `len(v.strip()) >= 12` candidate floor I reported is gone; line 47 is now a placeholder and the real rule is `_looks_like_credential`. I verified it and credited it rather than claiming it.
