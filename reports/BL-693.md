# BL-693 — The numpy 2.0 ABI break is now a machine check, not a memo

**2026-07-29.** Scope changed mid-task by the owner: the isolated heavy-ML virtualenv was
**cancelled**, and the pre-install guard — the part that closes a live, twice-hit risk — was
built instead. Everything below is new files only. **No existing file was modified**, no
config value changed, no credential read or printed, `outreach-dashboard` untouched.

---

## Verdict

`pip install` in this repo now dry-runs first and **refuses** if the resolution would move
`numpy`, `torch`, `PIL`, `onnxruntime`, `transformers`, `numba`, `cv2` or `scipy` backwards.
Proven live against the real package that triggered this: **`laion-clap` was refused,
`numpy 2.3.2 -> 1.26.4 DOWNGRADE`, exit 2, environment untouched.**

The near-miss has now happened **twice in eight days**, and the second one was in flight in
this repo while the guard was being written.

---

## 1. What was cancelled, and why that was right

The brief originally asked for a separate virtualenv for heavy ML models, invoked across a
subprocess boundary, with `silero-vad` shipped into it. The owner cancelled it mid-task. The
reasoning, recorded here because it is the more useful half of this report:

- **CLAP cannot be installed at all without breaking the host.** `laion_clap` requires
  `numpy<2.0.0`; `msclap` adds that plus a `transformers 5.12.1 -> 4.57.6` downgrade.
- **Its value collapsed independently.** Text beats audio decisively for mood on this
  population — captions are 100% coverage, free, and median 908 characters — and the
  energy-step detector already fills the arousal axis at ~78 ms per clip with **zero new
  dependencies**.
- Net: **a gigabyte of ABI risk for the weakest of three signals.**

That is a correct call, and it is worth stating plainly that the *isolation machinery was
never the point* — the point was not breaking the host. A guard that makes the breakage
impossible achieves that without a second environment to maintain.

**Independently confirmed here:** the guard's dry-run of `laion-clap` resolved to
`numpy 1.26.4`, matching the owner's account exactly.

## 2. The hazard, stated precisely

| | Package | What it pulls | Effect on numpy |
|---|---|---|---|
| **BL-681** | `inaSpeechSegmenter` | TensorFlow 2.13.1, pinning `numpy<=1.24.3` | 2.3.2 → 1.24.3 |
| **BL-682** | `laion-clap` / `msclap` | `numpy<2.0.0`; msclap also walks `transformers` back | 2.3.2 → 1.26.4 |

Both cross the **NumPy 2.0 ABI boundary**. Every compiled package in this environment was
built against numpy 2.x:

```
numpy 2.3.2   torch 2.11.0+cpu   Pillow 12.2.0   onnxruntime 1.22.1
numba 0.63.1  opencv 4.10.0      scipy 1.17.1    transformers 5.12.1
(Python 3.11, pip 26.1.2, packaging 25.0, CPU-only host)
```

A numpy 1.x downgrade does **not** raise a clean incompatibility error. It typically
**segfaults at import**, or returns silently wrong array data. That takes out **OCR,
thumbnail vision and the repost funnel at once**, and the traceback — where there is one —
points at the victim, never at the install that caused it.

The cause is structural: heavy audio/vision packages advertise GPU-flavoured extras, so pip
backtracks years of pins to satisfy them on a CPU host. **It recurs with every new model.**

## 3. What was built

| File | Role |
|---|---|
| `clippershq/pipguard.py` | the guard — CLI + `--hook` mode |
| `tests/test_pipguard.py` | 29 offline checks, synthetic pip reports, no network |
| `docs/DEPENDENCY_GUARD.md` | rationale, protected set, override, limits |
| `SAFE_PIP.bat` | Windows convenience wrapper |
| `.claude/settings.json` | `PreToolUse`/`Bash` hook (`.claude/` was previously empty) |

### How it works

It runs `pip install --dry-run --report`, reads **pip's own resolution report**, and compares
every protected package in the `install` list against what is installed now. Nothing reaches
`site-packages` unless the resolution is clean.

### Two verdicts, both refusing

**`DOWNGRADE`** — the public version goes backwards. `numpy 2.3.2 -> 1.26.4`.

**`VARIANT CHANGE`** — the public version is identical but the local/build tag changes:
`torch 2.11.0+cpu -> 2.11.0`. **This is the one a naive guard misses**, because PEP 440
ranks a local version *above* a bare one:

```python
Version("2.11.0+cpu") > Version("2.11.0")   # True
```

So a `proposed < installed` test returns `False` and the swap sails through — yet this is
precisely the BL-681 mechanism, a GPU-flavoured wheel replacing the CPU build the host is
pinned to. The guard compares the public version and the local segment separately.

### Deliberately *not* blocked

Upgrades · first-time installs of an absent package (installing `torchaudio 2.11.0` fresh
alongside `torch 2.11.0+cpu` is exactly the case BL-681 cleared, and stays frictionless) ·
anything outside the protected set · `--dry-run` · `pip list/show/freeze`.

**A guard that fires on things that do not matter gets routed around, and then it protects
nothing.** The protected set is eight packages, not everything installed.

### The override is per-package, and there is no `--force`

```
python clippershq/pipguard.py install laion-clap --allow-downgrade numpy
```

Allowing `numpy` does not quietly allow `transformers`. The refusal prints the exact flags
for whatever it caught — one copy-paste, never an accident.

### Distribution name vs import name

The mapping is the point, not decoration: `pillow` breaks **`PIL`**, `opencv-python` breaks
**`cv2`**. `opencv-python-headless` / `-contrib-` variants normalize onto one key, since one
replacing another is a real swap.

numba 0.63.1 · cv2 4.10.0 · scipy 1.17.1`

"deny"`; allows the guard's own invocation, `--dry-run`, and unrelated commands.

**Suites:** `test_pipguard.py` **PASS, 29 checks**. Full run **40/40 green, 1851 checks**.
*(See §7 — a 41st suite appeared mid-run and is red for reasons unrelated to this work.)*

**Config:** parses, 153 top-level keys, campaigns SHA **`8e02f8d6f6307ae8` MATCH**.

floor — 9 ms of actual guard** (was 105 ms before the deferral). Do not move those imports
back to module scope.

(`pipguard.py`, `SAFE_PIP.bat`) works right now regardless.

## 8. Limits

- **Uninstalls are not read from the report.** pip's `--report` lists what would be
  *installed*, not removed. The hook covers direct `pip uninstall` separately.
- **The dry run is not free** — pip still builds wheels for sdists to read metadata, so a
  heavy package can take a minute.
- **The shell matcher is broad on purpose.** A command merely *mentioning* `pip install` in a
  quoted string can be stopped. A false stop costs one message; a false pass costs the vision
  stack.
- **It guards one interpreter.** A different venv, `conda`, or pip run from elsewhere is out
  of reach.
- **`--hook` is not a security boundary.** It stops accidents, not a determined bypass — the
  threat model is a well-meaning agent installing a model, not an attacker.
- **The corrected figures in §6 are recorded as given by the owner**; they were not
  re-measured here, and the source files could not be edited.
