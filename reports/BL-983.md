A run from a worktree would have walked an **empty library**, appended leads to a **new CSV beside the worktree**, and **reset every well to unvisited**. None of it raises. Same family as `.claims` and `spend.json`, one level further in: the address is right and the contents are not.

`repo_paths.resolve_config_paths()` does the work; `main.load_config` calls it; and `run.py`'s headless entry — the one a worktree round uses, because there is no menu in a worktree — now goes through `load_config` instead of a bare `json.load`.

### The two things most likely to go wrong were not the resolution

**1 — rewriting an HTTP route.** Three values look exactly like absolute POSIX paths and are API route fragments:

```
api.videos_endpoint             /v1/user/videos
ig_api.medias_endpoint          /v2/user/clips
tikhub_api.user_posts_endpoint  /api/v1/tiktok/app/v3/fetch_user_post_videos
```

A value-shape heuristic turns the first into `C:\…\v1\user\videos` and a funnel that has worked for months stops. So the allowlist is by **key name**, and `CONFIG_NON_PATH_KEYS` records the exclusions as a decision somebody made rather than an oversight. **A hardcoded allowlist cannot detect drift on its own** (MEMEBOT-027), so a test walks the *live* config.json and fails on any path-shaped key that is in neither list. It currently reports `none — every path-shaped key is either resolved or deliberately excluded`.

**2 — baking one machine's paths into a shared file.** `control.py` hands the loaded dict to the settings editor and saves the **same dict** back. Resolve in place and the next settings edit writes `C:\Users\<whoever>\…\clip_library` into config.json — permanently, for every other checkout, and **invisibly**, because config.json is gitignored so no diff would ever show it. So `resolve_config_paths` returns a **new** dict and never mutates its input, and `save_config` **relativises symmetrically**.

The inverse reads the file currently on disk so each key keeps its own **spelling** — the live config writes five of these as `./clip_library` and three as `clip_seen.json`. `like` preserves spelling, never **value**: a genuine edit still lands as the new path. Proved on the **live** config, not a fixture, because the fixture is not the file that would be corrupted:

```python
def test_save_config_after_load_config_leaves_the_file_BYTE_IDENTICAL(self):
    M.save_config(M.load_config(copy), copy)      # on a temp copy of the LIVE config
```

## 3. The adoption verdict, plainly

**A worktree is now correct for the registry, the money ledger, and every config path. Everything that used to produce a *plausible wrong number* is fixed; what remains announces itself.** An empty registry answered "no rounds in flight". A second ledger made every `--cap` advisory. An empty library would have been walked in silence. All three now resolve to the shared copy. What is left raises `could not read memebot\scraper\config.yaml` and stops.

**Adoption, in order:**

1. **Resolve `clip_pipeline.py`'s four defaults** against the shared root, the same way `main.repo_path` now does. Small; it is the last piece. Its file is another round's today.
2. **A branch per round.** One branch cannot be checked out twice, so ten rounds need ten branches. This is the real cost, and it is a workflow decision rather than a fix.
3. **Decide about `scratch/`** — half-tracked today. Either track what rounds share, or accept that a worktree round cannot read another round's untracked measurements.
4. Then per-round worktrees **remove** the shared-index class instead of policing it at commit time, which is what the guard does today — after 29 commits had already carried another round's work.

## 4. Item 4: `claims_read.py` still always answers

Its contract is that a round gets an answer even when `claim.py` is mid-save; that is why it imports no `claim.py`. It imports `repo_paths` now, and three tests hold the line:

* an **unimportable** `repo_paths` degrades to the old CWD-relative name;
* a `repo_paths` that **raises** also degrades — **not the same failure**, and the more realistic one: a half-written module imports fine and then throws, which is exactly what a file being saved looks like;
* **degraded still means answering** — it reads a real registry and returns `1`, not merely "does not raise".

A stillness check that dies when its helper is mid-save is the precise failure BL-901/BL-903 built this module to prevent.

## 5. Item 5, and it caught me twice in this round

**An exit-code-only harness is not evidence.** BL-973's clone harness scored a `pathspec did not match` error as a guard refusal. Mine did worse, twice, and both were caught by insisting the result be the **observed string**:

* The first funnel check reported **`warnings.warn(`** as its evidence — true, useless, and hiding the real outcome. It now **classifies**: `CAP BOUND` / `NO CANDIDATES` / `DIED BEFORE THE CAP` / `OTHER`, records the transcript tail, and treats an exit code of 0 with the wrong reason as a failure. That is how the `memebot/scraper/config.yaml` blocker was found at all.
* Then it happened *again* one layer down: I took `tail[-1]` of stdout+stderr, and stderr's urllib3 warning is appended last, so the line carrying the claim was never examined. Now it greps the whole transcript for the line that carries the claim.

**The rule, in one sentence: the string you look at has to be the one that carries the claim.**

Only the second attempt, with an actual `cd`, showed the real failure — which is the same lesson as §5 arriving by a different road: **the thing you measured has to be the thing you meant to measure.**
