# BL-1191 — the TikTok funnel, built video-first, and the chain does not end in zero

**214 videos → 185 authors → 119 profiles bought → 117 passing → 13 emails → 12 in master → 12 in the send file.**

On Instagram the equivalent chain ran 722 → 373 → 63 → 273 → **ZERO**, and every loss hid in a
stage nobody counted. This one is counted at every arrow and ends with a file.

**The email rate on discovered accounts is 13 of 119 — 10.9%.** BL-1189 measured **0 of 48** on
the same vendor, and the difference is the discovery path: it used `followers` and `suggested`,
which return an account's *fans*; this uses `search` and `hashtag/medias`, which return
**content authors**. That single change is what makes the funnel work.

Every figure here came from **`.venv\Scripts\python.exe`, Python 3.11.9**. Bare `python` is
3.13.14 and lacks the packages; it was used only for the stdlib-only claim readers.

## 1. The endpoint that isn't there, made loud

BL-1189 measured that LamaTok has no user-videos endpoint. The shipped code still *asked* for
one: `config.json` names `/v1/user/videos`, `_get` maps its 404 to `None`, and
`discovery.fetch_recent_videos` documented that as *"FAIL-SAFE … deep signals stay UNKNOWN →
flagged, never cut"*.

**That is the benign-zero shape — a permanent, structural absence wearing a transient
unknown's costume — and it cost a billed request every single time.**

Changing the default was not enough, because config names the dead path explicitly. So:

- `api_client.DEAD_VIDEO_PATHS` — the seven paths BL-1189 measured to 404, refused in code
- `api_client.UnsupportedEndpoint(LookupError)` — **deliberately not** a subclass of
  `LamaTokApiError`, so a permanent absence and a transient failure cannot be retried alike
- `discovery.fetch_recent_videos` still returns `None` (its contract is kept) but now logs the
  cause at **WARNING**

Measured after the fix: **the refusal raises and spends 0 requests.**

## 2. The shape the vendor forces

```
/v2/search + /v1/hashtag/medias  ->  VIDEOS, each carrying author + play_count + desc
                                 ->  group by author
                                 ->  ONE profile call per author  (bio, followers, email)
                                 ->  frame_text (on-screen) + clip_speech VAD (talking?)
```

Every author arrives with evidence already attached, and the discovery that produced it is
shared across the whole batch. **Cost per author: one profile call, $0.000600.**

**Two dialects, both read.** `search` nests the video under `aweme_info` with snake_case
`statistics.play_count`; `hashtag/medias` returns camelCase `stats.playCount`. Reading one and
not the other is silently seeing zero views on half the supply.

**`envelope` is the fallback, not the first move — and that order is load-bearing.**
`envelope.items_of` depth-searches for the first list of dicts, which on a search payload finds
an *inner* list before the outer `search_item_list`; every video came back `None` until the
known key was tried first. It is the right tool for an uncatalogued shape and the wrong one for
a known one.

## 3. His rules, and what each one cost

| rule | source | effect |
|---|---|---|
| avg views ≥ 3,000 | his number, verbatim | free — `play_count` rides on discovery |
| English | his standing discipline | free — bio + captions |
| text on screen | his core format | free in money, ~15s OCR per video |
| not mainly talking | "text-on-screen should not talk" | free — `clip_speech`, local |
| any niche | explicit | queries span movies, cars, football, quotes |
| **follower size** | **explicitly NOT a rule** | **not gated** |

**Follower count is not a gate, and that is deliberate.** His 31 span 155 → 1,200,000, a
7,700x spread. But BL-1189 measured that the 7 who publish an email have **13.4x** the median
followers of those who don't — so **an email-first funnel is implicitly a big-account funnel
whether or not anyone writes a size rule.** `split_lists()` makes that visible rather than
letting it happen quietly.

### A real bug his own accounts exposed

`yndaep7`'s bio reads **𝑩𝒂𝒍𝒍𝒆𝒓 𝑪𝒐𝒏𝒕𝒆𝒏𝒕 𝑸𝒖𝒐𝒕𝒆𝒔 𝑫𝑴 𝑭𝒐𝒓 𝑺𝒐𝒏𝒈 𝑷𝒓𝒐𝒎𝒐** — U+1D400-block
mathematical bold italic, not the letters `DM For Song Promo`. A plain regex misses it
entirely, and it would have silently dropped a page **advertising exactly what he wants to
buy**. `_plain()` NFKD-folds those blocks before matching. Re-run over his real 31:

| | BL-1189's cruder regex | after the fix |
|---|---:|---:|
| promo advertisers | 7 | **9** |
| reachable (email ∪ promo) | 35.5% | **38.7%** |

### The two lists stay disjoint

22.6% publish an email, 22.6% advertise promo, only 9.7% do both. One list would bury half of
them, so `split_lists()` returns the **email list** and the **promo-only DM list** separately.
This run: **13 emails, 8 promo-only.**

## 4. The structural weakness, measured rather than hidden

Discovery returns **1.15 videos per author**. Requiring 3 observed videos before judging — the
honest reading of "average views" — leaves **6 of 185 authors, 3.2%**.

| `min_videos` | judgeable | profiles bought | passing | emails |
|---:|---:|---:|---:|---:|
| **3** (default) | 6 of 185 | 6 | 6 | 0 |
| **1** | 179 of 185 | 119 | 117 | **13** |

So the funnel as run used a **single-video** view sample, and **that is not his rule.** He
asked for an average over the latest ten; this vendor cannot supply ten, and search supplies
about one. `average_views(min_videos=…)` is a parameter with the cost printed beside it, the
verdict records `evidence_is_single_video`, and the default stays at 3 — an average of one
video is not an average.

**The other consequence: 117 of 119 passed.** With one video the view gate is nearly the only
active rule and it rejects almost nothing. This filter is not yet discriminating, and saying so
is more useful than a pass rate that flatters it.

## 5. The send file

`output/TIKTOK_PAGES_BOT_READY.csv` — **12 addresses**, its own file because a TikTok page is
somebody we PAY, not somebody we HIRE.

**MX was refreshed FIRST, and it mattered:**

| | before | after |
|---|---:|---:|
| this file's domains covered by the MX table | **4 of 8 — 50.0%** | **8 of 8 — 100.0%** |

Four of eight were UNPROBED. A domain absent from the table is correctly UNKNOWN and unknown
is never cut, so **suppression across half the file would have been vacuous** — the same shape
BL-1002 measured at 9 of 13 on the meme file.

**The partition is three-way now**: `ALL_BOT_READY` (editors), `MEME_PAGES_BOT_READY`
(Instagram), and this. Two files can stay apart by luck; three cannot, so `build()` excludes
anything present in either other file and `assert_clean()` re-reads the finished output
independently. Result: **0 overlaps, 0 duplicates, re-check CLEAN.** Role inboxes are kept and
flagged per his standing decision.

The dashboard download button is live via the `DATASETS` registry (`tiktok_pages`, 12 rows,
11 columns) — no `app.js` change.

## 7. Suites and spend

### Four guards caught this round, and every one was right

The first full run was **6 red of 272**, four more than the two inherited memebot failures.
All four were mine and all four were real:

1. **`test_atomic_io`** — two bare `os.replace` calls in my new modules. On Windows that call
   FAILS while another process holds the file, measured at up to **85% of `master_leads.csv`
   finalises** (BL-927), and a send file is exactly what somebody has open in Excel. Both now
   go through `atomic_io.replace`.
2. **`test_envelope`** — `tiktok_finder.profile_of` flagged as a depth-blind endpoint reader.
   It is on the allow-list *with its reason*: LamaTok's profile payload is a dict **keyed by
   username** (`.users.<handle>`), not a list, so `envelope.items_of` would return `[]`.
   Reading by key is stricter than a depth search — a payload for the wrong user cannot be
   mistaken for this one — and every LIST-shaped payload in that module does go through
   `envelope`.
3. **`test_send_superset`** — 12 addresses outside the primary. Added to
   `SANCTIONED_SECOND_SEND_FILES` with the three-way-partition reasoning, which is the
   mechanism BL-1182 built for exactly this.
4. **`test_send_list_rebuild`** — two separate failures in sequence: stale
   `ALL_BOT_READY.meta.json` (61,079 vs 61,091 after my master append), then
   `DIRECT_SEND.csv` holding 5 addresses no longer in the primary — **because my MX refresh
   newly suppressed them.** Both derived files regenerated; the refresh doing its job is what
   surfaced it.

Confirming re-run: **3 red of 272 suites, 690.6s, --jobs 4, 5 rounds in flight at 20:00.**
All four of mine are fixed. The remaining three are the two inherited memebot failures
(`pytesseract is not installed`) and `tests/test_review_sheet.py`, whose module
`clippershq/review_sheet.py` is **claimed by BL-1190 and is `' M'` mid-edit** as this is
written.
`tests/test_tiktok_finder.py` green — **25 tests**. `test_governance_rules` green —
