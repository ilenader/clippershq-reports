## Why ROUTED, not BOT_READY

The brief expected "6 after lead_kind lands". **Gate A blocks both `bot_ready_rows` and `dm_list_rows`, so its pass criterion has to be that every row lands *somewhere* — not that all six land in BOT_READY.** A row with no deliverable email belongs in DM_LIST by design; that is the whole point of having two files. Counting only BOT_READY would score a correctly-routed DM lead as a failure.

It is also not achievable as stated: the harness needs six channels that clear the size and country gates, and only **five** email-bearing candidates exist in the saved data. Forcing six would have meant inventing an address.

So the harness reports `ROUTED = BOT_READY + DM_LIST` as Gate A's criterion, and prints the split. Today: 6 routed, 3 and 3.

## The harness

Six real channels from `scratch/yt_viewfloor/channels.json` (200 captured live in an earlier round), selected deterministically against the live config — `subs >= 50,000 OR views >= 2,000,000`, `subs <= 5,000,000`, country in target-or-unknown. 58 of 200 pass; the six used are 4 with a description email and 2 without, so **both** writer paths are exercised.

**It needs no edit when the remaining fix lands.** Rows are not hand-written — they go through `youtube_finder.append_found_to_master`, the funnel's own writer, into a scratch CSV whose header is the real master header unioned with `writer.FULL_COLUMNS`. Nothing hardcodes a kind, a verdict or an activity. That is exactly why it detected Gate A opening without being touched.

It reports the scratch header and the real master separately, because only one of them means the fix has landed:

```
lead_kind in real master : False   <- the one that means the fix landed
lead_kind in scratch hdr : True    (harness unions FULL_COLUMNS so the column has somewhere to live)
funnel wrote a value     : True
lead_kind resolved to    : client
```

**`lead_kind` is still not a column in the real master.** The funnel writes it; the master schema has not caught up.

## Gate by gate

### A — routing / verdict · **OPEN**

`writer.py` was already kind-aware at both sites before this round — `bot_ready_rows:977` and `dm_list_rows:1174` both read `if kind == LEAD_KIND_CLIPPER and verdict not in BOT_READY_VERDICTS`. The block was never the verdict test itself; it was that nothing wrote `lead_kind`, so `lead_kind_of("")` returned `unroutable` and every row was excluded before the verdict was even considered.

```
bot_ready_rows : 3 kept, 0 dropped as unroutable
dm_list_rows   : 3 kept, 0 dropped as unroutable
verdict on these rows : (empty)     <- correctly ignored for a client
```

### B — liveness · **BLOCKED**

```
last_post_date : {''}      date_source : {''}      activity : UNKNOWN x6
ALIVE          : 0 of 6
```

`send_list.py:233` cuts anything that is not `ALIVE`. A YouTube row has neither field, so `_activity_of` returns `UNKNOWN`. BL-767 calls this **unpopulatable, not unpopulated** — there is no deep post check for a channel — and restores the never-cut rule by ranking on `_ACT_RANK` instead of filtering.

Worth noting: **`_ACT_RANK` already exists** at `send_list.py:58`, with the comment *"UNKNOWN is 'we could not check', never 'bad'"* — sitting directly above code that cuts on it.

### C — campaign attribution · **BLOCKED**

```
source_hashtag : {'youtube_finder'}
attribute()    : UNATTRIBUTED x6
```

**A correction to my own first draft of the harness:** I initially wrote that a client row "carries no source_hashtag". It does — the funnel label `youtube_finder`. But `attribute()` expects a `tt:hashtag:x` triple resolved against a campaign tag pool, so a funnel label resolves `UNATTRIBUTED` and the row never enters a campaign bucket. BL-767 specifies clients should resolve to a client campaign or `DIRECT`, never `UNATTRIBUTED` — and this gate is precisely why BL-767's own table leaves the SEND figure unchanged at 1,398.

## The `.la` finding, and how wrong the guess was

The harness surfaced it: 4 of the six rows carry a description email, but only 3 reach BOT_READY. `lay***@sparkmedia.la` fails `_first_email` because `la` is not in `bio_parser._GOOD_TLDS`.

**The stated hypothesis — that an allowlist missing `.la` "almost certainly misses .io, .ai, .co, .gg" — is refuted.** All four are present. The allowlist holds **93 TLDs** and is well curated:

| TLD | in allowlist |
|---|---|
| `.io` `.ai` `.co` `.gg` `.dev` `.xyz` `.tv` `.me` `.us` | **yes, all of them** |
| `.la` | **no** |

### Full sweep of master

**20 addresses of 4,233 (0.47%) carry a TLD outside the allowlist**, across 18 distinct TLDs:

| TLD | n | sample | reads as |
|---|---|---|---|
| `.im` | 2 | `con***@manus.im`, `con***@monica.im` | real |
| `.am` | 2 | `con***@hood.am`, `hel***@harbour.am` | real |
| `.band` | 1 | `man***@theguestlist.band` | **real — music industry** |
| `.cymru` | 1 | `ada***@clwbmusic.cymru` | **real — Welsh music org** |
| `.social` `.team` `.group` `.tools` `.chat` `.today` `.food` | 7 | `bus***@runa.social`, `she***@the.team` | real |
| `.is` `.je` `.la` | 3 | `lau***@votiv.is`, `tea***@blackbox.la` | real |
| `.buzz` `.sucks` `.cat` | 3 | `hai***@squad.buzz`, `hel***@sam.sucks` | ambiguous |
| `.con` | 1 | `ind***@gmail.con` | **typo — correctly dropped** |

**Roughly 16 of the 20 look like genuine businesses**, one is a `gmail.con` typo the filter is right to kill, and three are ambiguous. Two of the sixteen — `.band` and `.cymru` — are music-industry domains, which is the client funnel's exact target.

**So the allowlist is doing its job at 99.5%.** This is a long-tail gap of modern gTLDs and small ccTLDs, not the structural hole the `.la` case suggested. Sixteen addresses is small in absolute terms but they are silently dropped with no counter anywhere. **Reported only — the list was not changed.**

## Limits

- **Gate A's "OPEN" is measured on six synthetic-but-real rows in a scratch CSV, not on a live YouTube run.** No YouTube run has ever executed (BL-777), so nothing has exercised this path end to end against the real master.
- **`lead_kind` is not in the real master header.** The harness proves the funnel writes it and the writers honour it; whether it survives a real append to the real master is untested.
- **The three gates were found by reading `send_list.build` in order.** There may be further gates after attribution that no row has yet reached — nothing has ever got past C, so C+1 is unexplored.
- **The 16-of-20 "reads as real" split is my judgement from the domain string**, not verified by sending or by DNS. `.cat` in particular could be Catalonia or junk.
- **The TLD sweep counts addresses in the `email` column only.** Addresses living in `bio`, `link_in_bio` or `extra_socials` were not swept.
- **`.la` itself appears once in master** (`blackbox.la`); the `sparkmedia.la` case that started this is in the saved channel data, not in master, so it is not counted in the 20.
