## 1. It was broken four ways

| # | defect | consequence |
|---|---|---|
| 1 | the textarea existed **only on the "wrong call" panel** | "right call, wrong reason" had no box at all — the direction where a NEW word is most likely |
| 2 | it saved on **Ctrl+Enter only**, advertised nowhere but a placeholder, **no button** | a mouse user had no way to save typed text whatsoever |
| 3 | preset clicks passed `free` as `''` | clicking a preset **silently discarded** whatever he had typed |
| 4 | `reason:(free||label||'')` | typed text **overwrote the preset label** when both were present |

I had assumed one defect and found four. Defect 1 alone means half the brief's requirement —
"both directions" — was structurally impossible before this round.

## 2. What ships

- **A textarea on both panels**, each with a real `<label>` (a placeholder is not a label — it
  vanishes on input) and a visible **"Save this reason"** button.
- **Plain Enter saves.** Shift+Enter still makes a newline, because a two-line reason is a
  reasonable thing to want. Ctrl/Cmd+Enter kept — it is what the old placeholder taught.
- **Presets carry the typed text**, so both are recorded.
- **`free_text` is its own field**, beside `reason` and `reason_code`. `reason` keeps its old
  meaning for every existing reader.
- **An empty box is not an answer.**
- Presets, their order, and the two-click fast path are **unchanged**.

The record he now produces — read back off disk after a real click:

```json
{"handle":"…","mark":"BAD","reason":"not a meme page, this is some random chat page",
 "reason_code":"other","free_text":"not a meme page, this is some random chat page"}
{"handle":"…","mark":"BAD","reason":"A person / content creator — not a meme page",
 "reason_code":"creator_page","free_text":"and it is also a chat page"}
```

Append-only, newest-per-handle, **keyed by handle** — row numbers have already collided across
sheets.
