# BL-689 — CLAP for the coarse 4-way mood split: the model is cleared, the labels are the blocker

## The premise was right on both counts. The 56-tag PR-AUC 0.154 result genuinely does not speak to a 4-way coarse split, and CLAP had never been evaluated. So I evaluated it — and CLAP clears every objection that was ever raised against it: **Apache-2.0, 153.5M params, 0.208 s per 30s clip on this CPU, no GPU, and installable with ZERO package changes to this environment.** What I cannot deliver is the number you actually asked for. Producing "4-way accuracy on MY clips" requires hand-labelling 80 clips by listening to them, and I have no audio perception. The only labels derivable without ears come from licensed track titles, of which this corpus holds **22 unique tracks** — about 5 per class, a 95% CI near ±20 points, which cannot separate "85%, ship it" from "60%, don't". **The blocker is ground truth. It is not CLAP, not audio, and not the install.**

## 1. THE INSTALL HAZARD — fired, honoured, and then routed around

Environment, unchanged before and after: python 3.11.9 · torch **2.11.0+cpu** · numpy **2.3.2** · PIL **12.2.0** · transformers **5.12.1**.

Concurrency check first, as instructed: only two long-lived `http.server` processes from 2026-07-28 (unrelated static server). No agent Python process active.

`pip install --dry-run` — **nothing installed at any point**:

| package | verdict | what it would have done |
|---|---|---|
| `laion-clap` | **BLOCKED** | **downgrades numpy 2.3.2 → 1.26.4** (librosa→numba pin), plus wandb, sentry-sdk, h5py, webdataset, wget, progressbar |
| `msclap` | **BLOCKED, worse** | **numpy → 1.26.4**, **transformers 5.12.1 → 4.57.6**, **huggingface_hub → 0.36.2**, plus pandas, pytz |
| `librosa` + `soundfile` | safe | adds 10 packages, **no numpy/torch/PIL change** |
| `torchaudio` | safe | resolves to `torchaudio-2.11.0`, matching torch exactly |

torch 2.11.0 is built against the numpy 2.x ABI, so the 1.26.4 downgrade would break torch, PIL and every concurrent agent on this shared interpreter. Both CLAP pip packages trip the stop condition, so I stopped.

**Then the hazard turned out to be avoidable entirely, which is the finding that matters.** The poison is the *convenience wrappers*, not the model. `transformers` **5.12.1 already ships `ClapModel` and `ClapProcessor`**, loading the same `laion/clap-htsat-unfused` weights, and `ClapProcessor` accepts a raw numpy waveform. Everything below was measured with **zero package installs** — only a weight download.

> Two transformers-5.x API changes worth recording for whoever wires this: `get_text_features` / `get_audio_features` now return a `BaseModelOutputWithPooling`, not a bare tensor, and the processor kwarg `audios=` is now `audio=`.

## 2. LICENCES — one clean, one split, one disqualifying

| model | code licence | weights licence | commercially free? |
|---|---|---|---|
| **LAION-CLAP** `laion/clap-htsat-unfused` | Apache-2.0 | **Apache-2.0** | **YES — clean** |
| **Microsoft CLAP** `microsoft/CLAP` | **MIT** (verified in repo `LICENSE`) | **ms-pl** (verified on the HF card) | Yes, but two licences in one project |
| **MERT** `m-a-p/MERT-v1-95M` / `-330M` | — | **CC-BY-NC-4.0** | **NO — disqualified** |
| CultureMERT-95M | — | CC-BY-NC-4.0 | **NO** |

The MS-CLAP split is real, not a citation error: the GitHub `LICENSE` opens *"MIT License / Copyright (c) Microsoft Corporation"*, while the Hugging Face model card tags `license: ms-pl`. MS-PL is OSI-approved and permits commercial use with reciprocity on distributing modified source — but it is the **weights** that carry it, and weights are what ship.

**MERT is out on licence alone.** CC-BY-NC-4.0 forbids commercial use. Whatever it scores, it cannot be used here, and it should not be benchmarked further for this purpose. That answers item 6: the strongest-performing 2026-era music foundation models in the MERT family are all NC-licensed, which is why a CLAP-shaped model is the right target regardless of accuracy.

**Recommendation on licence grounds: LAION-CLAP.** Apache-2.0 on both halves, no ambiguity.

## 3. CLAP ON THIS BOX — measured, zero installs

`laion/clap-htsat-unfused`, CPU-only, 12 torch threads, synthetic 30s audio (throughput is a property of model and CPU, not content):

| measurement | value |
|---|---|
| parameters | **153.5 M** |
| fp32 in memory | **586 MB** (615 MB on disk at HF) |
| embedding dim | **512** |
| **GPU required** | **NO** — `torch.cuda.is_available() == False` throughout |
| model load (warm) | 4.2 s |
| text, 4 prompts | 0.607 s — once per prompt set, then cached |
| **audio, single 30s clip** | **0.295 s** |
| **audio, batch of 8 × 30s** | 1.665 s = **0.208 s per clip** |
| **throughput** | **~17,300 clips/hour** |

Batching 8 buys ~1.4×. The entire 225-reel corpus would embed in **under a minute of compute**. Cost is not a constraint for this feature at any volume this funnel will ever see.

## 4. THE TRANSDUCTIVE REFINEMENT — compute claim verified, accuracy claim untestable

*Transductive Zero-Shot Audio Classification with Audio-Language Models* (arXiv 2606.17160) models the test batch as a mixture of C directional components on the unit sphere, one per class, with the **frozen text embeddings as anchors**, fitted by EM — no labels, no gradients. Published settings: β=0.5, fixed 3 iterations, no early stopping, identical across datasets. Reported: **+4.6 to +9.2 top-1 points** (ESC-50 89.1→94.8, UrbanSound8K 73.8→81.8).

I implemented it and timed it on random 512-d embeddings:

| batch | measured |
|---|---|
| 2,000 clips, 3 iters | **10.4 ms** |
| 10,000 clips, 3 iters | 49.0 ms |

**The "~15 ms on one CPU core for 2,000 clips" claim is confirmed and slightly beaten.** The method is genuinely free at this scale, and this funnel's regime — unlabelled clips arriving in batches — is exactly the transductive setting it assumes.

**This verifies the COST only.** The accuracy gain cannot be checked without labelled audio. If zero-shot lands in the high 70s this is plausibly what clears 85%; it cannot rescue a result that was never measured.

> **Correction.** My first inventory reported "no audio, and ffmpeg missing". Both were wrong. I had checked only the *licensed* `music_asset_info` path (35/225) and missed `original_sound_info.progressive_download_url` (153/225) — the same asset BL-682 found independently. And my ffmpeg check tested a Python *module* named `ffmpeg`, not the binary: **`ffmpeg 8.0` is installed and on PATH.** Audio is obtainable, free, audio-only, in minutes.

Better still: **~91 clip audio files already exist on this machine** from BL-682's round, named `<handle>_<pk>.mp4`. Steps 1 and 2 of any benchmark plan are already done.

**Ground truth — this is the blocker, and it does not move:**

| | count |
|---|---|
| `licensed_music` with a real title + artist | **35 / 225** → **22 unique tracks** |
| `original_sounds` | 154 / 225 |
| no `clips_metadata` at all | 36 / 225 |
| original-sound, artist attributed but no title | 33 |

The 22 nameable tracks are real and mood-legible from title alone — *The Winner Takes It All* (ABBA), *Happier Than Ever* (Billie Eilish), *Where Is My Mind?* (Pixies), *Cornfield Chase* (Hans Zimmer), *Criminal* (Britney Spears), *stupid song* (Olivia Rodrigo), *Cico Buff* (Cocteau Twins). Publishing a number from that sample would be measurement theatre, so I have not.

This also matches BL-682's independent finding from the other direction: licensed track metadata is **0/108** on repost/meme pages. On the population this funnel actually targets, metadata-derived mood labels essentially do not exist.

## 6. WHAT I DID NOT DO

* **Did not install anything.** Both CLAP pip packages tripped the stated stop condition.
* **Did not fabricate labels.** I cannot listen to audio; inventing ground truth would have produced a confident, unfalsifiable, wrong number.
* **Did not report a 4-way accuracy or a confusion matrix.** There is no honest one to report. You asked specifically to see *which pairs* confuse — sad-vs-chill failing being very different from sad-vs-hype — and that diagnosis is exactly what a 5-per-class sample cannot support.
* **Did not benchmark prompt formulations (item 3) or few-shot k-NN (item 5).** Both are downstream of labels: prompt wording is scored *by* accuracy, and few-shot k-NN classifies *against* labelled neighbours. Both are mechanical once labels exist.

## 7. THE VERDICT, AND THE ONE DECISION THAT UNBLOCKS IT

**"Mood is not achievable" remains unproven — and so does the opposite.** What this round establishes is that every objection *except one* has now fallen:

* the coarse 4-way framing was never tested, and the 56-tag PR-AUC 0.154 result does not bear on it;
* CLAP is licence-clean, small, CPU-fast, GPU-free, and installs without touching this environment;
* the transductive lift is real, free, and applies to this exact regime;
* audio is free and already partly downloaded;
* MERT and its family are disqualified on licence, not accuracy.

**The remaining blocker is a single decision: who listens.** To finish:

1. Take 80 clips with a live `progressive_download_url` — ~91 audio files are already on disk.
2. Decode to 30 s mono 48 kHz (ffmpeg 8.0 present).
3. **The owner listens and labels all 80** into sad / hype / chill / aggressive. Persist as `mood_labels_v1.csv` — `pk, handle, url_hash, label, labeller, date` — committed to the repo, so the result is reproducible. This is the explicit lesson from the last measurement that became unreproducible: ground truth must be persisted, not remembered.
4. Load CLAP via `transformers` (zero installs), ideally in a dedicated venv so the shared environment is untouched regardless.
5. Zero-shot with ≥3 prompt formulations per class; report per-wording accuracy — prompt sensitivity is a real lever, not noise.
6. Apply the transductive EM (β=0.5, 3 iterations) on top.
7. Few-shot leave-one-out k-NN on the same 80 — this sidesteps the "no ground truth in music emotion" objection entirely, because the owner defines the buckets.
8. Report 4-way accuracy **and the confusion matrix**.

Step 3 is roughly 40 minutes of listening and is the only step that cannot be delegated to an agent. Steps 1-2 and 4-8 are mechanical and cheap — under a minute of compute for the whole corpus.

Reproducibility: `scratch/mood_corpus_inventory.py` (corpus counts), `scratch/clap_cpu_bench.py` (all §3 and §4 numbers, writes `clap_cpu_bench_out.json`), `scratch/mood_clap_findings.md` (incremental log). None makes a network call beyond the model download; none writes to production state.
