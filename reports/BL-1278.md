## 1. What the Spotify path actually touches

### The closure was resolved three ways, because a grep would have shipped a broken folder

1. **Import-time** — actually `import spotify_finder` and diff `sys.modules`.
2. **AST** — walk every module and collect imports *including inside function bodies*.
3. **Fixed point** — repeat until nothing new appears.

**Five modules are lazy-only and invisible to a top-level scan: `crossdedup`,
`musicbrainz`, `listenbrainz`, `run_resume`, `spend_ledger`.** `crossdedup` is the single
writer of `master_leads.csv`, imported at `spotify_finder.py:1408` — a folder missing it
fails at the last step, *after* every dollar has been spent.

**And the AST method over-catches, which matters just as much.** Walking `control.py`'s
function bodies pulls in every other funnel and the whole clip/OCR chain — **82 modules**,
torch, easyocr, cv2, faster-whisper. That is the entire product, gigabytes of dependencies
for code that never executes on this path. **The shipped closure is 38 first-party modules
+ 2 from `tools/` + 2 operational extras = 42.**

**`meme_finder.py` is NOT in the closure** — confirmed by import-time diff, by AST closure,
and by reverse-edge search. The `spotify` dispatch spec has no `module` key, so
`importlib.import_module` is never reached for it. **BL-1276 could keep editing it
throughout.**

### The two modules outside `clippershq/` that would have failed silently

`main.py:92` appends `<root>/tools` to `sys.path` and imports **`repo_paths`**;
`stillness.py:129` does the same for **`claims_read`**. Both swallow their import errors —
so omitting them does not crash, it silently disables config path resolution, which is
exactly what makes a relocated folder read the wrong master and re-pay for every lead. Both
are shipped, in a `tools/` subfolder so the `sys.path` shape is reproduced exactly.

### The 214-query bank — counted, not trusted

`playlist_harvest.query_bank()` returns **exactly 214** queries, built by cross-multiplying
five constants (50 genres, 24 regions, 19 moods, 10 sizes, 6 decades) and de-duplicating
first-wins. Executed, not read off a comment. The module's own selftest only asserts `>= 200`.

### The persistent state — this is money, not config

|---|---|
| `spotify_playlists_seen.json` (166 KB) | playlists already walked |
| `resolve_cache.json` (3,121 entries) | handle resolutions **already paid for** |

**Both state files were scanned: zero email-shaped literals in either.** They carry no lead

## 2. Credentials — his decision, and the two measured hazards handled

**No live key is in the folder. `config.template.json` ships with both key names present and
both values empty**, and the folder contains no `config.json` at all until he makes one.

**The key names were wrong in my first draft and that would have been worse than useless.**
I assumed `api.hiker_api_key` / `api.lamatok_api_key`; the code reads **`ig_api.key`**
(`ig_client.py:225`) and **`api.key`** (`api_client.py:248`). A template with invented names
invites him to paste a real key into a field nothing reads, then fail with a credential
error while the key sits right there. Corrected and verified against the source.

**`config_load.py` is new in the copy** and exists for two failures already paid for here:

| hazard | what it did | what the copy does |
|---|---|---|
| a key with a **trailing newline** | raised a client-side `ValueError` that **surfaced as a network error** and was misdiagnosed three times | every credential is `.strip()`ed before anything sees it |
| a **Windows user environment variable** shadowing the file | every fix that edited a repo file **changed nothing** | `source_of()` reports which source actually won |

Both demonstrated live in the off-site copy:

```
HAZARD 1 -- ig_api.key stored as "FAKE_HIKER_KEY_FOR_TEST\n"
   value the code receives : 'FAKE_HIKER_KEY_FOR_TEST'      (stripped)
HAZARD 2 -- HIKER_KEY set in the environment
   value actually used : FROM_THE_ENVIRONMENT_NOT_THE_FILE
   source_of reports   : environment (HIKER_KEY)
   the file still says : FAKE_HIKER_KEY_FOR_TEST
```

"I edited the file and nothing changed" is now answered in one line instead of three
sessions.

### The scan, and the thing it caught that nobody was looking for

| | |
|---:|---|
| **0** | credential-shaped literals |

**But the first scan was not clean, and the finding is worth keeping.** The copied modules
carry 308 email-shaped literals in docstrings — worked examples from debugging the bio
parser. Fingerprinted against the gitignored lead stores, **25 distinct addresses appearing
46 times turned out to be REAL ROWS in `master_leads.csv`**.

**A docstring is still a file.** Shipping the modules unchanged would have handed 25 real
people's addresses to someone who was never meant to receive them — invisibly, because
nobody thinks of a comment as lead data. Same shape as the round that committed 3,972
addresses by moving a container.

They are redacted **in the copy only**, to `two chars + true domain + 6 hex`, at the write
point. **The domain is deliberately kept** — `@letsencrypt.org` is the analytics-boilerplate
lesson, `@gmajl.com` is the typo-domain lesson; redacting the domain destroys the
explanation while the mailbox is the only part that identifies a person.

**One occurrence is executable**, not prose: `send_suppress.py:368` inside the module's own
self-test. A placeholder would break it, so it is substituted with a `booking@` address on an obviously fake label domain
— which preserves the assertion exactly (a `booking@` on a domain that does not match the
handle) — and **the self-test was then run in the copy: `send_suppress self-test: PASS`.**

**And the scanner itself was fixed.** Its first verdict was "NOT CLEAN" on 268 fake
docstring examples. A scanner that cries wolf 268 times is one somebody stops reading — the
exact BL-1257 lesson. The verdict is now decided by the intersection with the real lead
stores, with the harmless count reported separately.

## 4. Running on a clean PC

**Python 3.11+**, and **six packages, all pinned**, derived from the 42 copied modules
rather than inherited:

```
requests==2.32.3   tenacity==9.0.0   openpyxl==3.1.5
spotifyscraper==3.9.2   rich==13.9.4   google-play-scraper==1.2.7
```

`google-play-scraper` is there because `spotify_finder.py:39` imports five email helpers
from `google_play_finder` — the import fails without it even though no Google Play call is
ever made. `rich` is there because `control.py` imports `ui` at module level.

**Explicitly excluded**, and each is a real saving: fastapi, uvicorn, numpy, Pillow,
opencv-python-headless, onnxruntime, faster-whisper, rapidocr. Gigabytes, none of it on
this path. **The brief's warning about `anthropic 0.121.0` being installed but declared in
neither requirements file is exactly the shape avoided here** — every dependency the copy
needs is declared.

**The launcher follows the pattern this project already paid for.** `START_SPOTIFY.bat`
finds Python **by capability, not by name** — absolute paths first, each candidate *run*
before it is believed, so the zero-byte Microsoft Store stub can never be chosen — and
**every exit path goes through `:hold` and pauses**, so a window can never flash and vanish
with an unread error.

**On the taken port.** This folder starts no server, so there is no port to collide on. But
the failure the port guard prevents is live here in another shape: two runs sharing one
read-modify-write seen-set, where the second can roll back the first and re-buy playlists.
`run_spotify.py` takes a **pid-checked lock** and refuses the second run in plain words —
and clears a *stale* lock rather than bricking the folder.

**Absolute paths: zero anchored to this machine.** Verified by searching the finished folder
for `Game Centar` and `clipper finder` — **0 hits**. The 12 remaining drive-anchored strings
are README examples and `C:\Program Files\PythonNNN` *search locations*, which are correct on
any Windows PC.

**The real portability risk was not absolute paths — it was CWD-relative resolution.**
`scratch/resume`, `scratch/runs`, `logs`, `suppress_mx.json` and `output/` all resolve
against the working directory, and `main.load_config` only makes config paths absolute via
`git_common_dir()` — **which returns nothing outside a git repo**, silently leaving the old
CWD-relative behaviour. Two defences: the launcher does `cd /d "%~dp0"`, and `run_spotify.py`
anchors every config path to its own folder regardless.

**The hidden-file hazard was checked, not assumed.** `run_resume._safe()` maps every
non-alnum character to `_`, so a checkpoint name can never begin with a dot. The finished
folder contains **0 dot-prefixed files**.
