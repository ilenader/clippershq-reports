## 1. Commit verification — the fail-open was the wrong target

**The brief said to fix a fail-open. Two things were already true when I arrived, and both
change what the right fix is.**

**First, the `TypeError` was already fixed.** BL-966 claimed `tools/commit_guard.py`,
`tools/commit.py`, `tools/githooks/*` and `docs/CORRECTIONS.md` eleven minutes before this
round started, with the intent *"fix the shared git index … mis-attribution audit into
CORRECTIONS.md"*. `_ok_lines` already accepted `own=` and its docstring addressed exactly the
bug BL-963 hit. **I did not touch any of those files.**

**Second, the runtime fail-open is deliberate, and the reasoning is right.** From
`commit_guard.py`:

> *this hook runs on EVERY commit by EVERY one of ten concurrent rounds. A TypeError in my own
> logic exiting non-zero would brick the repository for all of them, and a guard that can take
> the tree down is a guard someone disables permanently within the hour.*

That is a correct trade, and the file already distinguishes it from the fail-**closed** path
for blindness (`git diff --cached` failing raises rather than reporting "nothing staged").
Converting it to fail-closed would have been the wrong fix.

**The actual gap is narrower and nobody had closed it: nothing detected that the guard had
stopped working.** A crash printed a banner, returned 0, and the commit landed unverified.
BL-963 caught it only because a human read stdout and then checked both commits by hand. Had
nobody looked, every round's commits would have been landing unchecked indefinitely.

So the fail-open stays at runtime, and **detection moves into the suite**.

### Why a refuse-only test would not have caught it

**The crash was on an ALLOW path.** `_ok_lines` is only called when the guard is about to say
yes, from three sites with three different `own=` values. A test that only planted violations
would have stayed green through the entire outage — the refuse paths never touch it.

So every allow path is exercised by name, plus a structural check that goes red if a fourth
call site appears:

```
GuardIsAlive.test_scoped_commit_of_own_paths_does_not_raise      # own=None   <- the crash site
GuardIsAlive.test_unscoped_commit_of_own_paths_does_not_raise    # own=True
GuardIsAlive.test_index_override_does_not_raise                  # own=False
GuardIsAlive.test_every_allow_path_is_covered                    # counts the call sites
```

That second line is the BL-958 gap closing live: `claim.py staged` answers *"do the staged
paths span more than one round?"*, which was true and correct and let BL-961's nine files
land under a BL-958 message. The guard asks the question that actually failed — *does the
round that OWNS these paths match the round that is COMMITTING?*

## 2. The measurement baseline — `docs/TESTING.md` rule 11

Two arms give a disagreement rate and no way to read it: some is the treatment, some is the
model, and nothing separates them. A third arm repeating the **control** condition is
mandatory.

**The measured vision noise floor** (`gemini-2.5-flash-lite`, production prompt, 58 clips,
default resolution *both* times):

| field | agreement between two IDENTICAL runs |
|---|---|
| `vision_on_screen_text` exact | **74.5%** — disagrees with itself on **25.5%** |
| `vision_on_screen_text` presence | 87.9% |
| `vision_scene` word Jaccard | **0.313** |
| beat count | median abs difference **2.0** |

A `vision_scene` Jaccard of 0.31 between two conditions is what *no change at all* looks like.
**This retires every two-arm vision comparison in this repo, including published ones.**

The corollary is recorded with it: **verify the treatment applied before reading the output.**
3 of 62 pairs returned HTTP 200 with no token reduction (~5%) because `extra_body` and
`generationConfig` accept `media_resolution` and silently ignore it. Those rows were dropped
before any quality number was computed; included, they would have scored as evidence the
treatment was harmless.

## 3. The corrections — recorded, and why not in `CORRECTIONS.md`

`docs/CORRECTIONS.md` is held by BL-966 and was modified in the working tree throughout this
round. It is still held now. Writing into another round's open file is the one thing
`docs/PRECONDITIONS.md` says to block on, so both corrections are recorded **in full** in
`docs/GROUND_TRUTH.md`, with **§3 a paste-ready block** for whoever gets that file next.

**Correction 1 — cuts do not beat beats 4.15× to 0.98×.** That score was
`mean |frame[i] − frame[i−1]|`, and `clip_cuts.find_cuts` **is** a frame-difference detector
on the same region. Against 28 hand labels with density controlled: **cuts 1.52×, beats
1.38×, and an exact 12–12 tie** on the 24 clips where both exist. Both required facts are
recorded: **neither signal is strong enough for an automatic drop placer**, and **4 of 28
clips (14%) have no usable cut while beats exist on all 28.**

**Correction 2 — `media_resolution=LOW` is REJECTED.** 3.43× fewer input tokens for
**$0.47 per 1,000 clips — $0.94 library-wide** — against **15.4 points** of exact
`on_screen_text` agreement on a field populated on 80.7% of the library. Safe only where
`on_screen_text` is never read, as a per-call parameter. The hybrid does not rescue it: it
fixes absence but **18 of 44 text-bearing clips disagree on content**, which no heuristic can
see.

## 4. The hand labels, made durable

28 labels and their 28 contact sheets moved from `scratch/` into tracked `ground_truth/`,
with `ground_truth/README.md` carrying the labelling rule, the limits and both scoring traps,
and `tests/test_ground_truth.py` (10 tests) guarding them.

**The limits are attached to the data, not just the report** — the JSON carries its own
`_limits` and `_rule`, and a test asserts both still mention *one labeller* and *inter-rater*:

- **one labeller, one pass — no inter-rater agreement figure.** The biggest gap and the
  cheapest to close: a second labeller on the same 28 sheets costs $0.
- **1-second resolution.** Nothing supports a claim finer than ±1 s.
- **3 of 28 are `low` confidence** — flat montages where the label is the strongest available
  change, *not* a claim a drop belongs there.
- **n = 28**, and selection is not random (8–60 s, local video + stored beats required).

The tests are a tripwire rather than a behaviour check: the set must never quietly shrink,
every label must keep the sheet it was read from, and the caveats must stay attached — that
is how "n=28, one labeller" turns into a number people quote without the caveat.

## What I got wrong

**My mutation harness silently proved nothing on its first run.** It shadowed `tools/` via
`PYTHONPATH` and reported all three planted defects as *"THE SUITE STAYED GREEN — test is
useless"*. The test file's own first line is `sys.path.insert(0, <its dir>/../tools)`, which
wins over `PYTHONPATH`, so every mutated run imported the real, working guard. Fixed by
mirroring the tree (`tmp/tools/`, `tmp/tests/`) so the test's relative import resolves to the
copy. **A harness that cannot fail is worth exactly as much as a test that cannot fail**, and
it was only caught because the harness reported a result I did not believe.

**My structural call-site check was off by one** — `src.count("_ok_lines(rid")` counts the
`def` line too, so it asserted 3 and found 4. Fixed to exclude the definition. Counting a
definition as a call site is the kind of error that makes a structural check useless the day
it fires.
