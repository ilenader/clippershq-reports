## 1. Five ways a leak check reads clean while leaking

Three of these were in the working checker this round was asked to preserve, one was
committed by this module itself, and each was found by making the guard try to fail rather
than by reading it.

### 1.1 `@handle` scored ZERO — the most explicit citation there is

The matcher treated a preceding `@` as a boundary violation and skipped the match. So a
brief writing **`You rejected @_ravelab_`** — the form v7 uses most — was invisible to it.

    "he marked @acog.hitbox as REJECT"   ->  occurrences = 0

**Measured on v7: this alone hid 7 of its 21 leaked pages** — `_diddy_oilup_`,
`absolutftbl`, `delivermeme`, `flash.aez`, `meme_.graveyard`, `memezar`, `roastoday`.
`@` does not extend a handle, it introduces one, and it is now read as the strongest
citation signal there is.

### 1.2 A one-record JSONL file read as an EMPTY MARK SET

`read_records` took the JSON-document branch for anything starting `{`, and a JSONL file
holding exactly one record parses as a `dict` — no list key, no dict values, so it returned
`[]`. An empty mark set is **indistinguishable from "nothing leaked"** at the call site.

**Fixing the fall-through took discovery from 64 mark sets to 115. Fifty-one sets had been
reading as empty.** Found by a test that plants a one-line set in a temp tree, not by
inspection.

### 1.3 A JSON array wearing a `.jsonl` name

`scratch/bl1280_seedprobe_verdicts.jsonl` is a **JSON array**. A line reader returns zero
handles for it. Same silent-empty failure, different route. Both formats are parsed now.

### 1.4 The 6-character floor is necessary and NOT sufficient

The floor exists because `him` and `men` are real handles that occur in prose. But the words
that actually flipped four clean briefs to "leaking" were all **≥ 6 characters**:

    cartoon   "a movie, a TV show, a cartoon, anime, sport"
    gaming    "apply the same test to sport, film, food, gaming and fitness pages"
    records   "the store records a window"

All three are real handles in a 1,122-page discovery corpus. Counting them is how a guard
earns a reputation for crying wolf and gets switched off — which costs more than the check
is worth.

**The rule now has two branches.** A token containing `.` or `_` is a handle by construction
— `acog.hitbox`, `_ravelab_` are not English and cannot be used by accident, so any
boundary-clean occurrence counts. A **plain alphanumeric** token must be *presented as a
page*: `@handle`, `` `handle` ``, `"handle"`, a URL path, or a table cell. Prose use is not
a leak; `` `cartoon` `` is.

### 1.5 The module committed the same sin, and the tree's own guard caught it

`tests/test_silent_zero_shape.py` went red on the first full-suite run with exactly one new
finding:

```
tools/brief_leakcheck.py:read_records
```

`read_records` caught **`OSError`** broadly and returned `[]`. A permission error, a locked
file or a bad decode would therefore produce *precisely the value an empty mark set
produces* — so an unreadable mark set would report as "no handles" and every brief measured
against it would read clean. **That is the silent-empty hole this module documents twice in
its own docstring, committed by the module itself**, and it was caught by a guard written by
another round rather than by me.

Two changes, following that guard's own prescription:

- the file read is narrowed to **`FileNotFoundError`** — the one case where "no records" is
  the honest answer. Everything else is now loud.
- the whole-document JSON parse **binds its exception and carries it forward**. A JSONL file
  legitimately fails that parse, so reaching the handler is ordinary control flow; but if
  the line reader then yields nothing, the file is recorded in `PROBLEMS` with the reason.

`PROBLEMS` earned its place on its first run: **`scratch/bl1271_sources.json` looks like a
mark set and will not parse** (`Expecting ',' delimiter: line 61`). It is now reported as
**UNCHECKED rather than clean**. Inspected: it carries **zero** `handle` fields, so it is a
pricing-sources file rather than a missed mark set — the flag is conservative, which is the
correct direction for this to err.

## 2. Two corrections to the brief I was given

Both were stated as fact and both are wrong. Recording them because a guard should not rest
on a reason that does not hold.

**`\bpeak_edits__\b` does NOT "never match at all".** Checked in three contexts before the
test was written:

| text | `\b` matches? |
|---|---|
| ``he marked `peak_edits__` REJECT`` | **yes** |
| `peak_edits__ was rejected` | **yes** |
| `@peak_edits__ ok` | **yes** |

A trailing `_` followed by a backtick, a space or end-of-line is a perfectly good `\b`.
`\b` **is** the wrong tool, but for the other reason in the brief: it **false-positives
inside a longer handle**, firing on `acog.hitbox` inside `acog.hitbox.backup`. That one
reproduces exactly and is the test that stands.

**The TikTok 105 is not the set the `_tt` briefs leak.** The brief said it was "precisely
the set the two `_tt` briefs would leak against". Measured: `output/bl1259_tiktok_judge/verdicts.jsonl`
has **0% handle overlap with his marks**, and `bl1260_brief_tt.md` and `bl1270_brief_tt2.md`
leak **15 pages each, all from the 623** — the Instagram marks — and **zero** from the
TikTok 105. The set is still discovered and still checked; it simply is not what those
briefs disclose.

## 3. The timing hole, which was the whole point

Checking a brief once per round proves nothing about the bytes actually sent. So the API
takes **text, not a path**:

```python
verdict = guard_scoring(brief_text, scored_handles)   # the bytes about to be sent
if verdict.void:
    raise SystemExit(verdict.sentence)                # DO NOT report a score
for h in verdict.scorable:                            # excluded pages already removed
    ...
```

`Verdict` carries `.excluded`, `.removed`, `.scorable`, `.void` and a `.sentence` that says
which. It is falsy when void, so `if not verdict:` is a correct gate.

For the case where a path is unavoidable, `Watch` holds the sha256 of what it last read and
`changed()` is true the moment the file differs — including when it has been **deleted**,
which must not read as unchanged. Both are tested by rewriting a brief under the watcher and
asserting the rewrite's leak voids the score.

`guard_scoring`'s first parameter is asserted by name in the suite (`brief_text`), so the
signature itself is the guarantee: a filename contains no handles and would silently pass.

## 4. The guard demonstrated failing — on real data, not a fixture

This project has shipped four guards that could not fail, including one that hardcoded a
single mark file with **zero handle overlap** with the corpus being scored, and a readback
that compared `src_line.text` to `src_line.text`. So the demonstration runs on the actual
leaking brief in the tree:

```
$ python tools/brief_leakcheck.py scratch/bl1262_brief_v7.md      ->  exit 1
    _diddy_oilup_        his mark=GOOD  ... `@_diddy_oilup_`
    _ravelab_            his mark=BAD   ... You rejected `@_ravelab_` a
    acog.hitbox          his mark=BAD   ... - `acog.hitbox` (said WANT, he says REJECT)
    maestremoros         his mark=BAD   ... - `maestremoros` (said REJECT, he says WANT)
    memezar              his mark=BAD   ... `@memezar` an
    roastoday            his mark=BAD   ... `@memezar` and `@roastoday`
    thedunkcentralhq     his mark=BAD   ... - `thedunkcentralhq` (said WANT, he says REJECT)
    ... 21 in total
```

It does not merely name the pages. It tells the judge **what it said last time and what he
said** — "You rejected", "You passed", "(said WANT, he says REJECT)". That is an answer key,
and BL-1267 already measured what it buys: with the names stripped, **two of v7's three
"fixes" failed again**.

Three tests hold the failure, each requiring the pre-fix rule to *disagree* with the current
one on real input:

- `test_word_boundary_false_positives_inside_a_longer_handle` — `\b` fires, ours does not.
- `test_the_at_fix_is_what_catches_seven_of_them` — the `@`-excluding matcher misses 7 of
  v7's handles; the test names three of them and fails if the count drops, so the fix cannot
  quietly stop mattering.
- `test_scoring_the_100_on_v7_is_VOID` — asserts `void`, `removed ≥ 6`, `scorable ≤ 94`.

## 5. The guard's own suite, and the ratchet

`tests/test_brief_leakcheck.py` — **24 tests, green**, ~13 s.

**Red on any NEW leak.** A brief not in the ratchet that names a marked page fails the
suite. The nine known-leaking briefs are frozen **by name and by count**:

```python
RATCHET = {
    "scratch/bl1005_briefs.md":      6,    "scratch/bl1260_brief_tt.md":   15,
    "scratch/bl1240_brief_v2.md":    5,    "scratch/bl1262_brief_v7.md":   21,
    "scratch/bl1240_brief_v3.md":   10,    "scratch/bl1265_brief_v8.md":   15,
    "scratch/bl1242_brief_v4.md":   15,    "scratch/bl1270_brief_tt2.md":  15,
    "scratch/bl1258_brief_v5.md":    5,
}
```

**Ratcheting is not cleaning, and the suite refuses to let it be mistaken for it.** Three
tests keep it honest: a ratcheted brief that **grows** fails; a ratcheted brief that is now
**clean** fails (delete the entry — a stale freeze is a lie the next reader inherits); and a
ratcheted brief that no longer **exists** fails. The count may only ever go down.

## 7. What this round did not do

- **It did not clean a single brief.** Nine still name marked pages and all nine are listed
  above by name and count. Stripping them is somebody's round, and the numbers only move
  down from here.
- **It did not touch `edit.py`, `paste_batch.py` or any render path.** Those defects belong
  to another round.
- **It did not wire the check into any scoring caller.** The API exists and is tested;
  adopting it at the call sites is the next step and nothing calls it yet — this project has
  shipped a "fixed" helper with zero callers more than once, so it is said plainly rather
  than implied.
- **It did not judge whether the 115 discovered sets are all scored populations.** They are
  all *checked*; whether a given one is a set a score is reported on is the caller's
  `scored_handles` argument, which is where that decision belongs.
