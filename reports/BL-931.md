Three rounds tried and each was correctly stopped by a live writer. This time the gate came back clean:


The write re-checked that hash and matched. `clip_library` now does `from provenance import DECLARED, DERIVED, MEASURED, ABSENT, READABLE` and re-declares nothing.

**Ownership verified on a non-interned object, because the obvious check is worthless here:**

```
  DECLARED  lib is owner: True   <- INTERNED, proves nothing
  DERIVED   lib is owner: True   <- INTERNED, proves nothing
  MEASURED  lib is owner: True   <- INTERNED, proves nothing
  ABSENT    lib is owner: True   <- INTERNED, proves nothing

  READABLE  lib is owner: True   <- a TUPLE, not interned: this is the real proof
  id(PV.READABLE) = 2262241535104
  id(CL.READABLE) = 2262241535104   same object

  clip_library re-declares a rung anywhere? False
```

Python interns short string literals, so `clip_library.DECLARED is provenance.DECLARED` returns `True` **whether or not the import happened**. That is exactly the false positive that nearly let BL-927 report success. `READABLE` is a tuple, is not interned, and is the same object by `id()`.

**The drift test passes because there is nothing left to disagree with**, not because two copies happen to match. Confirmed by the source check: no rung is re-declared in the file.

## 2. `_call_with_deadline` — NOT merged, and that is the finding

BL-927 listed it as *"four variants differing only in docstring prose"*. I applied BL-927's own rule — strip the docstrings, normalise the code, compare the **source**:

| | |
|---|---|
| `google_play` / `spotify` / `youtube` | **identical** |
| **`twitch`** | **DIFFERENT — and materially better** |

Twitch's carries an **abandonment ceiling** the other three lack:

```python
_ABANDONED = threading.Semaphore(24)   # ceiling on simultaneously-abandoned workers
```

On timeout the worker is a daemon thread that is *abandoned*, not killed. The other three abandon **without limit**. Twitch's reserves a slot and, once the ceiling is reached, **waits** for a straggler rather than stacking another thread. Its own docstring records why, and it is not theoretical:

> *"MEASURED FALSE on 2026-07-28: raw-site scrapes ran 153s, 214s and 215s … 51 of 108 channels abandoned a worker, ~61 threads piled up, and the run stalled dead."*

**So the correct behaviour is twitch's, and "merging" means adopting it into three finders — a deliberate behaviour change, not a de-duplication.** That needs a full-suite run, and three of the four files were held by BL-927. The analysis is recorded in `finder_common.py`; adoption is one line per finder once those claims clear.

**"Differs only in prose" is itself a hypothesis** until the docstrings are stripped and the code compared. It cost a wrong conclusion twice in two rounds.

## 5. The three method lessons

Each nearly produced a wrong conclusion in the last two rounds:

1. **Shape equality is a hypothesis; source equality is the finding.** BL-923's sweep matched AST node-type sequences and reported 16 duplicates. Two were real. The sweep is still worth running — it is a cheap net — but nothing may be merged on its output alone.

2. **An identity check on short strings is meaningless, because Python interns them.** `is` returns `True` for `"declared"` regardless of provenance. Use a non-interned object — a tuple, a list, a dict. This nearly reported an unmade conversion as done.

3. **An exit code read without checking what produced it is not a signal.** BL-927 read `exit=2` from `test_email_finder` as a failing suite; there is no such file and 2 was "file not found". Same family as the `grep -c` that read a crashed `claim.py` as zero rounds in flight.

All three are the same shape: **a proxy accepted in place of the thing it stands for.**
