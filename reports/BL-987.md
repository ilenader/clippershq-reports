## 1. Why the old numbers were wrong

BL-971 asked two questions about a whole `def` and applied both answers to every statement
inside it. Three distinct leaks, each found by hand-reading a hit:

| leak | what it did |
|---|---|
| **cost per function** | `main._execute_run` is ~600 lines and returns non-zero somewhere, so an unrelated `_l in _vlines` display loop was ranked BLOCKS-A-COMMIT |
| **provenance per function** | `dashboard/server.py::api_settings_put` names `config.json` somewhere, so `k in body` — dict membership on a **JSON request payload** — counted as a substring test over source code |
| **provenance by NAME** | a parameter called `path` seeded "this is source text", which is how `memebot/scraper/run.py::has_real_urls` — a URL list with `#` comments, returning a boolean — became the last surviving BLOCKS-A-COMMIT hit |

The third one is the one worth dwelling on. **Naming is not evidence, and this is the third
time it has bitten in this file's lineage**: BL-971 qualified on variable names and got 201
hits of data; BL-981 found the provenance test was per-function; and the first per-statement
run still ranked a URL reader as a commit-blocking guard because its parameter was spelled
`path`. A name no longer seeds provenance at all — `_PATHY` is now a regex that matches
nothing, kept only to carry the reason.

### What replaced it

**Provenance is traced, not guessed.** A value holds code/doc text only if it can be
followed to a reader within the function, then propagated through string operations,
aliasing, subscripting and `for line in <src>`. Readers are split in two, and the split is
load-bearing:

* `getsource`, `getsourcelines`, `head_text`, `_manifest_text` — **can only ever return
  source**, so they need no corroboration;
* `read`, `readlines`, `read_text` — general, so they must name a code/doc file by
  **literal**.

`.txt` came out of the code/doc extensions. It is a links list, a caption dump, an `.out`
fixture — data far more often than documentation.

**Cost comes from the statement's own consequence**: the `if` whose test it is, the
`assert` it sits in, or — the shape that was missing entirely — the assignment it flows
through.

lesson says a 0 is not a null result until the sweep finds the case it was built from, so I

```python

for word in sorted(emitted):
```

1. `getsource` takes a **function object**, not a path, so demanding a code/doc filename

`test_join_key.py:63`) land as **TURNS-SUITE-RED** — which is what BL-971 called them
before its own scoring buried them.

**Three consecutive rounds have now had to fix this sweep before trusting its output.**
The honest reading: this defect shape resists the tool built to find it, and no count it
produces should be quoted before the founding cases are re-checked.

## 5. The two lessons

### Scope is not truth

**An exemption that asks whether a statement is IN SCOPE and never whether it is TRUE will
excuse false statements indefinitely.** BL-965's manifest exemption asked "is this denial
about a path this manifest claims?" — a *relevance* condition. MEMEBOT-067's denial passed
it while being flatly false: the path it named verifies fine. The round's headline
deliverable stayed out of enforcement for as long as nobody read the sentence.

Generalised: **every exemption needs a truth condition alongside its relevance condition.**
Relevance decides whether the claim is worth checking; only truth decides whether it is
right. BL-981 added the missing half — the named path is now resolved before the exemption
is granted.

### A bare name is not an identity

`check` is defined in **23 files** at HEAD. Any symbol search must therefore be two stages:
**narrow** with `grep -w` on the name, then **resolve** each candidate through the claim's
own checker. A comment mention is dropped by the resolve stage; an unparseable candidate is
skipped, and **neither is fatal** — "I could not look" must never be recorded as "it is not
there" (BL-908). That is what makes it the same *symbol* rather than the same *string*.

## 6. Unused parameters — 43 in production, 3 that mislead a caller

`py_files` was taken by `check_superseded` from the day it shipped and never read, while
`verify()` dutifully passed the file list in. **An ignored parameter is not dead weight; it
is a false promise about what the callee does with it.**

Swept the tree, excluding the cases where accepting-and-ignoring is legitimate: `self`/`cls`,
`_`-prefixed, `*args`/`**kwargs`, interface stubs, and same-name overrides.

**246 unread parameters; 148 outside `scratch/`; 32 that a caller actually passes.** Most of
the 32 are **test doubles** — `get(timeout)`, `user_medias(count)` — where accepting a real
client's signature and ignoring most of it is the entire point. Three are production:

| site | call sites | verdict |
|---|---|---|
| `clippershq/clip_pipeline.py:296` `gate(now)` | 30 | callers pass a time the gate ignores. **BL-899's and MEMEBOT-088's file.** |
| `clippershq/main.py:949` `estimate_run_cost(ig_wells)` | 5 | free, unexamined |
| `clippershq/run.py:211` `run_headless(free_only)` | 1 | **traced in full — see below** |

`run_headless(free_only)` is the `py_files` shape exactly. `--free-only` is validated at the
CLI layer (`run.py:420-425` refuses `--cap 0` without it, and refuses it on a funnel with a
paid path), then **passed into `run_headless` and never read**. The guarantee is structural
— the flag is only accepted for funnels with no paid path at all — so this is **not a live
spend leak**. But a caller reading the signature believes `run_headless(..., free_only=True)`
constrains the run, and it does not. The safe fix is the owner's call: read it, or drop it
from the signature. Reported, not changed.
