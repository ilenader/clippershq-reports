## 4. The cause — and the brief's premise was wrong

**The run was not killed at its budget line.** Its own record says `status: completed`, and
its log says `Target met: delivered the 2,000 new leads you asked for.` It reached the master
append and executed it. So "killed before the append" cannot be the explanation, and fixing
only the cap path would have fixed nothing.

What actually happened is visible in the run's own summary:

```
Big enough to be worth it : 2,573 of 17,065 looked at
Saved to your leads       : +1,181  (30 merged)   [!] does not reconcile with 663 new
```

The run's in-memory `stats["results"]` held **2,573** passed artists. The checkpoint holds
**4,049**. `scratch/resume/spotify.jsonl` is a **shared per-funnel mailbox** — BL-1167 found
exactly this shape when two concurrent runs each reported the union of it — so the file
legitimately holds records this process never had: another run's, or its own from before a
target-met `work.clear()`. Every run only ever offered its own half, and `retire()` then
renamed the file and froze the remainder.

**The fix: the durable record gets the last word.** `control._append_checkpoint_leftovers`
runs after the normal append and offers everything contactable in the checkpoint.
`crossdedup` merges by identity, so re-offering what was just appended costs a merge and never
a duplicate — measured on the recovery itself: 2,781 offered → 810 appended, 1,971 merged.
It is wrapped so it can never fail the run it is protecting.

**A second, quieter defect fixed at the root.** `qualified_by` was stamped only at the *end*
of `run()`, onto the return value — so **no checkpoint record has ever carried it: 0 of
2,781**. `append_found_to_master` guards its routing write on that field, so recovering
straight from a checkpoint would land rows every downstream gate skips (the invisible-row
defect BL-1042 fixed, through the back door). The recovery had to restamp by hand; nothing
after this does. It is now computed once at run start and written into each record by
`_tally`.

## 5. The garbage collector could delete the only copy

`scratch/resume/` was **not** in `tools/scratch_gc.py`'s `PROTECTED` list, and `scratch/` is
that tool's entire hunting ground — everything else it protects is protected by being
somewhere else. Until a run reaches its master append, a checkpoint line exists **nowhere
else**: not in master, not in a spreadsheet, not in the ledger beyond a dollar figure. The
funnel measured 6,668 s on one pass and the GC's lifetime is 36 h, so this was reachable.

`scratch/resume` is now protected, and the guard is tested three ways in
`tests/test_scratch_gc.py`: a realistic checkpoint **planted** in the directory is refused,
the directory itself is refused, and a **retired `.done` file** is refused — because
*retired* does not mean *appended*, which is the entire lesson of this round.

Verified live:

```
protected_conflict(scratch/resume)                       -> scratch/resume
protected_conflict(spotify.jsonl.20260806-200619.done)   -> scratch/resume
```

## What I got wrong

1. **I ran `scratch/bl1173_export.py --help`.** That module has no argparse, so the flag was
   ignored and **the script simply ran** — and because it hardcodes `TODAY = date.today()` and
   `STEM = "..._FULL_DAY_1224"`, it selected today's 810 rows and wrote them over BL-1173's
   1,224-row file. The spreadsheets are gitignored, so there was nothing to restore from. I
   rebuilt that file to exactly 1,224 with its original run breakdown (1,181 + 43) before
   doing anything else. Nothing was lost, but only because the source data still existed.
2. **I assumed the brief's premise.** "Killed at its budget line before the master append" is
   not what happened — the run completed, met its target, and ran its append. Had I fixed only
   the cap-halt path I would have shipped a fix for a failure that did not occur and left the
   real one open.
3. **My first `run_resume.Checkpoint` read returned 0 records** from a 9,579-line file. I set
   `cp.path` by hand, not knowing BL-1167 had changed `records()` to glob by name and ignore
   it. The accessor had moved under me.
4. **My multi-day export driver crashed on the provenance sidecar** — `"...%r..." % TODAY`
   unpacks a tuple. Both sheets were already correct on disk; only the sidecar failed, and it
   is now written explicitly with the real multi-day rule instead of being left half-done.
