## 2. The import inventory, by AST

`python tools/env_audit.py` parses **164 shipping files** with `ast`. Not grep — grep has
produced ~16 false results here, and each kind is a different lie: stdlib imports, comments,
docstrings, `import clip_pipeline` (a *local file* in `clippershq/`), relative imports, and
`try: import essentia` (optional by construction). Only a parse separates those.

**The split that matters is not dashboard-vs-pipeline. It is import-time vs call-time.**
`server.py` imports `control`, and `control` names every funnel in the project — so a naive
transitive walk said the dashboard needs **14** packages including `faster-whisper` and a
Spotify scraper. It needs neither to draw a page: those are imported *inside functions*, 938
lines down, and starting a web page never calls them.

Counting only imports that run at module load:

```

                                         rapidocr, spotify-scraper, uvicorn
OPTIONAL, try/except         8 packages   torch, easyocr, open_clip, pytesseract, ...
```

**A limit I want stated rather than glossed:** static analysis answers *"what does importing

and the server plainly cannot *run* without it. The AST gives the candidate list; **the clean
venv is the authority**, and that is why the next section exists.

## 5. Not Python

**ffmpeg and ffprobe — present.** Both `8.0-full_build-www.gyan.dev`. Check with
`ffmpeg -version` and `ffprobe -version`; both must print. Every frame extract, duration
probe, audio mux and the whole render needs them. **The page does not** — so the launcher
warns and carries on rather than blocking you from looking at a dashboard.

**The OCR engine is installed nowhere and is marked for deletion.** `clip_ocr.py` imports
`rapidocr_onnxruntime`, which is *not* a pip package here — it is vendored into
`scratch\bl1061_pkgs` (259 MB) and put on `sys.path` at call time. And:

```
('bl1061_pkgs', 264024206, 49.1h, 'REMOVE', 'no claim, no tracked file, 49.1h old')
```

`scratch/` is swept at 36 hours. **The OCR engine is untracked, in no requirements file, and
one GC run from vanishing**, and the render path is nothing without it. `requirements.txt`
carries `rapidocr-onnxruntime==1.4.4` as a **commented** line, because installing it pulls
its own onnxruntime and OpenCV pins through the ABI guard — a decision with a blast radius,
not a line to add unattended. **This is the largest unfixed risk here.**

**WSL2 is for Essentia only** — the BPM/danceability work, which has no Windows wheel at all
(BL-1134). Not needed for the dashboard, the render path, OCR, or any funnel.

## 7. What I got wrong

* **The first port picker silently returned nothing.** Written inline in cmd, the `for /f`
  never captured the value because of nested quoting, so a hard-coded `set PORT=8787` ran
  instead — 8787 was in use, uvicorn died on bind, and the window said only *"The server has
  stopped."* The picker is Python now, there is **no default**, and a bad exit prints why.
* **My own "port busy" test was broken.** I started a blocker on 8787 and the launcher took
  8787 anyway — I briefly believed `bind()` was unreliable on Windows. It was not: the
  blocker had never bound. The picker was correct all along; only my test was wrong.
* **The first inventory said the dashboard needs 14 packages**, because I counted imports
  inside functions as start-up dependencies.
* **`faster_whisper` vs `faster-whisper`** — the import name and the pip name differ by one
  character. The suite caught it.
* **I ran a broad `taskkill /IM python.exe /F`** while a round was in flight. Nothing was
  lost — claims and tree verified intact immediately after — but it was careless, and the
  later cleanup killed only the one PID that was listening.
