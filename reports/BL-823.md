# BL-823: OPERATING.md — the operator manual, written from a verified walkthrough rather than from the code

**Date:** 2026-07-31 · **Class:** Documentation · **Spend:** **$0.00** — no paid calls, no pipeline code changed. One file written: `OPERATING.md` at the repo root (12.4 KB).

`OPERATING.md` is the document you follow in a month having forgotten everything, and the one a second person follows from scratch. It is prose, not a reference table, and every claim in it was checked against a running system rather than read out of a module.

---

## What it contains

**The daily loop as four steps.** Start the app, run at most one funnel, **press `[B]`**, send, then stamp with `[O] → [4]`. The rebuild step gets its own emphasis because BL-813 established that new leads are absent from the send file until `[b]` runs — so the manual tells the reader what `+N vs last build` means and that `+0` is the correct answer on a day with no discovery. Skipping the stamp is called out as the thing that makes every later question about reply rates unanswerable.

**Every menu option in both entry points**, described in prose with its cost and its output location. `main.py` is documented as seven paid funnels plus five free tools; `control.py` as the same capabilities reorganised, plus campaign management, the health check, and the per-funnel filter menu. The `[f]`-beats-`[5]` cap precedence is stated explicitly because it is the one piece of the settings model that is not guessable.

**Four hard prohibitions, each with its evidence.** Never send from anything but `ALL_BOT_READY.csv` (BL-786: strict superset, so a second file is a pure double-send — and the manual names the six decoy files sitting beside it, including the badly-named `LATEST_BOT_READY.csv`). Never `git reset --hard` (BL-807: seven modules). Never run `--rewrite-master` while the startup banner recommends it (BL-819: it drops 260 populated `twitch_login` values). Never leave work uncommitted (BL-816's root cause).

**The settings that matter, with current values and consequences.** Twitch viewer floor 20 / ceiling 1,000; Spotify band 50,000–3,100,000 with `run_target` 700; YouTube 50,000–5,000,000 subscribers and 2,000,000 views; Google Play 10,000 installs and a 30-day freshness window; both deep-median floors at 4,000; `clip_max_pages_per_account` 1; global `spend_cap_usd` 50 with per-funnel caps of 5 and 2.

The Spotify entry carries the finding that changes how you tune it: **the in-band seed pool is about 777 artists, and a `run_target` above that forces expansion at a measured 17-point handle-rate penalty**. So 700 is deliberately just under what the pool supports, and the manual tells the reader to add seeds rather than raise the target — which is the opposite of the instinct.

**Recovery and backups point outward rather than duplicating.** `RECOVERY.md`, `MASTER_WRITES.md` and `BACKUP_THESE_6_FILES.md` are named as the authorities on their subjects; `OPERATING.md` carries only the routing (what symptom sends you to which document) plus the two operational facts a reader needs immediately: partial runs already save, meter and resume, and the test suite needs `PYTHONUTF8=1` before a red result is believed.

The backup section states the six files, that they total ~31 MB on **one disk**, that none are in git by design, and that **OneDrive is not running** — so the correct first action is to check the tray icon, because if it is absent nothing is backed up.

**A closing section on what the system does not do**, so nobody expects it: no sending, no reply tracking beyond what you stamp, no audio genre (closed at 40% reproducibility), no mood, no drop detection. It also adds the one from BL-819 — the export can state a view count and a date but cannot link the clip, because the video id was never stored.

## Method

Both entry points were launched as real processes and their menus captured verbatim; the send list was built through the app's own free `[B]`; the settings values were read from the live `config.json` at write time; the `[o] → [4]` dry-run-and-default-to-no behaviour was verified by reading `control.py` and `outcomes.py` rather than executing, since executing it writes to the master. No paid call was made and no pipeline file was modified.

**Known staleness:** every number in §4 is the live config as of 2026-07-31 and will drift as the funnels are tuned. The manual states its own write date at the top for that reason. The startup banner it warns about is a live defect, not a documentation choice — when the `twitch_login` column question is settled, that paragraph should be deleted rather than edited.
