# BL-1043 — the clone bootstrap, and five defects it committed on its way to fixing one

BL-1026 measured a clean two-repo extract at **22 of 175 suites red** and concluded a clone
could not run this system. It is now one command. But the interesting half of this round is
not the tool — it is that **the tool written to stop "cannot run here" reading as "failing"
did exactly that to a working skip**, and three more things besides, and every one of them
was found by running it somewhere real rather than by reading it.

---

## 1. What a clone was actually missing

I ran all 22 reds individually on a pristine pre-bootstrap extract instead of trusting the
list. The result is narrower than the brief assumed:

| cause | suites | fixed by |
|---|---|---|
| **`config.json` absent** | **8** | bootstrap writes one |
| no `.git` at all (an *extract*, not a clone) | 5 | nothing — see §5 |
| `core.hooksPath` unset | 2 | bootstrap sets it |
| transient / other rounds writing the tree | 7 | nothing to fix |

**Every `FileNotFoundError` in the extract was the same one file.** Not five gitignored
paths — one. `master_leads.csv` and `clip_library/` never produced a crash, because the
suites that need them mostly skipped already.

So item 2's target turned out to be a different shape than "dies on `FileNotFoundError`".
After bootstrap **no suite dies on a missing file at all**. What was left is worse-behaved:
**vacuity guards** that assert against *real* credentials and go red when the credentials
are legitimately blank.

```python
self.assertTrue(self.leaves, "no credentials found in config to test against")
self.assertGreater(len(vals), 0, "real config should expose credential values to redact")
self.assertTrue(secrets, "no secrets to test against — the test would be vacuous")
```

Those guards are **right**. A scanner test with nothing to scan proves nothing. But on a
bootstrapped clone they are red, and that is the confusion this round exists to end.

### The skip has to be a discriminator, not an emptiness check

`if not values: skip` would skip on the operator's machine too, the moment credential
detection broke — turning a live regression green. `tests/_clone_state.py` separates three
states rather than two:

| state | verdict |
|---|---|
| blocks present, every credential unfilled | **SKIP** — a clone; nothing here to check |
| blocks present, credentials live | caller asserts, and **FAILS** if it found none |
| blocks absent entirely | caller asserts, and **FAILS** (`test_config_contract` owns that) |

Proven in both directions, which is the only way this is worth anything:

| | live tree | bootstrapped clone |
|---|---|---|
| `test_secret_scanner` | **OK**, 0 skipped, *"credential caught 72 times (8 blocks × 3 contexts × 3 profiles)"* | **OK (skipped=8)** |
| `test_secrets_guard` | **OK**, 0 skipped | **OK (skipped=2)** |
| `test_dashboard` | **OK**, 0 skipped, 99 tests | **OK (skipped=15)** |
| `test_unwalked_first` | **OK**, 0 skipped | **OK (skipped=1)** |

Every skip prints `SKIPPED, NOT PASSED`, what it did not check, and how to make it
checkable. A skip nobody can act on is only quieter than a failure, not better than one.

## 2. The five defects the tool committed

### (0) The one that mattered most: **every skip in this round was dead**

This is the headline and it was true right up until the last measurement.
`credentials_are_all_blank` used `secrets_guard.is_secret_leaf`, which matches `"auth"`.
On the **actual committed** `config.example.json` that makes two *settings* look like filled
credentials:

```
tikhub_api.auth_header  = 'Authorization'   -> read as a live credential
tikhub_api.auth_scheme  = 'Bearer'          -> read as a live credential
```

so the function returned **False**, and **not one skip fired for anyone bootstrapping from
the real committed example.** The round's entire claim was false in the one configuration
that matters.

**My clone rehearsal passed it** — because I had copied *my own regenerated* example into
the clone. The fixture was the thing I had made, not the thing a clone gets.

```
before   credentials_are_all_blank -> False
         test_secrets_guard FAILED (2)   test_dashboard FAILED (2)
after    credentials_are_all_blank -> True
         secret_scanner OK(skipped=8)  secrets_guard OK(2)
         unwalked_first OK(1)          dashboard OK(15)
```

The narrow rule already existed **twenty lines away** in the tool this module was written
beside — `bootstrap.CRED_KEY_HINTS`, deliberately without `"auth"` and `"bearer"` — and I
had written the comment explaining why the wide list is wrong for this direction, then used
the wide list anyway in the other file. One decision, two homes, and they diverged inside
one round. `_clone_state` now imports it.

**The lesson is the fixture, not the rule.** Every other test in that class is a dict I
wrote by hand, and not one of them could have caught this. The new test builds its config
from the real committed example: *a test about what a clone gets must use what a clone gets.*

## 2b. The four the tool committed earlier

### (a) It broke a working skip — the exact disease it was written to cure

`test_unwalked_first` already handled a clone correctly:

```python
if not os.path.isdir(lib):
    self.skipTest("no live clip_library")
```

`DIRS` included `clip_library`, bootstrap created it **empty**, `isdir` passed, and the
suite went on to fail on `len(walked_accounts(lib)) > 0` — **data that is in no repository
and never will be**. Empty-reads-as-present, in the tool written to close it.

Measured before changing anything: every writer calls `os.makedirs(..., exist_ok=True)` on
its own output directory (**8 sites in `clippershq/`**), and none of the extract's 22 reds
came from a missing directory. Creating them bought nothing and cost a skip. `DIRS` is now
write targets only, and the skip tests for **content**.

### (b) It listed a tracked file as unrecoverable

`CANNOT_CREATE` named `scratch/songs.json` as *"in no repository, restore from a backup"*.
It is **tracked — 36 KB at HEAD**. The table printed `present` for a file it had just
called absent. The test now asks `git ls-files` about every entry instead of trusting me.

### (c) It rewrote a curated file it should never have touched

`config.example.json` **already existed** (commit `4dda296`) — I did not need to write one,
and my regenerating it produced a **3,260-line diff** whose contents were worse in four
separate ways:

| what it did | why it is wrong |
|---|---|
| `ig_crawl_keyword: "edit"` → placeholder | `is_secret_leaf` matches **substrings** — "key" in "key**word**" |
| `tikhub_api.auth_header: "Authorization"` → placeholder | "auth" in "auth_header"; the value is a header name |
| `PASTE_CLIENT_ID_HERE` → `PASTE_KEY_HERE` | flattened placeholders that said *which* credential goes there |
| 7 live operational values copied in | a tool that copies live state into a committed public file is a leak waiting for one mis-classified key |

**The same rule is correct for redaction and wrong for generation.** Over-blanking is free
when you are hiding something and destructive when you are producing a file somebody has to
fill in. `secrets_guard.SECRET_LEAF_HINTS` is deliberately broad for the first job; this
round needed the narrower tuple `test_secret_scanner._secret_leaves` has always used.

The regenerator is gone. `audit_example()` is **read-only**: it names drifted keys
(`missing ['clip_round_robin']; stale ['ig_prescreen_on_followers_only']`) and any
credential-shaped value, and a person edits the file. `config.example.json` is **untouched
at HEAD** by this round.

### (d) It would have blocked every commit in `memebot/` — caught on the live tree

`install_hooks` pointed `memebot/` at the parent's `tools/githooks`. `pre-commit` begins:

```sh
ROOT="$(git rev-parse --show-toplevel)"
python "$ROOT/tools/verify_claims.py" --enrolling
```

From inside `memebot/` that root is **memebot**, which has no such file. Measured, not
reasoned about:

```
pre-commit exit=1
pre-push   exit=2
```

**Every memebot commit and push refused**, with ~3 rounds in flight. I set it, tested it,
and unset it inside the same minute. That is failure mode 1 of `tests/test_clone_rehearsal.py`,
which exists because this shape once blocked every commit for ~12 hours and 57 commits: **a
hook set that refuses everything is worse than no hooks.**

A repo is now wired only to hooks it owns; one with none is **reported unguarded**. Two
tests pin it — one re-runs the exit-code measurement, one reads `install_hooks` with `ast`
and fails on any `"../"` hooks path.

**`memebot/` is unguarded on this machine and I left it that way**, deliberately. Fixing it
means giving memebot its own hooks, which is somebody's round and not a config flip.

### What the 15 actually are

**More than half of what remains is the measurement instrument, not the system.** On a real

### One knob, and it is red on every clone

`test_clip_wiring::test_the_shipped_config_carries_every_knob` asserts every knob is present
in the shipped config. `config.example.json` is missing **`clip_round_robin`**, so this is
red for anybody who clones. `bootstrap --check` names it:

```
example : 161 keys, DRIFTED from the live config — missing ['clip_round_robin'];
          stale ['ig_prescreen_on_followers_only']. Edit it BY HAND
```

**The edit is one line — `"clip_round_robin": true`, the code default at
`clippershq/clip_runner.py:57`** (not a live operational value). I claimed the file to make
it, then found **BL-1050 had claimed it 3 minutes earlier alongside `config.json`, and it is
now `' M'` — dirty and mid-edit.** So I dropped it from my claim and left it alone. It is
BL-1050's to make, and it is written out above so nobody has to rediscover it.

### An archive extract is not a clone

`git archive HEAD` gives you the files and **no `.git`**. Five of the 22 reds were
git-dependent and could never pass there whatever bootstrap does. On a real
`git clone` + bootstrap, **`test_governance_rules`, `test_wip_commit`, `test_verify_claims`
and `test_ranked_runner` are all green** and all four are red in an extract.

If you want to know what someone else gets, **clone**. BL-1026's 22 conflated "a clone
cannot run this" with "an archive extract has no git", and I inherited that framing in my
own claim text before measuring it.

believe in. Restore is `tar -xzf` — **no Python, no network**, which is the point.

## 5. What I got wrong

- **I claimed `config.example.json` as a deliverable and it already existed.** I wrote 162
  keys over a curated 161-key file before checking `git log`. Reverted; the round's actual
  contribution there is the audit, not the file.
- **The blank-credential discriminator was wrong three times**, and each time it made the
  round's headline claim false rather than merely imperfect. It tested every value in a
  secret block (those blocks hold `base_url`, so it never returned True). Fixed, it
  recognised only `""` while the committed example writes `PASTE_KEY_HERE`. Fixed again, it
  still used the wide `is_secret_leaf`, so `auth_header` defeated it — see §2(0). **Three
  rounds of "fixed" on one function, and the first two survived a clone rehearsal**, because
  the rehearsal used a config I had generated rather than the one a clone gets.
- **My leak check cried wolf 29 times** — every hit a hashtag in
  `campaigns.*.default_hashtags`. Shape alone over-fires; key-name alone under-fires. Scoped
  to credential-named keys and secret blocks, and the resulting blind spot (a key parked
  under a harmless name outside every block) is **pinned by a test** rather than left to be
  discovered.
- **I filled the disk.** A `git clone --no-hardlinks` of a 3.6 GB `.git` hit *No space left
  on device* at 2.9 GB free and left a partial clone I had to remove. The scratchpad was
  then swept externally mid-round, taking a suite run and the clone with it. Recorded
  because the tree's disk trap is real and cost me two measurements.
