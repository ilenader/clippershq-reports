# BL-1197 — the presets only worked in one direction, and the wrong direction was the common one

He grades **the filter's verdict**, not the page. So "wrong call" means two opposite things,
and the sheet only had words for one of them:

| the filter did | and he says wrong call | he needs to say | the sheet offered |
|---|---|---|---|
| **PASSED** a page he does not want | | why it is **BAD** | five bad-page reasons ✓ |
| **REJECTED** a page he wants | | why it is **GOOD** | *the same five bad-page reasons* ✗ |

On a wrongly-rejected page his only options were reasons the page is bad — so defending a
page recorded a condemnation of it. **26 of his 166 marks are that case**, and it is the
largest single thing the filter gets wrong.

fixed sheet before this report was written — it reads the file from disk on every request, and
nothing changed on the server side. **Press Ctrl+R and the new buttons are there.**

## 3. The third verdict flips too, and that was the more expensive half

"Right call, wrong reason" is his own distinction and the most informative thing on the sheet.
It has a direction as well, and getting it wrong would have been **harder to catch**, because
the verdict itself still looks right:

| the filter did | he agrees with the outcome, but | the sheet now asks |
|---|---|---|
| REJECTED | for a different cause | *"which rule SHOULD have decided that?"* → the rejection rules |
| PASSED | for a different cause | *"which reason it is GOOD is the real one?"* → the good-page reasons |

Asking "which rejection rule should have fired" about a page he wants **kept** is the same
one-directional bug one level down. `SHOULD_HAVE_BEEN_PASSED` is the good list;
`SHOULD_HAVE_BEEN_REJECTED` is the rule list, unchanged.

## 4. Every mark now records which direction its reason points

Posted for real to a probe server and read back off disk:

```
a_rejected_page  BAD      REJECTED  is_meme_page       why_good
a_passed_page    BAD      PASSED    creator_page       why_bad
a_kept_page      GOOD     PASSED    dialogue_ok        why_good
```

`reason_direction` is stamped on every reason and `should_have_been_direction` on every
third-verdict pick. **Without it, `is_meme_page` on a rejected row and `creator_page` on a
passed row are both just "a reason"**, and a later round reading the file cannot tell
defending a page from condemning it. Row numbers have already collided across sheets once;
an undirected reason code is the same class of silent ambiguity, and this file is the only
ground truth the filter has.

Keys unchanged and still by **handle**: `sheet`, `key`, `handle`, `row`, `filter_verdict`,
`mark`, `reason`, `reason_code`, and now `reason_direction`. Append-only, newest-per-handle
winning. The two new fields are additive — every existing reader keeps working, and the
derived-truth axis (`passed XOR mark == BAD`) is untouched.
