# BL-1005 — the editor brief: what a human clipper actually gets per clip

The emails sell one thing — **we hire editors to cut clips** — and nothing in this repo has
ever assembled what an editor would need. Every ingredient was already stored per clip and
none of it had been put in front of a person in a form they could act on.

`python -m clippershq.editor_brief <clip_id> | --batch N | --folder DIR` now renders one
markdown page per clip from **stored fields only**. 20 tests pin the two honesty rules.
**Six defects were found by reading the output**, which is the fifth round in a row where
that was the only thing that found them.

---

## 1. The two rules the file exists to keep

**Rule 1 — a missing field says `unknown`.** Everything user-visible goes through `val()`,
so there is no second path by which a `None` becomes a blank, a zero, or a plausible guess.
`None`, `""`, `[]` and `{}` all render `unknown`; a gap must be **visible**, because a
silently-omitted line is a gap an editor cannot see.

**And a measured zero is not a gap.** `speech_frac: 0.0` on a music-only clip is a fact,
and rendering it `unknown` would be the mirror defect — hiding data that exists. It renders
`0%`.

**Rule 2 — no sentence asserts what the data cannot support.** The payoff is the dangerous
one. **Nothing in this repo has ever detected a drop**: audio detection was measured at
100% fabrication, and beat *timestamps* carry no pixel information (beat *text* is fine).
So `payoff_line()` returns the sentence **and its evidence class together** — the caller
cannot render the claim without it:

| class | when |
|---|---|
| `beat-text + duration` | beats stored, so the brief can say what the source described |
| `duration-only` | no beats; the statistical band is all there is |
| `none` | no duration either — *"there is no honest estimate. Watch it and decide."* |

Every brief carries *"This is a heuristic, not a detection"*, and the suite bans the
sentences that would break it (`the drop is at`, `payoff detected`, `guaranteed`,
`definitely`, `will go viral`).

### The statistics are derived, not quoted

`payoff_stats()` recomputes from `ground_truth/clip_drop_labels.json` at run time. Measured
here, n=28: **median payoff 7.0s, fraction 0.431**, split **0.463** on clips ≤20s and
**0.341** on clips >20s. A test asserts the module constants still match what the labels
produce, so a drifted constant fails rather than quietly shipping.

**Two correlations that are both true and are not the same thing** — exactly the shape that
produces a sentence where every number is true and the sentence is false:

* `corr(duration, drop_s absolute)` = **+0.733** — longer clips have *later* payoffs
* `corr(duration, payoff fraction)` = **−0.162** — but proportionally *earlier* ones

The brief states the second only as a **direction**. −0.162 on n=28 is not a number to lean
on, and the 0.73 in the brief I was given is the *first* quantity, not the second.

## 3. What a brief contains

```
STOP block          only when the clip is disqualified, above everything else
1. What this is     vision_scene, franchise, genre, format
2. The moment       evidence class + beat TEXT in order + the statistical band
3. Keep             the source's own burned-in text, quoted verbatim
4. Cut              7-20s target; CUT THE TAIL, never the head
5. Caption          keep the overlay, add nothing, strip nothing
6. Audio            class, speech %, track (or "ask before replacing")
7. Watch out        caption bars, letterboxing, templated, missing overlay
```

**"Cut the tail, never the head"** is not a preference. Payoffs sit early — median 7.0s
across the 28 labels — so trimming the head is what removes them. Every over-length brief
says the word TAIL.

**"Keep the source overlay exactly"** follows MEMEBOT-076's hand review: the source's own
burned-in text was the better hook on **nine of ten** clips.

`--folder` writes `<clip_id>/brief.md` **and** `<clip_id>/SOURCE.txt`. The library stores
**no local media path**, so it writes the permalink and says *"The video is NOT stored
locally by this repo"* rather than fabricating a path a person would go looking for.

## 4. Two data defects I did NOT paper over

Both are in `franchise`, and both are cases where the obvious cleanup would do more damage
than the defect.

**A `Word:` prefix.** 35 of 947 values carry one — but `Avengers:` (14 alone), `Avatar:`,
`Venom:`, `Thor:`, `Dune:`, `Furiosa:`, `Batman:`, `Predator:`, `Terminator:`,
`Madagascar:`, `Minions:` and `SAS:` are **real titles with a colon**. A `^\w+:\s` rule
would delete more real titles than labels. So `_SCRAPE_LABELS` is an **allowlist of the six
labels that actually occur** (`Fact:`, `About:`, `Credit:`, `Source:`, `Judul:`, `RARE:`),
and a test asserts the four real titles survive it.

**A URL slug.** `chief-dan-lin-theatrical-releases)` rendered as a franchise. The obvious
rule — no space, 2+ hyphens — catches it **and `Monster-in-Law`, a real film**. One garbage
value against one real title is not a filter, it is a coin toss, so **nothing is filtered**.

Measured: **945 of 947 (99.8%) plausible**, 1 slug, 3 over-long values carrying scraped
metadata blobs. And one undetectable class worth naming for whoever owns franchise
extraction: a zombie clip from the `songss` account carries **`Baby One More Time`** — a
song title where a film title belongs. Nothing in the row distinguishes that from a correct
value.

## 6. Still open, and whose

1. **`franchise` carries a song title on music-account reposts** and a URL slug on at least
   one row. Undetectable from the row; needs fixing where the field is extracted.
2. **No local media path exists anywhere in the library**, so an editor must download from
   the permalink. If briefs are ever handed out at volume, that is the next thing to build.
3. **`content_genre` is 17% filled and `vision_title` 59%** — both render `unknown` on most
   briefs. Honest, but thin.
4. **The brief is not wired to any funnel or hand-off.** It generates on demand; nothing
   assigns a clip to an editor, and nothing records that a brief was sent.
