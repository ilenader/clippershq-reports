## 2. 62,092 records — counted two ways, arithmetic shown

The file is **136,553 physical lines** and **62,092 people**. Anything that answers `wc -l`
answers the wrong question, because bios contain raw newlines inside quoted CSV values.

**Way A — the csv module**, which is the app's own reader
(`recover_ig_emails.read_master`): `csv.DictReader`, `field_size_limit(10**7)`, minus the
repeated-header guard. → **62,092 records**, 72 columns, 0 repeated header rows.

**Way B — a byte-level quote-parity scanner sharing no code with Way A**
(`scratch/bl1279_count.py::way_b`): walks the file one byte at a time tracking whether it is
inside a quoted field, honouring `""` as a literal quote, and counts a record boundary only
at a newline seen *outside* quotes. → **62,092 records**.

**The arithmetic closes exactly:**

```
   62,093  record lines (62,092 data + 1 header)
+  74,460  newlines embedded inside quoted values (bios)
= 136,553  physical lines   ==   wc -l master_leads.csv   ==   136,553   ✓
```

A detail that falls out and is worth keeping: `\r` occurs **62,093** times — exactly the
record-line count. **Record boundaries are CRLF; the 74,460 embedded newlines are bare LF.**
That is why the two counts can be separated at all.

Way A == Way B, and neither is `wc -l`. Both produced by `.venv\Scripts\python.exe` 3.11.9.
Raw output: `scratch/bl1279_count_master.json`.

## 4. It works by being dropped in, with no editing

**The path is anchored to the folder, not the working directory.** `run_spotify.py::_anchor()`
turns every relative path value in `config.json` absolute against `os.path.dirname(__file__)`
before anything runs, and `START_SPOTIFY.bat` does `cd /d "%~dp0"` first as well. Both
`INSTALL.bat` and `START_SPOTIFY.bat` reference `.venv` only as `%~dp0.venv` — relative to
themselves.

**Both required tools are present**, and they are required because they fail *silently*
when they are not: `main._repo_paths()` appends `<package>/tools` to `sys.path` and returns
`None` on any exception whatsoever, so an omitted `repo_paths.py` produces no error and no
warning — just a config whose paths were never resolved.

which is the designed behaviour, and it is what §5 exercises.

### And the guard fired on THIS REPORT, correctly

The first `tools/commit.py` attempt was **refused by the pre-commit hook**:

```

  reports/BL-1279.md   fingerprint 201ccc66dc93bed9  (lives in master_leads.csv)  ×2
```

about the author's reasoning. All 8 literals in the report are now redacted, including the

someone's address. Nothing was committed with `--no-verify`; the report was fixed and
re-staged, and the index was cleared with an explicit pathspec in between so the refused
attempt left nothing staged in the shared index.

### THE RISK, NAMED AND NOT SOLVED

**There are now two copies of one database, and from the moment the folder is handed over
they drift apart.** Anyone the colleague emails is recorded only in *his* copy; anyone this
machine emails is recorded only in *this* copy. Neither knows about the other. The finder's
dedup reads its own local file and cannot see across.

The drift is not slow. `master_leads.csv` gained rows as recently as 2026-08-14, and a single
700-artist run appends hundreds. **Within days both sides will be emailing the same people —
which is precisely the outcome this handover exists to prevent.**

Deduplicating a *find* is now solved on both machines. Deduplicating a *send* is not, and
nothing in this folder can solve it: it needs one place both of them write to when an email
goes out. That is a decision for the two of them, and this round was not asked to make it.
It is stated here, unsolved, on purpose.
