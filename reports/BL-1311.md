## 4. The reason was never captured — three independent proofs

### (a) The downloaded file already had the column empty

`~/Downloads/bl1296_his_marks.tsv` — **2,548 bytes, 2026-08-15 22:29**, sha256 `f2af4ff7f5e122a5`,
and named as `source` on all 100 rows of the `.jsonl`.

```
header:  handle \t his_verdict \t his_reason \t seq
non-empty per column:  handle 100 · his_verdict 100 · seq 100 · his_reason 0
```

101 lines, 100 data rows, **4 fields on every row, none ragged**. And **2,548 bytes across 100
rows is ~25 bytes per row** — arithmetically incapable of carrying 100 typed reasons.

**So the Python ingest faithfully carried an already-empty column. The ingest is exonerated,
and so is the merge.**

### (b) The browser's own store has it empty too

Chrome **`Profile 28`**, `Local Storage/leveldb/091032.ldb` (2,192,621 bytes), under a
`file://` origin, key **`bl1296_marks_v1`**:

```
{"seq":101,"downloadedThrough":101, … "verdict":"WANT","reason":"", …
```

**A WANT row with an empty reason, in localStorage.**

### (c) Not one non-empty reason exists anywhere in that store

| pattern | occurrences in 2.19 MB |
|---|---:|
| `"reason":""` | **2** |
| `"reason":"…"` non-empty | **0** |

⚠️ **Caveat, stated rather than buried:** leveldb compresses and delta-encodes, so a raw byte
scan cannot claim to have seen every record. What it establishes is that **every reason it can
see is empty**, and that the persisted object carries the key with an empty value.

> ### The conclusion BL-1309 can start from
> **The reason is empty at the moment of persistence.** It is not lost in the download, not in
> a merge, not in the ingest, and not hiding under another key. Of the six candidates in the
> brief, that eliminates **the download serialising a subset of fields**, **a merge dropping
> the column**, **a later write overwriting an earlier record**, and **the field written under
> a different key**. What remains is the pair the evidence points at: **the field is never read
> on save**, or **the mark object is built before the field is read**.
