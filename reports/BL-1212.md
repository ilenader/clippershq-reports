## 1. Why you saw somebody else's batch. One line, measured

`clippershq/paste_batch.py:722`, the function `/api/paste/status` calls to decide which
folder to read:

```python
return os.path.join(root, sorted(names)[-1]) if names else None
```

That sorts the folder **names**, lexicographically. Every batch this module makes is
`outputs_paste_<YYYYMMDD_HHMMSS>`, so for months the sort looked like a date sort and
behaved like one. Then BL-1209 named a batch `outputs_paste_20260810_bl1209`. In ASCII
`b` is `0x62` and every digit is `0x30` to `0x39`, so that one name outranks every timestamp
made on the same day.

**Proven, not argued.** I planted a folder called `outputs_paste_20260810_999999__PROBE`, a
stamp later than any real one that day, and asked the live function:

```
latest_batch() -> .\outputs_paste_20260810_bl1209
```

Your three presses each started a batch correctly and each made its own folder correctly:

| folder | started | what happened |
|---|---|---|
| `outputs_paste_20260810_141456` | 12:14:57Z | ran |
| `outputs_paste_20260810_171047` | 15:10:48Z | ran, **8 pairs** |
| `outputs_paste_20260810_172851` | 15:28:52Z | ran, **8 pairs** |
| `outputs_paste_20260810_bl1209` | 13:21:21Z | **what the page showed you, all three times** |

The BL-1209 batch's own counts are `total 12, done 7, refused 4, failed 1`. Your screen said
twelve links, seven finished, five skipped. Five is four refused plus one failed. That is
how the numbers matched a batch you never submitted.

**One precision, because I got it wrong first and my own test caught it.** The letter only
wins once the date matches, so a batch started on 2026-08-11 would have beaten it. The fault
would have cleared itself at midnight and come back the next time any round suffixed a batch
with a word. A fault that comes and goes gets blamed on the browser, which is exactly what
happened: you refreshed, and closed and reopened it, three times.

### The fix

`latest_batch` now orders by the batch's own `started_at`, the one field that means "when he
pressed Run", falling back to the folder mtime when a batch died before writing state. The
name is used only to break exact ties. A folder can be called anything now.

```
BEFORE  latest_batch() -> outputs_paste_20260810_bl1209     (13:21:21Z)
AFTER   latest_batch() -> outputs_paste_20260810_172851     (15:28:52Z)
```

`tests/test_bl1212_paste_identity.py::TheNewestBatchWins` plants that exact shape, and I ran
the old implementation against it side by side to confirm the test can tell the difference
rather than merely passing.

## 6. "Errors: 1" was never the whole story. The cause was on disk the entire time

**The diagnosis I was handed was wrong for this batch, and I have to say so plainly.** The
brief attributed the render failure to a 115 character label against a strip that holds 104.
The clip that failed in your last two batches carries a **52 character** label. The long line
theory does not touch it.

`edit.py` prints `Errors: 1` to stdout and nothing else, which is all this module ever
quoted. But it **also writes a dated log beside the render** and puts the real ffmpeg line
in it. Both of your failures, in two different batches:

```
2026-08-10T17:15:40  instagram/wasted  ...  edit:fail
    Error sending frames to consumers: No space left on device
2026-08-10T17:32:37  instagram/wasted  ...  edit:fail
    Task finished with error code: -28 (No space left on device)
```

Nothing had ever opened that file. Reading it costs one `open()`. The panel now says:

> *the machine ran out of disk while writing the video. Nothing is wrong with the clip: free
> some space and this one renders.*

instead of *"the edit ran but did not produce a healthy video"*. Unknown causes are quoted
verbatim rather than guessed at, so an unfamiliar failure is still a stated failure.

**And it is refused before your money is spent.** A batch now checks free space before the
song store is read, before the estimate, before any client exists, and raises `NoRoom` with
"nothing was fetched and nothing was billed". Ordering is the point: a guard that runs after
the plan is a guard a missing song can hide, which is what my first version did and what the
test caught.

### Long labels: shrunk to fit, or refused before the render

The 104 character measurement is real, it was just not this clip's problem. It is now used
