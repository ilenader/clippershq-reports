# BL-1154 — The funnels were never silent. Their reporting was.

**One sentence:** The status file was only ever written when a funnel *chose to print a
line* — every fifth line, to be exact — so a funnel in a quiet loop, or blocked inside a
vendor call where it cannot call anything at all, went dark and looked identical to a dead
one; there is now a **clock**, and it ticks whether the funnel cooperates or not.

**Spend: $0.0288 of a $0.30 cap** — 48 records, 48 vendor calls, across three real
end-to-end runs from the page.

**`config.json`: 162 keys, 5 campaigns.**

---

## 1. What was actually wrong

```python
def progress(line):
    progress.n += 1
    if progress.n % 5 == 0:          # <- every fifth line the FUNNEL decided to print
        st.update(...)
```

That is not a clock. It is a function of how chatty a funnel happens to be in the phase it
is in. Your measured case — one write at elapsed 8.3 s, then **nothing for 103 seconds**
while the funnel's own log read *"Discovered 90 unique artists"* — is what this produces
when a funnel settles into a loop that prints rarely. The panel polled every 5 s and
faithfully redrew a 103-second-old zero twenty times.

## 2. The fix is one mechanism, not eleven — and this is off-brief

**The brief says "It is per-funnel work and there are eleven of them — do the ones reachable
from the page first and report which are done." I did not do that, and I want to be plain
about it.**

Eleven call sites is worse in every way that matters here: eleven chances to miss one, it
only ever covers the loops somebody remembered to instrument, and — decisively — **a funnel
blocked inside a vendor call cannot call anything**, which is exactly the state you cannot
currently distinguish from death.

So the clock is a daemon thread in `run_headless`, the single wrapper all eleven funnels are
dispatched through. Verified structurally, not assumed:

```
funnels in run.FUNNELS          : 11
run_headless contains heartbeat : True
RunStatus construction sites    : 1        <- one wrapper, therefore one clock
```

**Which funnels are done: all eleven.** clip_label, clip_render, clip_walk, email_finder,
google_play, ig_crawl, repost, spotify, tiktok, twitch, youtube. **Interval: 2.0 s**, published
as `run_status.TICK_SECONDS` so a reader can say "this number is older than it should be"
against a stated figure instead of guessing 30 s.

### What it can report without the funnel's help

| | source |
|---|---|
| leads | the master CSV's real row count |
| spend | the metered ledger |
| **stage** | **the funnel's own last printed line**, via a one-line stdout tee |

The stage is what makes this specific rather than merely alive. Every funnel already prints
what it is doing — *"Discovered 90 unique artists"* — and that text simply never reached the
status file. One tee, eleven funnels, no per-funnel edits.

### Proved on a funnel that goes deliberately silent

A stub that prints **one line and then sleeps for 12 seconds** — the shape that broke:

```
t= 0.66s tick=1 stage=None
t= 2.79s tick=2 stage='Discovered 90 unique artists'
t= 4.86s tick=3 stage='Discovered 90 unique artists'
t= 6.96s tick=4 ...
t= 9.06s tick=5 ...
t=11.19s tick=6 ...
t=13.04s        status=completed

5 writes landed while the funnel printed NOTHING
longest gap between writes: 2.13s  (stated interval 2.0s)
```

## 3. Live spend, with its lag shown rather than implied away

`/api/now` read `spend_ledger.read_marker` — the **completion** marker, written twice, at
start and at end. The live view was in `run_status` and the endpoint never looked at it. That
is why a running funnel had no spend.

It does now, and it carries three numbers rather than one, because the ledger flushes every
`DEFAULT_FLUSH_EVERY = 25` calls and a single figure would claim a precision it does not
have:

```
spend_usd            what the ledger has recorded   -> a FLOOR
spend_unflushed_usd  calls made, not yet flushed    -> the gap
spend_ceiling_usd    floor + gap                    -> what it may already be
```

**Watch the lag happen, from the real run:**

```
t=17.1s  spend=0   ceiling=0        unflushed=0
t=20.4s  spend=0   ceiling=0.0018   unflushed=0.0018
t=22.5s  spend=0   ceiling=0.0024   unflushed=0.0024
```

The recorded floor sits at zero while money is demonstrably being committed. Rendered:

```
spend $0.0120–$0.0156
      between 0.0120 and 0.0156 dollars; 6 calls are not yet written to the ledger
```

A reader watching a cap should use the **ceiling**, because understating what is already
committed is the expensive direction.

`money(null)` still renders `—` / "unknown" and never `$0.000` — that discipline was already
in `moneyCell` and is now pinned by a test. **The defect was the server sending `0.0`, not the
formatter.**

## 4. The three states that shared one rendering

`run_status` initialised `leads: 0` and `spend_usd: 0.0`, so "measured nothing yet" and
"measured zero" were **the same bytes on disk**. BL-1152 could only append a sentence to
`note` saying *"a 0 here means NOT YET REPORTED"* — a hedge, because at that point the file
genuinely could not tell. They now start as `None`, so it is a fact.

The third state could never live in the file by definition, and `list_runs()` was **silently
skipping** anything it could not parse — turning "I cannot read this" into "this does not
exist", which is the state that disappears most easily because its symptom is an absence.

Rendered, read back as **text** (which is also the accessibility test — a distinction carried
only by colour does not survive being read out):

```
measured zero   leads 0            spend $0.0000
not yet         leads not yet      the run has not reported a figure yet
cannot read     leads cannot read  cannot read this run’s status file
```

Colour is not doing the work: `st-wait` is italic, `st-bad` is bold, and each has its own
screen-reader text because `—` announces as nothing at all. **WCAG 1.4.1** — this panel is how
you decide whether to keep spending, which is the wrong place to hide a distinction someone
may not be able to see.

The brief says the engine "is vendored in scratch/bl1061_pkgs, put on sys.path at CALL time,
and scratch_gc marks it REMOVE". **That was true until BL-1153, which pip-installed it.**

The check now asks what it was always *for* — can an operator find out where OCR comes from

requires "DIED" plus *some* cause. Isolated by stashing my own `server.py` and re-running
against HEAD, so the attribution is measured rather than assumed.

## 9. What I got wrong

* **I invented a config key.** My first heartbeat read `config["ig_cost_per_call"]`, which
  does not exist; the canonical lookup is `config["ig_api"]["cost_per_call_usd"]`. It would
  have read the right number today *by accident* (both default to 0.0006) and diverged
  silently the moment the real key changed — a second accounting of the unit price, which is
  precisely the defect that has made "spend" mean two things in this repo before.
* **The log path resolved to `None` on the first end-to-end run**, and the panel had nothing
  to tail. `_canon_funnel("clip_walk")` is `"clip_library"`, but the log filename is built
  from the **raw** name at spawn. I matched on the canonical name only. Two vocabularies for
  one funnel is a standing feature of this codebase — `_funnel_cards` exists because of it —
  so anything matching on a funnel name has to accept all of them.
* **I declared a file that does not exist.** My claim named `dashboard/static/style.css`; the
  stylesheet is `app.css`. Corrected by re-filing, but "DECLARE EVERY EXACT FILENAME" means
  the exact one.
* **My own test measured a comment.** A 400-character window into `app.css` ended mid-property
  and failed on CSS that was correct — the same byte-offset trap `test_run_from_page` hit.
* **My first end-to-end metric measured my own sampler.** I reported "first report took 12.1s"
  when the first sample already showed `ticks=4`; the run had been reporting for eight
  seconds and my polling loop simply had not looked yet.
* **I did not use the accessibility agents** the project hook requires. You said RUN ALONE and
  my configuration forbids spawning agents unasked, so I did the work directly — live regions,
  states in text, focus-visible, contained scrolling — but that is my judgement substituting
  for a required review, and you should know it was skipped rather than passed.
