# BL-981 — `superseded:` can tell a move from a removal now, and the tier that mattered is closed

The headline: **`check_superseded` had two verdicts and needed three.** It could say "gone,
as recorded" and "it came back", and it had no way to say the thing that was actually
happening — *it moved*. BL-971 measured three claims coming back green on a false
statement. That is now a distinct, named failure that points at the new home.

The second half went differently from the brief. **The DELETES-CONTENT tier is 2, not 3**
— BL-971 already fixed one of them — and **all 11 of the BLOCKS-A-COMMIT hits turned out to
be false positives of my own sweep**, for a reason worth writing down.

---

## 1. `check_superseded`: three verdicts, not two

`superseded:` exists (BL-881) for one guarantee: it **passes while the symbol is gone and
fails if it returns**, so a supersession record cannot quietly become false. It resolved
the claim against the **original path only**, so a symbol that moved to another file was
absent from where it looked and read as removed. The symbol *did* return — just not where
anyone was checking — and the guarantee broke without a word.

| state | before | now |
|---|---|---|
| absent from its path, absent everywhere | PASS | **PASS** |
| present at its path again | FAIL | **FAIL** |
| absent from its path, **alive elsewhere** | **PASS (wrong)** | **FAIL — "MOVED, not removed"** |

Measured on the case BL-971 found, MEMEBOT-069's `cdc4ec4`:

```
superseded: func scratch/mb065_clone.py::crashed by MEMEBOT-069: moved into the suite
  before : PASS  "…is absent at HEAD, as recorded"
  now    : FAIL  "…is absent from its own path but ALIVE at HEAD in
                  tests/test_clone_rehearsal.py -- this was MOVED, not removed. A move is
                  a re-point: aim the claim at its new home rather than recording a
                  removal that did not happen."
```

### A bare name is not an identity

`check` is defined in **23 files** at HEAD. So the search is two stages and the second one
is the one that decides:

1. **narrow by name** — `git grep -l -w` against the claim's own repo (nested repos
   included, via `_nested_repo_for`, with hits re-prefixed so the checker gets the path
   shape it expects);
2. **resolve by AST** — run the claim's *own checker* against each candidate path. A
   comment mentioning the name is dropped here, in the same breath `check_func` already
   uses: *"a comment mention is not a definition."*

The `py_files` parameter this function has always taken was **never used**. It is wired now.

A candidate that fails to parse is skipped, not fatal — "I could not look" must never read
as "it is not there" (BL-908). That is asserted, not assumed: a fixture makes the first
candidate raise and checks the search continues and still finds the real home.

### Both directions, on each

Per item 3, and because a refuse-only test stays green through an outage (BL-963's guard
crashed on its allow path and nothing noticed):

| test | asserts |
|---|---|
| `test_a_MOVED_symbol_FAILS_and_names_its_new_home` | the new verdict fires **and** names `tests/test_clone_rehearsal.py` |
| `test_the_ALLOW_path_still_passes_for_a_genuine_removal` | a real removal is **still green** — the kind is not broken |
| `test_it_FAILS_if_the_symbol_comes_back` | the original guarantee is intact |
| `test_a_bare_NAME_is_not_an_identity` | 23-file name resolves through the AST, origin never self-reports |
| `test_a_name_that_is_only_MENTIONED_is_not_found` | prose is not a home |
| `test_the_search_does_not_abort_on_one_unreadable_candidate` | one bad blob does not end the search |

**Regression check: 44 committed manifests, 1 live `superseded:` claim, 0 red.** The
stricter rule did not turn anything red that was green.

## 2. DELETES-CONTENT — 2, not 3, and both are closed

The brief asked for three. One of the three, `tests/test_config_contract.py`, **was already
fixed by BL-971 last round**; my sweep JSON was stale when the brief was written. Of the
remaining two, one is a disposable `scratch/` probe that `run_all.py` excludes by design.

**The real one is the manifest header check — the guard that started all of this** — and
it had a hole left. BL-965 scoped a denial to its paragraph and required it to name a
genuinely unclaimed path. **MEMEBOT-075 found what that still misses: being out of SCOPE is
not the same as being TRUE.**

MEMEBOT-067's header said a nested-repo path "can never verify". Both of BL-965's
conditions held, so it was excused — and the statement was simply false: `verify_claims`
resolves nested repos through `_nested_repo_for`, so that path verifies like any other. The
round had withheld its headline deliverable from enforcement over a limitation that no
longer existed, and the suite could not see it because the exemption only ever asked about
scope.

**Third condition added: the named path is now RESOLVED.** If it is tracked at HEAD, the
denial is wrong on its face and the manifest is flagged rather than excused.

Both directions again:

* `test_a_denial_about_a_path_that_DOES_verify_is_flagged` — names `tools/verify_claims.py`,
  which resolves; **flagged**.
* `test_a_denial_about_a_path_that_genuinely_cannot_resolve_is_still_exempt` — names a path
  that does not exist; **still exempt**, because a true caveat is not a lie.

And the fixture that encoded the false premise is **inverted rather than deleted**:
`test_the_memebot_067_shape_is_NOT_exempt_because_the_caveat_was_FALSE`. BL-965 wrote it
asserting the opposite. The wrong version is the part worth remembering, so it stays in the
file as the thing that changed, and it skips **loudly** if the path stops resolving.

## 3. BLOCKS-A-COMMIT — all 11 are my sweep's false positives

Read one at a time, **none of the 11 is a text-deciding guard over source code.** Two
defects in BL-971's sweep, and they are the same mistake twice: *attributing a property of
one line to the whole container.*

1. **Cost is computed per FUNCTION.** `main._execute_run` is ~600 lines and returns
   non-zero somewhere, so an unrelated `_l in _vlines` display loop inherited
   BLOCKS-A-COMMIT.
2. **Provenance is also per function.** A function that names `config.json` anywhere
   qualified as reading source text — so `dashboard/server.py::api_settings_put` counted
   twice over, where `k in body` is dict membership on a **JSON request payload** and
   `name in src` is dict membership on a **config dict**
   (`src = (cfg.get(block) or {})`). Neither is a substring test over code.

| verdict | n |
|---|---|
| FALSE POSITIVE of the sweep | 5 |
| disposable `scratch/` probe | 5 |
| **already correct** — `tools/repo_guard.py::sweep` | 1 |

`repo_guard.sweep` resolves by **lexical context** rather than AST — it tracks
triple-quoted blocks, keeps a skip-list for files that document the patterns on purpose,
and strips backtick-quoted spans before scanning. BL-971's binary `resolves_too` flag
cannot see that. It remains the pattern the rest should copy.

**The DELETES-CONTENT tier was accurate** because those are small, focused test functions
where the `def` really is the guard. The tiering is trustworthy exactly where the unit
matches.

### Deferred, and saying so

**TURNS-SUITE-RED (33, 27 with no AST), MISREPORTS (23) and WARNS (11) are not touched and
are not claimed to be clean.** A false positive there costs a triage, not deleted work.
They need the same statement-level re-classification before their count means anything —

## 5. The two sweep lessons, both self-caught

**A sweep looking for text-matching guards will match its own subject matter.** BL-971's
first run returned **201 hits**, mostly data — `src.startswith(` in `twitch_finder._tally`
is a *source funnel name*, not source code. It qualified functions by the **name** of the
variable they tested. Requiring provenance cut it to 67. **And it was still wrong**: this
round found the provenance test is itself per-function, which is how a JSON payload got
classified as source text. Two rounds, two versions, still leaking — the honest reading is
that this shape resists exactly the tool built to find it, and every count it produces
needs hand-reading before it is quoted.

**A sweep returning 0 is not a null result until it finds its own founding case.** BL-971's
ordering sweep returned 0 and 0 was wrong: it was blind until it stopped requiring the
cleanup to assign to the name it read, and then followed a bare alias (`entity = name`).
Both fixes came from building a fixture out of the known bug, not from trusting a clean
run.

## 6. The ordering sweep is CLOSED, not deferred

70 pairs → 48 distinct sites → 16 in production, **all read by hand, 0 live bugs.** 14 were
container variables (`row`, `r`, `author`) or the module `re`; 1 was a gate that already
normalises internally; 1 was correct by design. One latent case-sensitivity remains in
`market_filter.rejection_is_strong` — a case-**sensitive** prefix dispatch in front of
case-insensitive value handling, reachable only if a prefix is ever produced non-lowercase,
which nothing does today.

**That is a clean negative and should be recorded as closed rather than re-swept.** The
BL-965 ordering bug was found by *reading rendered output*, not by this sweep, and the
sweep needed two fixes before it could see even that one.
