# BL-778: The dead-knob population at source — 83 invisible knobs, 11 unread keys (one BL-775 missed), 32 orphan functions, and a startup assertion that would end the class

**Date:** 2026-07-31 · **Class:** Audit · **Spend:** **$0.00** — no paid calls, no changes, nothing written to the project tree. Static AST analysis of `clippershq/` (60 modules), `tests/` (51 files, 989 test functions) and the live `config.json`.

**Nothing was implemented.** Every recommendation below is a proposal.

## 0. Reconciling with BL-775's 89

BL-775 reported 89 keys read-but-absent. My first sweep said 131, then 113. The gap was mine, twice, and both corrections matter because they change which keys are real:

1. **Receiver over-capture.** I initially accepted `.get("k", d)` on any config-ish variable, including `c` and `base`. In `repost_finder` those are *payload* dicts — `c.get("height")`, `c.get("followers")` are media fields, not knobs. Restricting to `cfg` / `config` / `eff` / `conf` / `settings` dropped 18 false keys.
2. **Nested config sections.** `config.json` is not flat: it has 15 nested sections (`repost_finder`, `caption_finder`, `twitch_finder`, `youtube_finder`, `gp_finder`, `spotify_finder`, `ig_api`, `youtube_api`, …). Counting only top-level + campaign keys made 18 genuinely-present keys look absent — `account_consistency_min`, `pages_per_tag`, `run_target`, `max_run_usd` and others all live inside sections. **Total keys visible anywhere in config.json: 334, not 245.**

After both corrections:

| population | count |
|---|---|
| distinct keys read via a config receiver | 338 |
| keys visible anywhere in `config.json` | 334 |
| **read but ABSENT from config** | **95** |
| — of those, read **with an explicit code default** (BL-775's shape) | **83** |
| — of those, read with **no default at all** (silently `None`) | **12** |
| **load-bearing** (value enters a comparison/branch at its read site) | **65 of 83** |

83 against BL-775's 89 is the same finding measured slightly differently. **The 12 with no default are the more dangerous subgroup and BL-775 did not separate them** — `cfg.get("clip_noneditor_cats")` returns `None`, and every downstream `for x in None` or `x in None` is a latent crash or a silently-empty rule, with no default to fall back on.

989 test functions scanned. 216 are named after a known config key or function; **65 never reference their own subject in their body.**

I am reporting that 65 with a caveat, because my matcher accepts substrings and most of those hits are its noise, not real mislabelling — `test_recency_filters_old_posts` matched the function `filter`, `test_role_inbox_shared_does_NOT_merge` matched `_merge`. Those tests are fine.

## 5. The structural fix — a startup assertion, and why it must be two-sided

The class recurs because nothing ever compares the two sides. A single check at load time closes it:

```
validate_config(cfg, read_keys, documented_defaults):
    A. every key in config.json is read by something          -> else FAIL "orphan key"
    B. every key read by code exists in config OR is in the
       documented-defaults table                              -> else FAIL "invisible knob"
    C. every key read with NO default is in config            -> else FAIL "no fallback"
```

Making it practical:

1. **Build the read-set statically, not at runtime.** A runtime hook only sees keys on paths that execute; a build-time AST pass over `clippershq/` sees all 338. Ship it as a test (`test_config_contract.py`) so it runs in the existing suite and fails red.
2. **Introduce an explicit defaults table.** `DEFAULTS = {"clip_fetch_timeout": 8.0, …}` with a one-line comment each. Then `cfg.get(k, DEFAULTS[k])` and rule B becomes checkable — a key must be in `config.json` *or* in `DEFAULTS`, never invented at the call site. This alone converts the 83 from invisible to documented.
3. **Fail loudly, allowlist deliberately.** A small `KNOWN_UNUSED` set with a reason string per entry, so retiring a feature is a visible edit rather than a silent orphan.
4. **Extend the rule to functions.** The repo already has the scanner; promote `scan_dead_knobs.py` PASS 3 to a test that fails when a *public* function gains zero production callers, with an explicit `PUBLIC_API` allowlist.
5. **Name-tests-after-subjects.** A test named `test_<config_key>` must reference that key in its body — a five-line check that would have caught both `test_ig_niche_check` and `test_tt_deep_check`.

Ordering by value: **(2) then (1)** removes the 83-key population and prevents new ones; **(3)** makes deletion of the 11 safe; **(5)** is nearly free and closes the "looks covered" illusion; **(4)** is the widest net and the most likely to produce false positives, so it should come last with a generous allowlist.

## Method and limits

AST parse of every module in `clippershq/` and `tests/`, plus literal-text search for key names; `config.json` flattened to all nesting depths (334 keys). Receiver set for a "config read" is `cfg`/`config`/`eff`/`conf`/`settings` — a deliberate narrowing after over-capture, and it will miss config reached under another local name. Load-bearing is judged from the single line of the read, so a value stored now and compared later reads as not-load-bearing; **65 is a floor, not a ceiling.** The keep/surface/delete split is rule-based (infra-pattern vs threshold-pattern) and reviewed, not individually hand-audited across all 83. Uncalled-function figures are the repo's own scanner, re-run today, not re-derived. Nothing was executed against live APIs and no file in the project tree was modified.
