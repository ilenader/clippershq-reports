## 3. The blank field was mostly a mirage, and that is the finding

I targeted 711 clips (26.0%) with no pixel text. **Then the writes did nothing**, and the
reason reframes the item:

```
ocr_gate_text ABSENT   -- never read              : 2,203 (80.7%)
ocr_gate_text PRESENT but EMPTY -- read, no text  :    16  (0.6%)
ocr_gate_text PRESENT with text                   :   512 (18.7%)

of the 711 targeted:  699 genuinely never read (98.3%),  12 already read and empty (1.7%)
```

**All 9 clips with free local media were among the 12 already-read** — the pathological subset.
`merge_append` GAP-FILLS: a field that is present-and-empty **is not a gap**, so an incoming
`rev=1` row cannot outrank it and the write is a **silent no-op** — the exact 45-row failure
`merge_append`'s own docstring documents. Only `correct=True` could overwrite, and the brief
forbids it **correctly**: `''` is a real measurement, not an absence.

### So I proved the write path instead, offline, on a copy

```
clip 2471409311694698413_175633544   ocr_gate_text ABSENT
  before rev=2  ocr=None   ->   after rev=3  ocr='PRIMECUTTV MOVIE SERIES'
  GAP-FILL WORKED: True
  caption/account/posted_at PRESERVED: True        <- the SHARD TRAP stayed closed

clip 3364979048672720226_22505356    ocr_gate_text PRESENT but EMPTY
  before rev=7 ocr=''      ->   after rev=8 ocr=''
  SILENT NO-OP CONFIRMED: True   (the rev moved, the value did not)
```

**The tool is correct and the field is 699 clips from finished.** What stopped it was not the
mechanism — it was §5.

## 5. What I got wrong, and it cost the round's headline deliverable

**`clip_pipeline.default_fetchers()` returns a TUPLE `(fetch_page, http_get)`, not a dict.** My
sweep subscripted it with strings, so all 307 retrievals raised `TypeError` **inside** the try
block, before the network. I had charged the attempt **before** the try, then metered all 307
in one batch at the end.

**307 paid calls were recorded for calls that never happened. The tell was in my own output and
I nearly published it: retrieval p50 0.00 s.** A real IG page fetch cannot return in zero time.

**It could not be reversed.** `record_aux_spend(ig_calls=-307)` writes a row but clamps the
count to zero — correctly; a money ledger should not take negative calls from a caller. The
compensating row `bl1118_ocr_backfill_REVERSAL` exists at 0 calls / $0.00 so the attempt is
visible, and it nets nothing. **I did not hand-edit `spend.json`.**

**And I did not re-spend to recover.** The declared cap was $0.20; $0.19955 is already recorded
against it, and pushing the recorded total to $0.399 to work around my own bug is not a trade a
round should take. **The paid stage did not run, and that is why the field is still 699 clips
short.** Recorded in `docs/CORRECTIONS.md` so a future round can void the row.

Two fixes are in `scratch/bl1118_sweep.py` for whoever runs it: unpack the tuple positionally
and assert both are callable, and **charge inside the call, not before it**.
