## 1. Subtitles — wired, and proven on live payloads for $0

`clip_record` now fetches the `.srt` when the payload carries a `video_subtitles_uri` and a
fetcher is injected. Proven end to end against **real media dicts from the saved probe

| carrying `video_subtitles_uri` | **37 (22.7%)** — the library's stored rate is 20.4% |
| **fetched OK** | **37 of 37** |
| dead / expired | **0** |
| cost | **$0.00** — the URI is in a payload already paid for and the `.srt` GET is unbilled |

Real dialogue, verbatim from three of them:

> *"Hi, so I have you down for the total brozillion wax… It was either that or the butt
> reynolds."*
> *"Watermelon. Best prank ever. You're going to be so wet…"*
> *"Who am I saying hello to? I can tell you for damn sure who's not here and that's Rachel."*

**Free at walk time and only at walk time.** The URI expires like every other CDN link, so
fetched retroactively this costs a paid call per clip to re-fetch the manifest. That asymmetry
is the whole argument for doing it inside the walk rather than in a backfill script, and it is
why `subtitle_text` sat at 0 of 617 while 126 clips advertised a track.

The fetcher is **injected**, so a walk with no `http_get` makes no network call of its own and
stores `subtitle_text = None` — tests and the dry harness stay offline. A dead `.srt` costs
that clip its text and nothing else.

## 3. The ~30 discarded DECLARED fields now reach storage

`caption_parser` computed 21 fields and storage kept 1; `content_genre` computed 13 and kept 3.
This is **DECLARED metadata** — the accounts wrote it in their own captions, the highest-trust
tier the schema has — computed on every clip and thrown away one layer later.

**CLIP_FIELDS 32 → 60.** On a single templated caption, readable fields went **from a handful
to 29**:

| field | tier | value |
|---|---|---|
| `title` | declared | `Two and a Half Men` |
| `created_by` | declared | `['Chuck Lorre']` |
| `genre` | declared | `['Comedy', 'Sitcom']` |
| `cast` | declared | `['Charlie Sheen', 'Jon Cryer']` |
| `storyline` / `summary` / `where_to_watch` | declared | populated |
| `genre_declared` | declared | `['comedy', 'sitcom']` |
| `genre_conflict` / `medium_conflict` | derived | `False` |
| `is_templated` | derived | `True` |

`content_medium` — the field BL-836 shipped as a deliberately-empty column — is in the list.
It was never unbuilt; the value was computed and discarded before it reached storage.

**Why it happened, and why it will not recur.** Every stored field needed its own keyword
argument, so adding one meant editing a signature, a call site and a column list: fields cheap
to compute were expensive to plumb. `build_record` now takes the analyzers' **whole result
dicts** (`caption_fields`, `genre_fields`), so storing a new analyzer field is a one-line
change to `CLIP_FIELDS`. Explicit keyword arguments still win over the analyzer's copy.

The conflict flags matter for the reason BL-703 built them: a page that declares "Comedy" over
a horror scene is a different kind of page, and the disagreement is itself the signal. Both
flags were computed and dropped.

## 4. The nine valued-but-unattributed keys

`caption_parser` omits provenance for `is_templated`, `caption_chars`, `valence_score`,
`valence_evidence`; `content_genre` omits it for `content_genre_source`,
`content_medium_source`, `genre_conflict`, `medium_conflict`, `genre_declared_raw`. Exactly
nine. `field()` was behaving correctly the whole time — a key with no provenance entry reads
as None, which is the contract. The values simply had no attribution.

Each analyzer's **own** provenance is propagated rather than re-invented, because
`caption_parser` already knows `title` is declared and this module has no business
second-guessing it. The nine unattributed ones default to **DERIVED**, which is what they are:
our code worked them out; the account did not state them. All nine now read through `field()`.

## 5. The latent tier bug — fixed before the audio work lands

`put()` stored the caller's tier verbatim on a non-empty value. Two call sites passed `ABSENT`
explicitly (`arousal_audio`, `affect_conflict`) and were harmless **only because the value was
also None**, so the empty-value downgrade masked them. The day an arousal detector produced a
number, it would have been stored with tier `absent` and **every consumer would have read
None** — silently, for all of it, with the value sitting in the JSON next to the attribution
hiding it.

Two changes: the call sites now pass the tier the value *will* have (`MEASURED`, `DERIVED`),
and `put()` **raises** if anyone reintroduces absent-plus-a-value.

```
arousal_audio 0.87  -> tier 'measured', field() 0.87      (was: unreadable)
affect_conflict True -> tier 'derived',  field() True
left None            -> tier 'absent'                     (correct downgrade, unchanged)
```

The guard is hard for **direct callers**, where absent-plus-a-value is a bug in code. The
analyzer pass-through **repairs** it instead, because there it is a mismatch in data and a run
must not die of stale attribution.

**The test that would have caught it** asserts the invariant across a fully-populated record:
no field may hold a value while attributed `absent`. It fails the moment anyone reintroduces
the state that makes `field()` hide real data.

## Honest limits

- **No live walk.** `run_id` on real rows, and the subtitle fill rate against the *library*
  rather than against probe payloads, both need a paid run. The wiring is proven; the
  production numbers are not yet.
- **The same-clip subtitle-vs-OCR comparison was not made** — zero overlap between the
  subtitled clips and the clips whose video is local, and closing that costs a paid call.
- **The 37/37 fetch rate is survivorship-flattered.** Those URIs were captured ~2 days ago and
  happened to still be inside the ~105h window. A backfill over older clips would find a much
  worse rate, which is the argument for fetching at walk time, not evidence that fetching
  always works.
- **The 22.7% carry rate is from 163 medias across a handful of accounts**, and BL-798 measured
  subtitle availability to be strongly account-concentrated — 45 of 66 accounts have none.
- **Fill rates for the newly-stored fields are from BL-838's audit (755 clips), not re-measured
  here.** What this round proves is that the fields now reach storage attributed; how often
  they are populated across the whole library will only be known after the next walk.
- **`content_medium_source` reads absent on the sample clip** — correctly, because no medium was
  declared in that caption. It is wired, not populated.
