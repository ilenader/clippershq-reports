## 4. The numbering race — why CONVENTION.md cannot fix it, and what can

Three collisions happened *after* CONVENTION.md was written. I hit two more producing the last two reports: BL-772 and BL-773 were both taken between reading the ceiling and pushing, and BL-773 collided a second time mid-rebase. `git log` confirms `reports/BL-773.md` carries **two independent commits**.

**And it happened once more while this report was being written.** `BL-776` was claimed between my ceiling read and my push — the sixth collision in the corpus and the third I have personally hit today. This document is published as `BL-777` for that reason.

**The reason is structural and CONVENTION.md cannot address it.** The rule is:

> read the highest ID from `origin/main`, add one, write that path

That is a **read-then-write with no lock**, across two projects and N concurrent agents. Every proposed patch — a claim file, a reservation, a bigger gap between numbers — is still read-then-write and still races. The window is small; the number of writers is not.

### The fix: stop deriving the filename from shared mutable state

```
<PROJECT>-<YYYYMMDD>-<slug>.md
```

```
reports/LG-20260731-send-path-audit.md
reports/PAY-20260731-payout-retry-ledger.md
```

**Why this makes collision structurally impossible rather than merely unlikely:** the filename is computed from facts the author already holds — which project, today's date, what the report is about. **No remote read is involved**, so there is no window to race in. Two agents collide only by choosing the same slug, on the same day, in the same project — which means they wrote the same report, and that is a duplicate worth catching, not a numbering accident.

It also fixes the thing the brief actually cares about: `LG-` vs `PAY-` puts the split in the filename, so a reader never opens a payments report expecting lead-gen.

**Migration, deliberately cheap:**
1. **Leave all 258 existing files exactly as they are.** Every link in every report keeps working. `MANIFEST.tsv` supplies the project split retroactively.
2. New reports use the new scheme.
3. `BL-NNN` becomes a closed historical range.

**If you would rather keep `BL-NNN`:** the minimum viable change is one line in the convention — *derive the ID, then `git push` immediately, and on rejection take a new ID rather than rebasing onto the same path*. That does not remove the race; it just makes the loser cheap. I would not recommend it over the dated scheme.

## Honest limits

- **Classification is a keyword scorer plus 11 hand reads, not 258 hand reads.** The 165/92 split is only as good as the stack markers; a report about neither codebase would be misfiled, and I hand-checked only the low-confidence tail.
- **The supersession map covers the five chains I could prove with a quote.** There are almost certainly more — BL-764 alone cites six prior reports. I did not attempt an exhaustive supersession graph, and an unlisted report is not thereby current.
- **I did not verify the payments-side reports' contents at all**, only that they belong to that project. Their own superseded chains are unmapped.
- **`MANIFEST.tsv` is generated and will drift** the moment a report is added without regenerating it. That is a real maintenance cost the dated-filename scheme would reduce but not remove.
- BL-775's counts were re-derived independently, not audited line by line; where we differ I have shown the reasoning rather than assuming either is right.
