## 1. REFUSAL IS THE DEFAULT

`render(strict=True)` had refused a half-filled message correctly since BL-961. It was
**opt-in**, so BL-1091 rendered 60 of 60 messages carrying `[[SENDER_NAME]]` without a single
error. **A guard nobody switches on is a guard nobody has.**

Now the safe behaviour is what you get by typing the obvious thing, and the escape hatch is
named for what it bypasses:

| | before | now |
|---|---|---|
| API | `render(row)` → half-filled message | `render(row)` → **`ValueError`**, naming the fields and the file |
| API override | `strict=True` to be safe | **`allow_placeholders=True`** to be unsafe |
| CLI | `--strict` to be safe | **`--allow-placeholders`** to be unsafe |
| existing callers | — | `strict=` still honoured and still wins, both ways |

**Measured by exit code from the real command, never by reading output:**

```
no identity file at all          exit 2   REFUSED
the UNEDITED example             exit 2   REFUSED
a FILLED copy                    exit 0   accepted
--allow-placeholders override    exit 0   printed, labelled NOT sendable
```

The refusal now says what to do, not just what is wrong:

```
REFUSED: <the row's address> still has 5 unfilled placeholder(s):
         SENDER_NAME, RATE, TURNAROUND, PAYMENT_TERMS, REPLY_TO
Fill them in send_identity.json, then re-run.
Start from send_identity.example.json — copy it, fill every value, keep it out of git.
To preview the copy anyway (NOT sendable): --allow-placeholders
```

(The real command prints the row's actual address — it runs in the operator's own terminal.
It is elided here because this report is public and the secret scanner rejects anything
address-shaped, fingerprint or not. It is right to.)

### The two call sites where the new default would have been a disaster

`render()` refusing by default silently breaks anything that renders rows *to analyse them*.
Two such callers exist and both count `ValueError` as a refusal:

- **`ladder_markdown()`** and **`coverage()`** — with an unfilled identity file every row
  would have raised, been tallied as REFUSED, and **turned the coverage split into
  0 / 0 / 0 / 0 / 2,970**, reporting the operator's missing terms as a renderer failure on the
  whole file. Both now pass `allow_placeholders=True` with a comment saying why.

That is item 5's answer: the split is **1,110 / 462 / 1,387 / 11 / 0, delta +0**, verified
through `coverage()` and `--ladder` — the two paths that would have moved.

## 2. THE EXAMPLE SHIPS EMPTY

`send_identity.example.json` — committed; `send_identity.json` stays gitignored.

**All 7 operator fields ship as `""`.** A prior example shipped with prose values, and prose
is a non-empty string: it **passes** the placeholder check, so the copy goes out describing
itself. An empty example is refused loudly; a plausible one is not refused at all.

Guidance lives in `_`-prefixed keys, which `load_identity` already drops as comments — so the
explanation sits inside the file being edited without ever becoming a value:

```json
"RATE": "",
"_RATE": "What you pay an editor, in the unit you will honour. e.g. 'USD 40 per finished short'."
```

`tests/test_send_identity.py` (**12 tests**) asserts every field is present **and** empty, that
each has a guidance line, and that the unedited example is refused at exit 2 while a filled
temp copy is accepted at exit 0. The live identity file is never touched.

### One name, one constant

`load_identity`'s error told the operator to copy **`send_identity.json.example`**; the file is
**`send_identity.example.json`**. The name was written by hand in three messages. It is now
`IDENTITY_EXAMPLE`, used everywhere. An instruction that sends someone looking for a file that
does not exist is worse than no instruction.

## 4. THE INSTRUMENT IS SHOWN ABLE TO FAIL

Every count above is preceded by an assertion that the check can fire. The plant does double
duty — it proves the detector works **and** reproduces the exact hole BL-1091 fell into:

```
PLANT: an address on beamz.ae  ->  classify(exclude=True)     <- caught
       the same address, mx_table={}  ->  exclude=False       <- the hole
```

That second line is the whole lesson. `classify()` defaults `mx_table` to `{}`, `mx_status()`
then answers `"unknown"` for everything, and the dead-MX exclusion **cannot fire** — so
"0 excluded" is structurally guaranteed on any input. It is now asserted in the permanent
suite, not just in a scratch script:

- `test_the_suppressed_check_can_actually_fail` plants a known-dead address in a live-looking
  file, requires the guard to catch it, then requires the guard to go quiet once removed.
- `test_this_test_can_actually_fail` proves `unfilled()` still detects a placeholder — without
  it, every refusal test would pass vacuously and "filled" would look identical to "empty".
- The refusal matrix asserts refused and accepted produce **different** exit codes, so the
  expectations cannot all be satisfied by a command that always exits 0.
- **The suite was run unpiped**, `> log 2>&1`. BL-1091 piped it through `tail` and got tail's
  exit code — reporting 0 while the suite had failed.

## THE BLAST RADIUS OF THE NEW DEFAULT — ONE SUITE, MINE, FIXED

Inverting `render()` broke `tests/test_message_template.py` outright: **45 of its call sites
render a row to READ the copy** — greetings, articles, funnel leakage, agency phrasing — on
rows that deliberately carry no operator terms. Under the new default every one raised.

That is the correct signal, and it is the whole reason the change is worth making: it found
every place in the tree that produces a message without supplying terms. All of them were
analysis; none was a send path.

Fixed with **one** documented wrapper at the top of the test module rather than 45 scattered
edits, so the reason is stated once:

```python
def render(row, operator=None, **kw):
    """`mt.render` for tests that READ the copy — never a send path."""
    kw.setdefault("allow_placeholders", True)
    return mt.render(row, operator, **kw)
```

`strict=` still wins, so the cases asserting the refusal itself are untouched. **95 tests, OK.**

## Method / limits

**`strict=` was kept, not removed.** Every existing caller passing it keeps its exact meaning
and wins over the new default. Removing it would have been a cleaner API and a worse change —
it would break callers in other rounds' working trees that I cannot see.

**The CLI renders permissively and refuses itself.** `main()` calls
`render(..., allow_placeholders=True)` and then decides, because a bare traceback carries no
exit-code contract and cannot name the row. The refusal happens before anything is printed for
that row, so a half-filled message never reaches the terminal it would be copied from.

**Quarantine is a directory convention, not an enforcement mechanism.** Nothing stops an
operator opening `output/quarantine/DIRECT_SEND.csv`. What the test now guarantees is narrower
and worth stating exactly: **no file outside quarantine offers a suppressed address**, so a
stale export cannot sit in the sendable directory unnoticed again.

**`output/` already had `_archive_stale_2026-07-31/` (17 CSVs), `PILOT_20_BL-1023/` and
`bl1081/`.** My first version of the scan used `os.walk` and pulled 98 unclassified and 82
suppressed addresses out of directories that were archived precisely so nobody would send them.
The scan is top level plus quarantine, deliberately — those other directories have never been
in scope and this round did not put them in scope.
