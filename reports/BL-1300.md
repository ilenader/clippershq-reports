## 1. THE BUILD, SCOPED BEFORE A LINE WAS WRITTEN — AND THE SCOPE CHANGED THE SHAPE

The plan is committed at `scratch/bl1300_plan.md`, written before any code. Its first finding
overturned the brief's framing, so it goes first here too.

### The brief said "wiring a judging stage in is the real work". It is the one thing this must not do.

Priced before building, `.venv` 3.11.9, on the 5,263 pages a 1,000-wanted run walks:

```
vendor saving from the reorder         $5.67
a PAID vision judge on those pages   $215.43      <- 38x the saving
a FREE Claude sub-agent judge          $0.00, 45.0 M subscription tokens
```

**Put a paid judge inside the funnel and the reorder costs 38 times what it saves.** The judge has
to stay free, and the free judge is a Claude sub-agent, which **cannot be called from inside an
unattended Python process**. So `run_funnel` taking no judge argument is not an oversight to
correct — it is where the free judge lives.

**The correct reorder is therefore: let the funnel CONSUME a verdict the judge has already
written, and skip the purchase for pages it rejected.** Capture and judge stay outside, free,
where they already are. That is the whole saving, because the saving was never in the judging.

### What moved out of `scratch/`

`scratch/bl1257_capture.py` (321 lines) → **`clippershq/page_capture.py`** (260 lines). Every
measured constant and every comment explaining what it cost to learn came over verbatim — the
2,200-tall viewport, the dismissal that must never remove a node containing grid links, the
failed-capture check, the full-page crop in page coordinates.

Three things had to change, and only three:

| change | why |
|---|---|
| `os.chdir(ROOT)` at import — **removed** | a module a funnel imports may not move the process's working directory. This is the single change that made promotion more than a copy. |
| `argparse` / `main()` / `lane()` threading — **left behind** | the shipping surface is `capture_one()` plus the constants; a runner is a caller's business |
| `from playwright.sync_api import ...` — **made lazy** | the funnel imports this module whether or not judge-first is on, so a box with no browser must still be able to import it. `open_browser()` is the only thing that needs it, and it names `clippershq/pipguard.py` when it is missing rather than telling anyone to install bare |

### What `run_funnel` needed

**One keyword: `page_verdicts=None`.**

* `None` → **today's order, byte for byte.** No behaviour change and no risk to any live round.
* a `{handle: verdict}` map → a page whose verdict is `REJECT` is recorded and `continue`d
  **immediately above `profile_and_contact`**, the only unconditional purchase in the loop.

Plus `load_page_verdicts(path)`, which reads JSONL, a JSON array, a one-record file or a plain
handle→verdict map.

### Proving the caller exists — the pattern this project keeps repeating

`profile_and_contact` sat unwired for four rounds. `tiktok_send_list.build()` had no caller.
**`clippershq/triage.py` has none today** — verified again this round — so even its measured 5.3%
is not running. **A stage that is not called is not shipped.**

`run.py:116` already registers `meme_pages → meme_finder.run_funnel` with a **fixed four-argument
dispatch**, so the switch could not be a new parameter on the caller. It is a config key
(`meme_finder.page_verdicts_path`) that `run_funnel` reads for itself, exactly as
`top_text_budget` already does. **No caller changes and the live one keeps working.**
`TheCallerExists` asserts the registry entry resolves to the function, that the function reads the
key, that the camera is in `clippershq/` and not `scratch/`, that importing it does not chdir, and
that Playwright is not imported at module scope. Five tests, because five things can each silently
un-ship this.

### What could break — named before building, and all four handled

1. **`judge_page` uses all six paid fields and did not move.** Under judge-first it runs, unchanged,
   on every page that gets bought. **Rejected pages get no rule verdict at all.** That is the real,
   permanent cost of this change and it is not recoverable afterwards.
2. **Bookkeeping.** A skipped page is still written to the seen-set (`batch[h]`) and the checkpoint
   (`ck.record`) through the *same two writers* every other page uses. Skip without recording and
   the page is re-discovered and re-captured on every future run forever — the money saved would
   come back as wall clock.
3. **Counters.** `stats["judge_first_skipped"]` is new; `rejected` still increments, so the funnel
   does not silently under-report.
4. **No early-discard gate was added, and a test forbids one.** More in §3.

## 2. THE SAFETY WAS ALREADY MEASURED — CONFIRMED, NOT REDONE

BL-1287 §5 ran the same 24 pages twice, both arms free, batched 8 per agent, $0.00:

| | result |
|---|---|
| the two arms agreed | **22 of 24 = 91.7%** [74.2, 97.7] |
| with the paid fields | 20/24 = 83.3% |
| without them | **20/24 = 83.3%** |
| confusion matrices | **identical** — WANT 7/2, REJECT 2/13 |
| McNemar discordant pairs | **1 and 1** |
| paid fields ever named in a reason | `bio` ×3, `category` ×1; **`followers`, `media_count`, `full_name`, `verified` named ZERO times** |

**And the reason that gap is an upper bound rather than a live dependency: the shipped free judge
never receives those fields at all.** The batch builder carries the handle, the picture, a
follower string and the tiles. The "without" arm *is* production.

**I did not re-run this.** It is measured, it is recent, and re-running it would spend tokens to
learn nothing.

### What happens to `judge_page` under the reorder — stated plainly

`judge_page` (`meme_finder.py:1294`, 552 lines) genuinely reads `media_count`, `bio`, `category`,
`handle`, `full_name` and `verified`. **It does not move and it is not weakened.** Every page that
survives the picture judge still buys the full profile and still goes through the rule filter with
all six fields present.

What changes is its **population**: it used to see every walked page, and now it sees only the
~19% the picture judge wanted. Three consequences, all real:

* **No rule verdict on rejected pages.** "Which rule rejected this page?" becomes unanswerable for
  81% of pages. Today it is answerable for all of them.
* **`meme_share` is no longer computed on rejects**, so any future analysis of *why* rejects were
  rejected loses its main quantitative field.
* **The rule filter can no longer catch a page the picture judge wrongly wanted** — it still can,
  because it runs after. It can no longer *rescue* a page the picture judge wrongly rejected.

`JudgePageDidNotMove` pins both halves: that all six fields are still passed, and that
`judge_page` is still called *after* `profile_and_contact`.

## 3. THE FINDING THAT CORRECTED THE THEORY — CARRIED, AND ENFORCED IN CODE

TikTok's 62-day freshness gate was credited with making TikTok cheap. BL-1291 measured it:

| | with the gate | without |
|---|---:|---:|
| **$ per 1,000 wanted** | **$1.94** | **$1.94 — identical** |
| million tokens | 17.29 | 17.97 |
| **wanted pages destroyed** | **34 of 84 = 40.5%** [30.6, 51.2] | — |

It buys **3.9% of tokens** and costs **40.5% of the pages he wants**. Wanted and rejected pages are
**the same age** — medians 10.5 days against 10.4. The want rate *falls* through it, 0.344 → 0.312.

**TikTok is cheap because its want rate is high and because it buys the profile last. Money is
saved by buying LATE, not by discarding early** — now evidenced from both directions: BL-1284 from
the buying side, BL-1291 from the discarding side.

**So no early-discard gate was added, and one cannot be added quietly.**
`TheOnlyThingThatSkipsIsAVerdict` asserts the skip condition is exactly
`page_verdicts.get(h) == 'REJECT'` — a verdict a judge actually wrote about that page — and scans
the 800 characters around it for `follower`, `taken_at`, `create_time`, `days_since` and
`media_count <`, failing on any of them with BL-1291's numbers in the message.

**Absence is never a rejection.** A handle missing from the map, or carrying `UNSURE`, is bought
exactly as it is today. An absent verdict file degrades to today's order. A **torn** verdict file
**raises** — because `{}` because there is no file and `{}` because the JSON was half-written are
the same value and not the same fact.

## 4. THREE DEFECTS THIS ROUND'S OWN GUARDS CAUGHT — ALL IN CODE I WROTE TODAY

**Every one was found by an existing guard within minutes of being written. Recording them
because a round that reports only its successes teaches nothing.**

### 4.1 The format sniff that would have disabled judge-first on every real input

The first cut of `load_page_verdicts` sniffed with `raw.lstrip().startswith("{")` — and **a JSONL
file's first character is `{`**. Every real input was routed into the single-object branch and came
back as `{"verdict": "WANT"}`: a map keyed by the word *verdict*, matching no handle, which at the
call site reads as an ordinary "no rejections" and **silently buys everything**.

Caught by `test_jsonl_is_read`, because the fixture was a real `.jsonl` file rather than a dict.
The reader now sniffs **by parsing**.

### 4.2 A missing verdict file returned `{}` — the benign zero with its sign flipped

`tests/test_silent_zero_shape.py` — the ratchet — flagged `load_page_verdicts` the same hour, and
it was right. The harm is not that a page gets killed; it is the opposite. **An operator who sets
`page_verdicts_path` believes rejected pages are no longer being bought.** If a missing file
returned `{}`, every one of them *would* be bought, the entire saving would quietly not happen,
and nothing would say so. Not a wrong answer — **an unnoticed non-event**, which is worse, because
nobody goes looking for one.

Now: **unset → today's order; configured but absent → `FileNotFoundError` naming the path and the
two ways out.**

### 4.3 A sentinel that collided with a real value

Fixing 4.2 meant restructuring the sniff, and the obvious `except ValueError: doc = None` is both
the silent-zero shape *and* wrong: **`json.loads("null")` returns `None`**, so a None-sentinel
cannot tell "this is JSONL" from "this file parsed to null". Replaced with a unique module-level
sentinel object. The guard pushed me into fixing a latent bug it was not looking for.

### And a fourth, in the config contract

`tests/test_config_contract.py` RULE B went red: `page_verdicts_path` was read with no default and
not documented. **A knob nobody can discover is a knob nobody turns on** — the same family as the
zero-caller pattern. It is now documented in `clippershq/config_defaults.py` with what it points
at, what it costs, and the fact that unset is today's order.

falsifiable after the fact.

### On the wall clock — it got worse, and that is the honest reading

717.6 seconds for 24 pages, 29.9 s/page, against a normal ~1 s. **All of it is HikerAPI's 500/502
backoff, none of it is the reorder.** The reorder cannot improve wall clock: the same pages are
captured and the same pages are judged. **It has been mis-sold as a speed win twice. It is not
one, and this batch does not make it one.**
