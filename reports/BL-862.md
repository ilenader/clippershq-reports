## 3. Item 6a — the `set_run_id()` call that did nothing, removed

BL-851 measured that `run_id` never reaches a clip row. This round removed the call that pretended
otherwise, at what was `control.py:2490`:

```python
import writer as _wr; _wr.set_run_id(_wr.new_run_id("clip_library"))   # BL-843
```

**Three independent checks, all agreeing it was inert:**

1. None of `clip_runner` / `clip_library` / `clip_walk` / `clip_speech` imports `writer` at all.
2. BL-851's real 54-minute walk appended 1,366 clip rows and **0 master rows** (`"leads": 0` in its
   run-status file).
3. The same walk's 1,369 new library rows carried a `run_id` on exactly **0** of them.

`run_id` is a master-CSV column: declared in `writer.FULL_COLUMNS`, stamped by
`writer._stamp_run_id()` as a row is appended to `master_leads.csv`. That is the only place it is
ever read. The clip walk writes no master row, so the line set a module global that nothing in its
code path consumed.

It was also **actively harmful in headless mode**: `run.py:203` sets the operator's `--run-id` on
the writer before calling the funnel, and this line overwrote it a moment later.

The line is replaced by a 20-line comment recording all three checks and saying **do not restore
this** — the gap is real but it closes in `clip_library.py` (`run_id` in `CLIP_FIELDS` plus a stamp
in `append()`), not by setting a global in the caller. Removing a dead call and leaving nothing
behind is how it gets helpfully re-added in six weeks.

`clip_library.py` is held by BL-849 and BL-854, which is why this round removed rather than added —
the option the operator chose when asked.

### An observation this turned up, not fixed

The four surviving `set_run_id()` calls (`email_finder`, `twitch_finder`, `spotify_finder`,
`youtube_finder`) have the same overwrite behaviour and those funnels **do** write master rows. So
`python -m clippershq.run --funnel spotify --run-id MY-ID` stamps rows with
`spotify_finder-<ts>-<pid>`, not `MY-ID`. The operator's `--run-id` is silently discarded on every
headless run of all five lead funnels. Out of scope here and not touched; flagged for whoever owns
run attribution.

pool, before the view floor takes its cut. BL-851 had to route around it with a scratch config to
reach 2,000 at all.

5 is not a guess. BL-851 ran a full 189-account walk at exactly this value and measured:

  accounts on page 1, so the ceiling is rarely approached

- corpus ceiling lifts 2,268 → 11,340 gross

**This is a different knob from BL-854's `max_pages=2`, and conflating them would be an error.**

catalogue. `clip_vision.DEFAULT_MAX_PAGES` is how deep *`retrieve()`* pages a live feed to fetch
one clip's media for rendering. BL-854's "keep 2" is about the second; it is untouched here, and
BL-861 set it correctly.
