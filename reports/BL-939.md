## 3. The proxy rule — `PRECONDITIONS` §10

The most useful generalisation this session produced, with all eight instances in one table:

| the proxy | stood in for | what it waved through |
|---|---|---|
| an **interned string** (`is` on `"declared"`) | identity | an unmade conversion read as done |
| a **docstring diff** | a code diff | a merge that would have deleted a thread ceiling |
| an **AST shape** | a duplicate | 26 of 28 candidates were not duplicates |
| an **empty stdout** | "nothing found" | a crashed `claim.py` read as zero rounds in flight |
| a **commit message** | a blob | the wrong commit named as having swept work |
| a **claim** | a file's real state | released ≠ committed ≠ unstaged |
| **`str.count("import ")`** | an assertion | a *comment* about an import broke the build |
| **`os.path.exists`** | committed | a tool one `git clean` from gone, four times |

The test it gives a round: *what exactly does this measure, and what am I concluding from it?* Two different sentences means a proxy. Then: **what does it do when the thing is absent?** — because absence is where all of them fail. An empty list, a zero count and a `True` from interning are indistinguishable from success.

The fix is nearly always to measure the thing itself: AST not substring, `id()` on a non-interned object not `is` on a string, exit code not output, `git ls-tree HEAD` not `os.path.exists`, source comparison not shape.
