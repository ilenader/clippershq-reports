## 2. Rank 1 — the credential path: three guards, three numbers

The repo stops a credential at three moments, and each moment invented its own length.

```
tools/wip_commit.py:47     CRED_SHAPE  ...['"][^'"]{12,}      commit time
clippershq/secrets_guard.py:55,103   SECRET_MIN_LEN / NEEDLE_MIN_LEN = 16   log-emit time
scratch/scan_report_for_secrets.py   RUN_MIN = 24                            publish time
```

**Measured on the real `config.json`** (`scratch/bl932_sweep.py`; the script prints counts and lengths only and never a value):

```
credential-block string leaves by length band
  <12   (below every floor)           6
  12-15 (scanner YES / redactor NO)   4
  >=16  (both)                       14

secret_values() returns 8 needle(s); shortest=30 longest=73
```

**The live exposure today is zero, and I will say that plainly**: all 8 real keys are ≥ 30 characters, comfortably clear of 12, 16 and 24 alike. The four values in the 12–15 band are `auth_header`, `key_env_var` and friends — env-var *names* and header *names*, not secrets. Rank 1 is a **structural** finding, not a live leak.

What makes it rank 1 anyway is the direction of the next mistake. The publish gate now demands 24; the log redactor stops at 16; the commit guard fires at 12. A future key shorter than any of these — a short-lived session token, a numeric account id used as a bearer — is caught by a different subset of the three depending only on its length, and **no test compares the three numbers to each other**.

### The dead branch inside `secrets_guard`

```python
for k, v in blk.items():
    if not isinstance(v, str) or len(v) < NEEDLE_MIN_LEN:   # 16 — PRE-FILTER
        continue
    ...
    if is_secret_leaf(k) or len(v) >= SECRET_MIN_LEN:        # 16 — RULE
        out.add(v)
```

`SECRET_MIN_LEN` is only ever evaluated on values that already cleared `NEEDLE_MIN_LEN`. The effective rule is `max(16, SECRET_MIN_LEN)` — lowering `SECRET_MIN_LEN` to 12 to catch a shorter key changes **nothing**, and the edit looks like it worked.

The `is_secret_leaf(k)` branch is half-dead for the same reason: **5 credential-*named* leaves are dropped by the pre-filter before the rule ever sees them**, and **0 of 5 match any `_PATTERNS` shape**, so nothing backstops them. On this config all five are harmless routing strings. On the next config, one of them is a short key.

Two tests apply the threshold a *third* time — `tests/test_dashboard.py:59` and `:110` filter `secret_values()` output by `len(s) >= SECRET_MIN_LEN`, redundantly, on a list already filtered at 16. **A test that re-applies the threshold it is testing cannot notice the threshold moved.**

## 3. Rank 2 — `speech_frac == 0.20` contradicts itself, and the guard is exempted from seeing it

The numbers agree. The **operators** do not:

```python
clip_speech.py:264   talking = speech_frac >  SPEECH_PRESENT_MIN   # strict
clip_library.py:583  fmt = FORMAT_MUSIC if speech_frac < SPEECH_MUSIC_MAX else FORMAT_DIALOGUE
```

Called rather than compared (`scratch/bl932_sweep.py` §A):

```
frac       audio_class          format          agree?
0.199      music-only           music-first     yes
0.1999999  music-only           music-first     yes
0.2        music-only           dialogue-first  *** NO ***
0.2000001  dialogue-over-music  dialogue-first  yes
0.201      dialogue-over-music  dialogue-first  yes
```

**This is reachable, and I measured how often**: of **3,453** library rows carrying `speech_frac`, **2 sit exactly on 0.20** (0.058%). Both currently store `audio_class: None` — the field postdates them — so the contradiction is **latent, not yet materialised**. The next `build_record` on a 0.20 clip writes `audio_class=music-only` and `format=dialogue-first` into the same record, and the treatment router reads `audio_class` while the mood/format map reads `format`.

**Why the existing test passes.** `tests/test_clip_speech.py:196` is aimed squarely at this hazard and still misses it:

```python
def test_the_two_thresholds_agree(self):
    """...Two different numbers for one question is how the 0.05 gate survived
    unnoticed next to a sane 0.30."""
    self.assertEqual(CS.SPEECH_PRESENT_MIN, CL.SPEECH_MUSIC_MAX)
```

It compares the **constants**. The constants are equal. The decision is not.

**Why the AST guard cannot help either.** `test_speech_frac_is_not_compared_against_a_threshold_outside_the_labeller` walks every module for a magnitude comparison on `speech_frac` — and opens with `allowed = {"clip_library.py", "clip_speech.py"}`. It exempts **exactly the two files that hold the two thresholds**. The guard is doing its stated job (stopping BL-742's gate returning in a third module); it is structurally incapable of being the thing that catches this pair. This is the *"a guard that hardcodes what it checks cannot detect drift"* shape again.

## 4. The related shape — a bound checked in one place, consumed in another

**`clip_vision.DEFAULT_MAX_PAGES = 2` is still consumed as a reachability limit by the module whose own header says it is not one.** BL-925 fixed the estimator's *axis* (count by views, not by date) and wrote the lesson at the top of the file:

> `DEFAULT_MAX_PAGES = 2  # a waste ceiling on dead clips, not a coverage dial`

but `should_skip` 150 lines below still does:

```python
pages = estimated_pages(clip, newer_by_account)
if pages > max_pages:
    return True, SKIP_UNREACHABLE % max_pages     # "unreachable_within_%d_pages"
```

The reason it is *safe today* is a coincidence, not a coupling: the actual retrieval budget is a **separate bare literal** in another module — `clip_pipeline.retrieve_video(..., max_pages=2)` and `run(..., max_pages=2)`. Two `2`s in two files with no reference between them. Raise retrieval to 4 for deep clips and vision keeps discarding clips estimated at 3–4 pages that retrieval would now reach. Lower it to 1 and vision selects clips retrieval cannot get, paying for the walk and returning nothing.

**`MAX_ATTEMPTS` vs `VISION_MAX_ATTEMPTS`, both in `clip_vision.py`** (2 and 3) are genuinely different quantities — attempts *across runs* before a clip is abandoned, and retries *within* one call. They are not a bug. They are a naming hazard: `SKIP_FAILED = "vision_failed_%dx" % MAX_ATTEMPTS` renders `vision_failed_2x` for a clip whose last call may have made 3 HTTP attempts, so the recorded reason understates the calls bought by up to 50%.

**`DEFAULT_MAX_PAGES` at 10 and at 2** in `clip_walk` and `clip_vision` are likewise different quantities (catalogue walk per account; retrieval depth per clip) wearing one name. Nothing imports the wrong one today. `from clip_walk import DEFAULT_MAX_PAGES` in a vision caller would be silent and 5× wrong.

## 5. The structural fix — copy MEMEBOT-056's `RUN_MIN` pattern

**One constant per decision, referenced by both sides, with a test asserting no second literal exists.** MEMEBOT-056 did this and its own comment is the specification:

> The single floor for "an unbroken run long enough to be a credential". Used BOTH by the candidate regex and by `_looks_like_credential`, so the two can never drift apart again.

Proposed, in rank order — **none of this is implemented; this round changed no shipping file**:

1. **`CREDENTIAL_MIN_LEN`, owned by `secrets_guard`.** `wip_commit.CRED_SHAPE` builds its `{n,}` from it by interpolation rather than typing `12`; `scan_report_for_secrets` imports it as it already imports `SECRET_BLOCKS`. Delete `SECRET_MIN_LEN` outright — it is the dead half of pair #3, and the pre-filter is the real rule. Test: no `.py` under `clippershq/`, `tools/` or the scanner contains a second numeric literal in a credential-length position.
2. **One predicate, not one number, for "is anyone talking".** Export `clip_speech.is_talking(speech_frac)` and have `clip_library.build_record` call it instead of comparing. That makes the operator part of the shared answer, which the equal-constants test cannot cover. Replace `test_the_two_thresholds_agree` with a sweep across the boundary asserting `audio_class` and `format` never disagree — the check in §3 above, which is nine lines.
3. **`RETRIEVAL_MAX_PAGES`, owned by `clip_pipeline`,** imported by `clip_vision.should_skip`. Kill both bare `max_pages=2` defaults. Test: `clip_vision`'s skip threshold **is** the retrieval budget object, not a number equal to it.
4. **Rename, don't renumber:** `clip_walk.WALK_MAX_PAGES_PER_ACCOUNT` and `clip_vision.RETRIEVAL_WASTE_CEILING_PAGES`; `clip_vision.MAX_LABEL_ATTEMPTS` and `VISION_HTTP_RETRIES`. A name collision between two real quantities is not fixed by making the numbers agree.
5. **Name the 12** in `quality_gate.py:1088` as `LANG_DETECT_MIN_LETTERS` and have `market_filter`'s comment cite the constant. Pair #8 *should* disagree; the fix is to make the disagreement referenced rather than remembered.

## 6. The measurement lesson worth carrying

MEMEBOT-056 tested whether case-transition rate separates CamelCase identifiers from credentials. **It does not** — CamelCase 0.38–0.45, real keys 0.30–0.41, fully overlapping. Digit presence does: 5 of 5 keys carry digits, 0 of 3 CamelCase names do.

The transferable rule: **a discriminator that looks obvious should be measured before it is trusted**, and the measurement that matters is *range overlap*, not whether the means differ.

This round hit the same shape twice. Both times the obvious-looking check was the wrong one:

- **comparing two constants for equality looked like a threshold-agreement test.** It is not. It tests the numbers and misses the operators, and §3 shows a pair that passes it while disagreeing on live data.
- **"same value ⇒ same decision" is false**, and **"different value ⇒ a bug" is also false** — pair #8 disagrees 12 vs 120 and is correct. Neither the equality nor the inequality is the signal. *Whether one side can move without the other* is the signal.

Corollary for anyone repeating this sweep: **grep finds the pairs, calling the code decides them.** Every finding above that survived came from executing both predicates over a boundary; every candidate that died came from reading two numbers and assuming.
