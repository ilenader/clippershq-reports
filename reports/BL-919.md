## 1. The merge — and which one won

`tools/claims_read.py` wins and becomes the single implementation:

- it has the **production caller** — `tests/run_all.py:203`, which already handles its `None` correctly (`"registry unreadable"` vs `"N round(s) in flight"`)
- it had **the better idea first**: *"no rounds in flight" and "could not read the registry" are the same integer and must never be the same answer*

`stillness.py` now delegates and **keeps no second copy**. What it had before was a fallback that re-read the directory itself — and that fallback **was** a second implementation. A reasonable-looking fallback is how three treatment maps and two ledger writers started.

The import stays defensive, because `claims_read.py` is itself a live edit target. But the failure mode changed:

| before | now |
|---|---|
| import fails → silently fall back to a second reader | import fails → **returns a reason that BLOCKS**, naming the import error |

That is BL-908's loud-failure rule rather than a duplicate. Unavailable-to-read and nobody-working stay distinguishable, which is the entire point of the merge.

## Honest limits

- **The merge is a delegation, not a single file.** `claims_read.py` holds the claims logic; `stillness.py` holds fingerprints, the verdict and `poll()`. That is one implementation per question, which is what was asked — but it is still two files, and a reader looking for "the stillness module" will find both.
- **`--poll`'s still-tree proof is a constructed tree, not the real one.** The mechanism is demonstrated; whether the real tree ever satisfies it is unchanged, and the standing constraint says it will not without the operator.
- **Nine overlapping pairs are reported and unfixed.** Only the `claim.py`/`claims_read.py` pair is documented as deliberate. The `caption_parser`/`clip_library` divergence is live today and the other eight are latent.
- **The sweep only finds pairs sharing NAMES.** Two modules solving one problem with different names — the three treatment maps, the two loop runners — would not appear. It is a lower bound on duplication, not a census.
- **I did not run the full suite.** 13 rounds are in flight; four prior reports established that an aggregate number under those conditions cannot be interpreted. The six suites this round touches were run individually.
- **`run_checked` now has exactly one caller.** If rank 2 (`test_clip_media_audio.py`, held by MEMEBOT-047) is ever fixed, it gets a second. One caller is enough to stop it being decoration; it is not yet a widely-adopted convention.
