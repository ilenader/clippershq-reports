### The credential gate, and why it took three passes

The first scan **blocked the commit** — 8 files flagged. It was wrong, and the way it was
wrong is worth recording.

| pass | rule | result |
|---|---|---|
| 1 | any key whose NAME matches `key\|secret\|token\|access\|auth` | 8 files flagged — **false** |
| 2 | resolve each hit to its config key path | every hit was an ordinary string inside a secret-bearing block |
| 3 | only values whose **leaf key** is a credential name | **CLEAN — 0 of 8 credential values in any file** |

The false positives were `ig_api.field_map.follower_count` (a field name),
`ig_api.medias_endpoint` (a path), `youtube_api.base_url` (a public URL),
`spotify_finder.seeds` (public playlist URLs). A blocklist keyed on the *parent* block
cannot tell a secret from a setting that lives beside one; only the leaf key can.

The 8 real credential leaves — `api.key`, `gemini_api.key`, `ig_api.key`,
`openrouter_api.key`, `tikhub_api.key`, `twitch_api.client_id`, `twitch_api.client_secret`,
`youtube_api.key` — appear in **no** committed file. No value was printed at any point.

## Honest limits

- **Nothing was pushed.** 47 commits, including these 7, exist only on this disk. The remote
  is private and 15 days stale. This is the single largest remaining risk and it is one
  command away.
- **Three files were deliberately left uncommitted**: `clippershq/outcomes.py`,
  `clippershq/control.py` and `tests/test_outcomes.py`. A concurrent agent was writing
  `outcomes.py` **0.7 minutes** before I checked, and touched the other two during the round.
  Committing a file mid-edit captures a half-finished state; they are that agent's to commit.
- The fresh-clone test ran from `git archive HEAD`, which is the committed tree — not a real
  `git clone` from the remote. Since nothing has been pushed, a real clone from `origin`
  today would be **47 commits behind** everything measured here.
- `config.example.json` is generated from the live config, so it inherits any key that is
  currently mis-set. It guarantees completeness, not correctness of the values.
- The credential scan checks for **verbatim** occurrences of current values. A key that was
  rotated after being written into a file would not be caught by it.
