## 3. `tests/test_suites_parse.py` — the new guard

Every module under `tests/`, `clippershq/` and `tools/` must parse.

**Why it is worth a file.** A suite that cannot be parsed does not fail loudly — and if it is a *guard*, whatever it guards is silently unguarded. **The specific mistake, twice in three rounds by two different rounds** — prose appended *after* a module docstring's closing quotes:

```python
MORE PROSE THAT IS NOW CODE          # SyntaxError
"""
```

BL-923 did it and repaired it; BL-929 did it to the same file. It is easy to hit because the edit looks like editing a comment and is in fact editing an expression.

Six tests, including two plants — the orphaned-docstring shape, and a real unparseable file written into `tests/` and confirmed detected. It found **zero** unparseable modules at the time of writing, which is the correct answer today and the point is that it will not be silent tomorrow.

## 4. Two method rules, recorded beside the code that produced them

In `finder_common.py`, not in a document nobody opens while editing:

1. **An identity check on short strings is meaningless.** Python interns short literals, so `a.DECLARED is b.DECLARED` is `True` whether or not one module imported the other. BL-927 nearly reported an unmade conversion as done on exactly that. Prove ownership on a **non-interned object** — a tuple — and confirm with `id()`.

2. **"Differs only in prose" is a hypothesis** until the docstrings are stripped and the source compared. `_call_with_deadline` was reported as prose-only; stripped and normalised, three were identical and twitch's carried a bound the others lacked.

**Both are the same shape as everything else this project keeps paying for: a PROXY accepted in place of the thing it stands for.** An interned string proxies for identity; a docstring diff for a code diff; an AST shape for a duplicate; an empty stdout for "nothing found". None of them are the thing.
