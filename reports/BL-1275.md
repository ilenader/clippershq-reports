# BL-1275 — one judged page burns 65,296 subscription tokens, and 95.2% of it is overhead

**Measured live today, $0.00 of vendor spend** — the claim never listed `spend.json`, so
spending would have required re-filing first. Every number below was produced by
`.venv\Scripts\python.exe` (3.11.9) by full path; `python` on PATH is 3.13, lacks the
project's packages, and produced nothing here.

**The answer, and it is not the answer anyone expected:**

| | tokens | share |
|---|---:|---:|
| **agent floor** — system prompt, tool definitions, the task prompt | **48,173.7** | **73.8%** |
| the brief (28,282 chars, re-read every page) | 12,068.3 | 18.5% |
| the reference card | 1,888.3 | 2.9% |
| **image + reasoning + output — the actual work** | **3,165.7** | **4.8%** |
| **TOTAL PER JUDGED PAGE** | **65,296.0** | 100% |

**The largest single component is not the brief and not the screenshot. It is the agent
harness itself — 48,174 tokens before this round's work begins, four times the brief and
fifteen times the per-page work.**

And **65,296 is essentially the old 66,439** — down 1.7%. The caching, capture-floor and
brief work since then moved the *paid* path. It could not move this one, because none of it
touches the 95.2%.

---

## 1. How it was measured

A single full-judge agent returns one number and no decomposition. So: **four control arms,
each adding exactly one thing to the one before it, differenced.** Three replicates each,
twelve agents, **each in its own output directory** — a shared scratchpad is a recorded
hazard.

The instrument is `subagent_tokens`, reported by the harness in each agent's completion
notification. That is a measurement of what the plan actually paid, not a token-counter
approximation of a prompt I assembled myself.

| arm | what it does | mean | min | max | spread |
|---|---|---:|---:|---:|---:|
| **Z** | run one trivial command, reply | **48,173.7** | 48,173 | 48,175 | 0.004% |
| **A** | Z + read the judging brief in full | **60,242.0** | 60,239 | 60,246 | 0.01% |
| **B** | A + read the reference card image | **62,130.3** | 62,129 | 62,131 | 0.003% |
| **C** | B + read a page sheet, judge it, write the verdict | **65,296.0** | 64,754 | 65,756 | 1.5% |

The three fixed arms are reproducible to within 0.01% — which is what makes the differencing
trustworthy. Only arm C varies, and it varies by 1.5%, because only arm C thinks.

**The arm-C agents also judged correctly.** All three verdicts (`alwayslowqmemes`,
`bqwrzerd`, `harrisonsmyth4`) match the verdicts those same pages received in the earlier
free-path run. I measured a working judge, not a broken one.

## 2. Where it is going

### The paid path's shape does NOT hold here

On the paid API the brief (8,178) and the reference card (1,722) are ~9,900 of a 10,510-token
prompt — so the brief *is* the dominant fixed cost there, and the screenshot is 5.1% of the
bill. That shape is real and it is the wrong intuition for this path.

Here the brief is only **18.5%**, not because it got smaller but because it sits on top of a
48,174-token floor **the API path never pays at all**. The total prompt is **6.2× the paid
path's**, and nearly all of that difference is harness.

The one thing that holds on both: **the screenshot was never the bill.** 5.1% on the paid
path, **615 tokens = 0.9%** here.

### The image sizes actually in use, measured off disk

`tokens = width × height / 750`, validated against the figures in circulation — 467×467 → 291
exactly, 560×560 → 418 against 419 quoted.

| what | pixels | tokens | files |
|---|---|---:|---:|
| **TikTok contact sheet — what the TikTok judge reads** | **465×992** | **615** | 168 |
| Instagram operating point | 560×560 | 418 | 66 |
| Instagram legibility floor | 467×467 | 291 | 66 |
| the reference card | 1202×1074 | **1,721** | 1 |

So the size actually in use for TikTok is **neither** 1,844 nor 419 nor 291 — it is **615**.
And the reference card measures 1,721, confirming the 1,722 on record. *(The Instagram shots
directory holds a whole rung ladder — 374/467/560/700/934 — because the capture writes every
rung; 560 is the operating point.)*

### The fixed overhead cannot be cached away, and here is what that costs

Prefix caching is an **API feature**: `cache_control` is a request field and no sub-agent
exposes the request. Per-page context reset is also exactly the property that makes each
judgement independent, so it is not a defect to be removed.

**62,130.3 tokens are re-sent in full on every single page.** Over 1,000 judged pages that is
**62,130,300 tokens of overhead against 3,165,700 tokens of work — 19.6 to 1.**

### What is not observable here, stated rather than estimated

`subagent_tokens` is one total. **No sub-agent exposes a reasoning count**, so the
visible-vs-reasoning split cannot be measured on this path. What is known is a *paid-path*
measurement: visible JSON never exceeded 602 tokens across 19 replies while reasoning reached
1,502, and reasoning was 49.3% of the paid bill at 2.47× the entire input.

But the bound here is decisive regardless: **the entire image + reasoning + output block is
3,165.7 tokens, 4.8% of the page.** Even if reasoning were *all* of it, it could not exceed
4.8%. On the subscription path, reasoning is arithmetically too small to be the problem.

## 4. What would cut it — one lever, and it is not any of the obvious ones

| lever | share it attacks | measured cost | verdict |
|---|---:|---|---|
| trim the brief | 18.5% | agreement 83.3% → 75.0% on stored verdicts, 76.5% → 64.7% against his marks; the leanest version collapsed every reject to `creator` | **NO** |
| smaller screenshot | 0.9% | 615 → 291 at the legibility floor saves **324 tokens = 0.5% of a page** | **not worth it** |
| cheaper model to "see" | — | 70.0% vs 74.0%, and **high confidence on 50 of 50 while wrong on 15** | **NO** |
| pre-sort as a gate | removes pages | kills wanted pages every time: 13 of 148 out of sample on Instagram, 3 of 13 on TikTok | **ORDERING ONLY** |
| more agents | **0%** | 2.07 / 3.29 / 3.45 / 4.01 pages/min at 1/2/4/8 — 8× for 1.94×; and per-page **tokens get worse**, because each agent pays the floor again | **NO** |
| **batch pages per agent** | **the 95.2%** | **6.4× fewer tokens per page** | **the only real lever** |

**Everything on the operator's list attacks at most 19.4% of the bill combined, and each item
is measured to cost accuracy.** That is the measured refusal: *per-page tokens cannot fall
much by tuning the brief, the screenshot, the model or the pre-sort.*

### Batching is the exception, and it is already measured

BL-1271's parallel-judging curve ran yesterday on the same brief and the same TikTok sheets,
and its per-agent `subagent_tokens` were recorded. Re-read as a **batching** curve:

| pages per agent | agents | tokens per agent | **tokens per PAGE** |
|---:|---:|---:|---:|
| 1 | 8 | 64,216.9 | **64,216.9** |
| 2 | 4 | 66,676.8 | **33,338.4** |
| 4 | 2 | 71,227.5 | **17,806.9** |
| 8 | 1 | 80,434.0 | **10,054.3** |

**The marginal cost of one more page inside an agent is 2,316.7 tokens** — against 65,296 for
a page in its own agent. That is the whole finding in one number: **you are paying 60,000
tokens to set up, and 2,300 to judge.**

*Corroboration: the 1-page-per-agent figure of 64,216.9 independently reproduces this round's
arm C (65,296) to within 1.7%, from a different round, a different day and a slightly
different prompt (no reference card).*

Batched at 8 pages per agent:

| | tokens/page | pages per million | wanted per million (TT / IG) |
|---|---:|---:|---:|
| one page per agent | 65,296 | 15.3 | 9.6 / 2.8 |
| **eight pages per agent** | **10,054** | **99.5** | **62.7 / 17.9** |

**6.5× more pages from the same plan.**

**The cost of doing it, stated plainly:** independence. On the free path independence is
*instructed in the prompt*, not enforced in code the way the paid harness's
`_assert_independent()` enforces it. Batching N pages into one context is exactly the
condition under which cross-page anchoring becomes possible, and that is already on the
record as not ruled out. **Batching trades tokens for an accuracy risk that has never been
measured — and it should be measured before it is taken at scale.** That is the next round,
and it is cheap: re-judge a marked set at 1 and at 8 pages per agent and compare agreement.
