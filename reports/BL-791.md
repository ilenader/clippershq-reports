## The defect this round found: `qualified_by` bypassed in all four funnels

I ran Google Play **first, on purpose** — free, ~1 minute — as a canary before committing 2.8 estimated hours. It returned **`qualified_by` 0 of 55**.

```python
if int(concurrency or 1) > 1:
    return _run_parallel(...)          # early return
...
_r.setdefault("qualified_by", _qb)     # the stamp — never reached
```

The stamp sat below the parallel return. Every client funnel is configured parallel (`spotify` 3, `twitch` 6, `gp` 6, `youtube` 6), so **the live wiring never reached it**, and `append_found_to_master` guards its write with `and r.get("qualified_by")` — so the column stayed silently empty. Same failure class as BL-746.

**My first scan said three of four funnels were affected and Twitch was clean. That was wrong.** The scan looked for a bare `return _run_parallel(...)`; Twitch's is wrapped —

```python
return flag_repeat_emails(_run_parallel(...), repeat_email_min_channels)
```

— so the pattern missed it. The live Twitch run then returned `qualified_by` **0 of 75**, which is how the miss surfaced. **All four had the bug.** Fixed in all four: the stamp is defined above the branch and applied at both exits.
