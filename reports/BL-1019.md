**Two data-safety items, both named and unowned. One is now closed. The other is laid out for
the operator and deliberately not acted on.**

**The one number: 19 people are exposed in 3 blobs of the public repo's git history, and

**And the brief's stated cost of a rewrite is measurably wrong.** All 102 raw-URL citations

## 1. `backups/` is a copy, not a backup — and now there is one that isn't

INFRA-024's claim verified and worse than stated. Measured today:

**252 files, 1.8 GB**, sitting *inside the working tree*, *under the same OneDrive folder*,
*on the same C: volume* as the data it copies. The outcome ledger: **eight copies, all on C:**.

**Count of copies is not redundancy. Count of devices is.**

Two more facts from this machine, both of which change the advice:

- **OneDrive is not running.** The env var is set; no process is live. The folder is not
  syncing anywhere right now. Even if it were, OneDrive propagates deletions and corruption —
  `rm -rf` reaches the cloud copy in seconds.
- **There is exactly one volume: C:**, 17.2 GB free. No D:, no external, nothing mounted.
  **The second device does not exist yet.** That part cannot be automated; the operator has to
  plug something in.

### The command

```
python tools/backup.py --dest E:/clippershq-backups
python tools/backup.py --verify E:/clippershq-backups/clippershq-<stamp>.tgz
```

**A `--dest` on the repo's own volume is REFUSED, exit 1**, naming `backups/` as the mistake
it is repeating. `--force-same-device` exists for staging and says so on the record.

**93 files, 94.7 MB → 26.0 MB, in 6.6 seconds.** `master_leads.csv` (59,006 rows),
`clip_library/` (2,728 clips, ~$10 of paid labelling), `memebot/runs.jsonl`, `ground_truth/`
(the only hand labels anyone owns), `scratch/songs.json`, `config.json`. Excluded: `backups/`
itself, the render trees, and stale `.lock` files — restoring one would make the next writer
wait on a lock held by a process that died on another machine.

### The restore, verified

```
files            : 93
byte-identical   : 93
VERIFIED         : True
```

**Checked independently of the tool's own manifest**, because the manifest was written by the
same program and checking only against it is circular. Eight files re-hashed against the
**live originals** — master, the ledger, both `ground_truth/` label files, the 29.3 MB clip
shard, songs, config, the export: **8/8 identical.**

`--verify` extracts **off-tree**, so checking a backup can never overwrite what it protects.
The archive is a plain `.tar.gz` — `tar -xzf` restores it with no Python and no network.

**15 tests** (`tests/test_backup.py`), including that a corrupted member is caught, a
path-traversal member is refused, and a missing *required* file aborts rather than silently
producing a backup you would trust.

**Not solved: nothing schedules it.** A backup that depends on remembering stops the week it
gets busy — and the device that makes it survive is the one that is not always attached.

## 2. The history decision — options and their real costs

BL-1017 redacted 20 live addresses from the public repo. **Redaction does not undo
disclosure.** Measured on a full clone (739 commits, 3,196 objects, 722 text blobs):

| | measured |
|---|---|
| blobs in history carrying a live lead address | **3** |
| distinct paths | **3** — `reports/BL-743.md`, `BL-788.md`, `BL-797.md` |
| **distinct people exposed** | **19** |
| public working tree today | **0** across 661 artefacts — the redaction holds |
| exposure window | first published **2026-07-31**, redacted **2026-08-02 23:21** — ~2.5 days live |

### What a rewrite would actually cost — the brief's figure corrected

The brief says a rewrite "breaks every raw URL ever cited, and this project cites hundreds."
**Measured: 102 citations (45 private, 57 public; 59 distinct), and every single one is pinned
to `/main/`, not to a commit SHA.** A history rewrite changes SHAs; it does not move `main`.
**None of the 102 would break.**

What a rewrite *does* cost:

- **Every existing clone keeps the data.** Anyone who cloned in those 2.5 days still has it,
  and no force-push reaches them.
- **GitHub keeps unreachable objects accessible by SHA** for a period after a rewrite, and
  forks/caches/archives may retain them indefinitely. A rewrite reduces discoverability; it
  does not guarantee deletion.
- **Commit SHAs referenced elsewhere break** — `judged_at_commit` in `ground_truth/`,
  `Claim-Override` trailers, `verify_claims`' `git show HEAD:` checks. Those live in the
  *private* repo and reference *its* SHAs, so this is small, but it is not zero.
- The 3 affected reports are referenced by **34 files** (BL-743 ×7, BL-797 ×21, BL-788 ×6) —
  by report ID, which survives.

| option | what it costs | what it buys |
|---|---|---|
| **Rewrite + force-push** | ~30 min; re-clone for anyone holding a copy; **does not** break the 102 URLs; does **not** guarantee deletion from caches/forks | removes the addresses from the default fetch path |
| **Leave it** | 19 people remain discoverable to anyone who reads history | zero effort; the current tree is already clean |
| **Make the repo private** | every raw URL breaks **immediately** — all 102, plus anything external | strongest containment; ends public disclosure outright |

**Note the asymmetry the brief inverted:** the option that actually breaks the URLs is *making
the repo private*, not rewriting history.

**This round did not rewrite anything.** That is the operator's call and it is not reversible.

## 3. The sweep's own limit

**The join knows 4,729 addresses — those currently in `master_leads.csv` plus the export.**

An address that *was* in a lead file and has since been removed — a bounce purge, a
suppression, an unsubscribe, a re-export — **is not in that index and will not be caught.**
The 19 people found in history were found because they are still in master. Anyone removed
since would be invisible to every number in this report.

**So a zero from this sweep means "nothing matching what we hold today". It never means "no
PII".** Closing that gap needs an append-only record of every address ever exported, which
does not exist.
