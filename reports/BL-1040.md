## 1. The silent zero — already fixed, by INFRA-026

The brief says four rounds named `dashboard/server.py:1874` and left it. **At HEAD it is
fixed**, and line 1874 is now a comment explaining the fix:

```python
try:
    names = os.listdir(audit_dir)
except FileNotFoundError:
    names = []                       # a checkout with no scratch/ genuinely has no audit
except OSError as exc:
    out["unavailable"] = ("could not read %s (%s) — this is NOT the same as having no "
```

`FileNotFoundError` still returns `[]` and **that is correct** — a checkout without
`scratch/` genuinely has no audit. Every other `OSError` returns an explicit state. Landed
in `b152f30`, *"INFRA-026: a seventh defect, and it was mine"*.

**I verified the chain reaches the operator's eye, which is the part a code fix alone does
not prove.** `dashboard/static/app.js:549`:

```js

```

The UI consumes `unavailable` and renders it. So "could not look" no longer renders as
"nothing found" — at the endpoint *and* at the panel.

**One deliberate difference from the brief.** It says three secondary endpoints return 500
and calls that the established pattern. `api_audit` returns **200 with an explicit
`unavailable` string** instead. I did not change it to 500, because this endpoint is not the
same case: it is a *panel among many* on a page that polls, and a 500 would blank the panel
with a generic browser-level failure, whereas the string names the directory and the errno
class in the panel itself. The brief's requirement is *"RAISE or return an explicit error
state the UI shows as an error, never an empty list"* — the second branch of that is what is
implemented, and it is verified end to end. **Changing it to 500 would be a downgrade in
what the operator is told.**
