# BL-971 — two of the four items had the wrong premise, and saying so was the work

Four items. **Two were already resolved or resolved themselves**, and **one asked for a fix
that would have been wrong** — the manifest did not need a `superseded:` entry, and adding
one would have produced a green record of a removal that never happened. That is proven
below rather than asserted, because "the brief was wrong" is a claim that has to carry its
evidence.

The two sweeps landed. One of them had to be fixed twice before it could see the bug it was
built from, and the other committed the exact defect it audits. Both are reported as they
happened.

---

## 1. MEMEBOT-065 — the symbols were MOVED, not deleted

The brief's premise: *"MEMEBOT-069 deleted symbols it claims … if the symbols were
deliberately removed, the manifest needs a `superseded:` entry."*

They were not removed. All three are at HEAD right now:

| claimed | at HEAD in `scratch/mb065_clone.py` | actually at HEAD in |
|---|---|---|
| `crashed` | absent | `tests/test_clone_rehearsal.py:118` |
| `check` | absent | `tests/test_clone_rehearsal.py:135` |
| `live_claim` | absent | `tests/test_clone_rehearsal.py:233` |

MEMEBOT-069's `cdc4ec4` moved the clone rehearsal into the suite and took its helpers with
it. The manifest is red because it still points at the old file — which is the check
working exactly as designed.

### A `superseded:` entry would have passed WHILE BEING FALSE

This is the part worth proving. `check_superseded()` resolves through
`check_func(inner)`, and `inner` is **path-qualified**: `scratch/mb065_clone.py::crashed`.
It asks *"is this symbol absent from this file"*, never *"is it absent from the repo"*. A
moved symbol is absent from its old file. Measured, feeding it the entry the brief asked
for:

```
superseded: func scratch/mb065_clone.py::crashed by MEMEBOT-069: moved into the suite
   verdict : PASS   "…is absent at HEAD, as recorded"
   truth   : crashed IS AT HEAD in tests/test_clone_rehearsal.py
   -> GREEN ON A FALSE STATEMENT
```

All three do it. `check` is worse: it exists in **23 files** at HEAD, so a superseded
record for it would be false twenty-three times over — a bare symbol name is not an
identity.

**This is the same defect class BL-965 removed from the neighbouring guard one commit
earlier: a check whose SCOPE is narrower than its CLAIM, passing on a false statement.**
BL-881 built `superseded:` to assert an absence and fail if the symbol returns; it cannot
do the second half across a move, so for a move it is the wrong instrument entirely.

**The honest fix is to re-point the three claims.** `docs/claims/MEMEBOT-065.claims` is
**held by MEMEBOT-075**, which started one minute before this round and is doing exactly
that. **BL-971 did not write it.** No symbol was restored to satisfy a manifest — nothing
needed restoring.

**Proposed, not applied** (`tools/verify_claims.py` is MEMEBOT-075's this round): before
accepting a `superseded:` claim, resolve the symbol across the tree, not just the named
path, and refuse the claim when it is found elsewhere — "moved to X" is a re-point, not a
removal. Demo: `scratch/bl971_superseded_demo.py`.

## 4. The text-guard sweep — 67 guards, ranked by what a false positive costs

Ranked by **cost**, not by likelihood, because cost is what BL-965 was bitten by: a guard
that merely warns is cheap to be wrong about; a guard whose flag instructs a human to
**delete** something is the expensive kind, and that is the kind that fired.

| cost | guards | with **no** AST resolution |
|---|---|---|
| BLOCKS-A-COMMIT | 13 | **11** |
| DELETES-CONTENT | 3 | **2** |
| TURNS-SUITE-RED | 23 | **19** |
| MISREPORTS | 21 | 21 |
| WARNS | 7 | 6 |
| **total** | **67** across 52 files | **59** |

### The one I proved, and fixed

`tests/test_config_contract.py::test_the_deleted_keys_stay_deleted` concatenated every
`clippershq/*.py` into one blob and asserted the literal string
`'cfg.get("crawl_require_email"'` was not in it. **Measured, that predicate is wrong in
both directions — four of six cases:**

| case | a real restoration? | old guard fires? | |
|---|---|---|---|
| `cfg.get("crawl_require_email", False)` | yes | yes | correct |
| `cfg.get('crawl_require_email', False)` | yes | **no** | FALSE NEGATIVE |
| `cfg.get ("crawl_require_email")` | yes | **no** | FALSE NEGATIVE |
| `k = "…"; cfg.get(k)` | yes | **no** | FALSE NEGATIVE |
| a **comment** explaining the removal | no | **yes** | FALSE POSITIVE |
| a **docstring** explaining the removal | no | **yes** | FALSE POSITIVE |

The false positives are the BL-965 shape exactly: documenting *why* a key was removed trips
the guard that enforces its removal, and acting on the flag deletes the explanation.

**Fixed by using `read_keys()` — the AST resolver twenty lines up the same file**, already
used by rule A and already proved by an existing test to tell `cfg.get` from `media.get`.
The resolver was two functions away the whole time. Five of the six cases now behave;
the sixth (a key read through a variable) is **asserted as a known limit** rather than
quietly claimed, since it was invisible to the substring too.

The new fixture is wired into the file's `__main__` block, because this suite is
script-style and a test function not named there never runs — green while testing nothing.

### The counter-example the repo already had

`tools/repo_guard.py::sweep` — BLOCKS-A-COMMIT — got there first. It tracks triple-quoted
blocks so a docstring naming a dangerous command is prose, keeps an explicit skip-list for
files that "DOCUMENT the patterns on purpose", and strips backtick-quoted spans before
scanning. Its own comment says why: *"Flagging it trains people to ignore the tool."* That
is the pattern the other 59 should copy, and it was written before BL-965 learned it
independently.

### What the sweep got wrong, first time

The first version qualified a function by the **name** of the variable it tested — anything
ending `src`/`text`/`body`/`line`. It returned **201 hits** and most were data:
`src.startswith(` in `twitch_finder._tally` is a *source funnel name*; `f in text` in
`quality_gate._free_niche` is a *bio*; `caption_parser` tests caption templates. **The
sweep written to find guards that match a mention rather than resolve a structure was
itself matching a mention** — the fifteenth instance, inside the instrument, in one
sitting. It now requires **provenance**: the function must demonstrably read code or doc
text. 201 → 67.

## 5. The ordering sweep — an honest null result

`scratch/bl971_ordering.py` looks for a gate on a value followed later in the same function
by a cleanup of that value, where the cleanup's output would have passed the gate.

**It found 0 hits on the first run — and 0 hits is a broken sweep until proven otherwise.**
Validated against a reconstruction of `greeting_name()` as it stood before BL-965 fixed it,
it was **blind twice**:

1. it required the cleanup to assign to the same name it read, but the real bug was
   `entity = _LEGAL_SUFFIX.sub("", entity)` — gated variable `name`, cleaned variable
   `entity`;
2. `entity = name` is a bare alias with no call, invisible to a reader that only looks at
   the cleanup line. One level of alias resolution was needed.

After both fixes it detects its founding case, and finds **70 pairs / 48 distinct sites /
16 in production**. Every one of the 16 was read by hand:

| verdict | n | why |
|---|---|---|
| container variable, not the gated value | 11 | `row`, `r`, `author` — the gate tests one field, the cleanup builds another |
| the module `re`, not a value | 2 | `_names_in` picks up module names |
| gate already normalises internally | 1 | `is_dupe` → `_keys()` calls `normalize_handle` itself; the later call builds a *cache key* |
| **latent, not live** | 1 | `market_filter.rejection_is_strong` dispatches on `d.startswith("script:"/"market:"/"lang:")` — case-**sensitive** — then lowercases the tag. `"Lang:fr"` would fall through to "no decisive evidence". The prefixes are produced internally and are always lowercase today, so it is a fragility, not a bug. |
| **correct by design** | 1 | `repo_guard.sweep` — the backtick strip comes after the safe-context skip deliberately |

**0 live bugs.** Reported as a null result rather than dressed up as 70 findings. Worth
saying plainly: **the BL-965 bug was found by reading rendered output, not by this sweep**,
and the sweep needed two fixes before it could see even that one.

## 6. The measurement lesson, demonstrated twice more

BL-965's automated "declining" check missed all 7 real cases and flagged 6 correct ones;
reading caught them. **Any flag never validated against hand-read output is a hypothesis.**
This round produced two more of exactly that:

* the text sweep's first run: **201 flags, precision so low the top of the list was
  entirely data**. Caught by reading the output, not by the sweep passing.
* the ordering sweep's first run: **0 flags, and 0 was wrong** — it could not see its own
  founding case. Caught by building a fixture from the known bug (docs/TESTING.md rule 1)
  rather than trusting a clean result.

A sweep that returns a suspiciously round number — 201 or 0 — has told you about itself,
not about the tree. Both are now validated against a known case before their output is
quoted.

### The one I got wrong, and who caught it

`test_the_exemption_is_reached_by_the_live_manifest_it_was_written_for` was written by
BL-965 — by me, one round earlier. It named `docs/claims/MEMEBOT-067.claims` and asserted

from enforcement on the strength of a limitation that no longer existed. My exemption
asked only whether the denial was in scope, and so let a **factually false** statement
stand. Being in scope and being true are different questions, and BL-965 only checked the
